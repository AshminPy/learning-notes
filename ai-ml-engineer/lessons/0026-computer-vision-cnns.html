Computer vision: CNNs & image classification

In Project 2 (Lesson 23) you built an image classifier using only Flatten and Dense layers, and it worked — around 87–88% test accuracy. But plain Dense layers are not really built for images. This lesson covers the layer type that is: the convolutional layer, and the network built from it, the CNN (convolutional neural network).

Why Dense layers struggle with images

A Dense layer connects every input number to every neuron. In Project 2, Flatten turned each 28x28 image into 784 numbers in a row, and Dense(128) connected all 784 of them to each of its 128 neurons — that's over 100,000 weights in one layer, for small 28x28 grayscale images. A bigger, color, real-world photo would blow that number up fast.

There's a second problem, worse than the parameter count: Flatten throws away position. Once the grid becomes one flat list, the network has no built-in sense that pixel 5 and pixel 6 are neighbors, or that a curve in the top-left of the image is the same kind of shape as that same curve in the bottom-right. Nearby pixels in a real image are related — they form edges, textures, shapes — and a plain Dense layer has no way to use that fact.

Simple example: imagine describing a photo to someone by reading out all its pixel brightness values in one long list, left to right, top to bottom, with no mention of rows or columns. They could technically reconstruct the image from that list, but they'd have a much harder time spotting "there's an edge here" than if you just handed them the actual 2D picture. Flatten does exactly that — turns the picture into a long list before the network gets to look for shapes.

Convolution: a small filter sliding across the image

A convolution uses a small filter (also called a kernel) — for example a 3x3 grid of numbers — and slides it across the image, one small step at a time. At each position, it multiplies the filter's numbers against the pixels underneath it and adds up the result into a single number. Do that at every position and you get a new grid of numbers called a feature map.

Different filters detect different patterns. One filter's numbers might be tuned to light up strongly wherever there's a vertical edge; another might respond to a curve, or a patch of a certain texture. The network doesn't get these filters handwritten — it learns the filter numbers during training, the same way it learns the weights in a Dense layer, through backpropagation and gradient descent (Lesson 20).

The key win: the same filter is reused at every position in the image. Instead of one giant set of weights connecting every pixel to every neuron, you have one small filter (say, 3x3 = 9 numbers) that slides everywhere. Far fewer parameters, and the filter that learns "vertical edge" in the top-left of the image also recognizes a vertical edge in the bottom-right — because it's the exact same filter, reused.

Pooling: shrinking the feature map

Pooling shrinks a feature map by keeping only the strongest signal in each small region and dropping the rest. The most common kind, max pooling, looks at each 2x2 block of the feature map and keeps just the single largest value, throwing the other three away. A 28x28 feature map becomes 14x14 after a 2x2 max pool — a quarter of the size.

Two benefits from this shrinking:

  • Faster and smaller — fewer numbers to carry into the next layer means fewer computations and fewer parameters downstream.
  • Tolerant of small shifts — if the same edge shows up one pixel to the left in a slightly different photo of the same object, max pooling still picks up roughly the same strongest signal in that region. The network becomes less sensitive to exact pixel position, which is exactly what you want — a shoe is still a shoe whether it's centered or shifted a few pixels in the frame.

Stacking conv + pool layers

A single convolutional layer only sees small patches (like 3x3) at a time, so it can only learn simple, local patterns — edges, corners, small blobs of color. Stack a second conv+pool layer on top of the first, and it operates on the feature maps from the first layer, not the raw pixels. That means the second layer can combine simple edges into more complex shapes — a corner plus two edges might become "the outline of a sneaker's sole."

Stack a third layer, and it combines those shapes into full objects. This is the core idea of a CNN: early layers learn simple, generic patterns (edges), and each layer after that combines the previous layer's patterns into something more complex, right up to recognizable objects.

Simple example: think of building a face from LEGO. The first layer of bricks gives you straight edges and curves. The second layer combines those into recognizable parts — an eye shape, a mouth shape. The third layer combines the parts into a whole face. Each layer builds on what the layer before it already found — it never starts over from raw pixels.

Try it — before looking below

Q1. Why does a plain Flatten -> Dense network (like Project 2) struggle compared to a CNN, even though both can technically be trained on image data?

Flatten turns the 2D grid into one long list, so the network loses the information that nearby pixels are related — it can't use position to spot edges or shapes directly. It also needs far more weights, since every pixel connects to every neuron in the next Dense layer, instead of reusing one small filter across the whole image.

Q2. A 3x3 filter slides across an image and produces a feature map. What is that filter actually made of, and where do its numbers come from?

The filter is a small grid of numbers (9 numbers for a 3x3 filter). Those numbers start out random and are learned during training through backpropagation and gradient descent — the same process that learns weights in a Dense layer. The network is not handed a "vertical edge detector" — it discovers filters like that on its own because they help reduce the loss.

Q3. What does max pooling with a 2x2 window do to a 28x28 feature map, and why is that useful beyond just making the network faster?

It shrinks the 28x28 feature map to 14x14 by keeping only the single strongest value in each 2x2 block and dropping the other three. Beyond speed, this makes the network more tolerant of small shifts in the image — the same pattern shifted by a pixel or two still produces roughly the same strongest signal in its region, so the network doesn't need the object in an exact pixel position to recognize it.

Now write your own — a small Keras CNN

Open a new cell in your Project 2 notebook (or a fresh Colab notebook) and rebuild the same Fashion MNIST classifier from Lesson 23, this time with convolutional layers instead of a plain Dense stack.

One setup difference from Project 2: Conv2D expects a channel dimension on the input, even for grayscale images (color photos would have 3 channels for red/green/blue; grayscale has 1). Reshape the images to add that extra dimension before training:

import tensorflow as tf

fashion_mnist = tf.keras.datasets.fashion_mnist
(train_images, train_labels), (test_images, test_labels) = fashion_mnist.load_data()

train_images = train_images / 255.0
test_images = test_images / 255.0

# add a channel dimension: (28, 28) -> (28, 28, 1)
train_images = train_images.reshape(-1, 28, 28, 1)
test_images = test_images.reshape(-1, 28, 28, 1)

Now build the CNN: Conv2D -> MaxPooling2D -> Conv2D -> MaxPooling2D -> Flatten -> Dense -> Dense:

model = tf.keras.Sequential([
    tf.keras.layers.Conv2D(32, (3, 3), activation='relu', input_shape=(28, 28, 1)),
    tf.keras.layers.MaxPooling2D((2, 2)),
    tf.keras.layers.Conv2D(64, (3, 3), activation='relu'),
    tf.keras.layers.MaxPooling2D((2, 2)),
    tf.keras.layers.Flatten(),
    tf.keras.layers.Dense(64, activation='relu'),
    tf.keras.layers.Dense(10)
])

model.compile(optimizer='adam',
              loss=tf.keras.losses.SparseCategoricalCrossentropy(from_logits=True),
              metrics=['accuracy'])

model.fit(train_images, train_labels, epochs=10)

test_loss, test_acc = model.evaluate(test_images, test_labels, verbose=2)
print('\nTest accuracy:', test_acc)

Reading the architecture line by line:

  • Conv2D(32, (3, 3), activation='relu', input_shape=(28, 28, 1)) — 32 different 3x3 filters, each learning to detect a different simple pattern, producing 32 feature maps. input_shape is only needed on the first layer, same rule as Flatten in Project 2.
  • MaxPooling2D((2, 2)) — shrinks each feature map by keeping the strongest value in every 2x2 block.
  • Conv2D(64, (3, 3), activation='relu') — a second conv layer, 64 filters, now combining the first layer's simple patterns into more complex ones.
  • MaxPooling2D((2, 2)) — shrinks again.
  • Flatten -> Dense(64, activation='relu') -> Dense(10) — same job as the end of Project 2's network: take whatever the conv/pool stack found, flatten it to a list, and use ordinary Dense layers to make the final 10-class prediction.

compile, fit, and evaluate are unchanged from Project 2 — same optimizer, same loss, same rule about checking accuracy only on the held-out test set. Run it and compare your test accuracy against your Project 2 number.

Recap
  • Plain Dense layers need huge parameter counts for images and ignore that nearby pixels are related — Flatten throws away position.
  • A convolution slides a small learned filter across the image, producing a feature map that lights up wherever it finds the pattern it detects.
  • Max pooling shrinks the feature map by keeping only the strongest value in each region — faster, and more tolerant of small shifts in the image.
  • Stacking conv+pool layers lets the network build up from simple patterns (edges) to complex ones (shapes, objects), layer by layer.
