Path A — extend your CNN to a bigger, real image dataset

Lesson 26's CNN worked on Fashion MNIST: 28x28 grayscale images, 60,000 of them, already loaded and pre-sorted by Keras. Real-world image data is rarely handed to you that neatly. This path uses the flower photos dataset — 5 classes of real color photographs, downloaded as actual image files in folders, the way image data usually shows up on the job.

Load real image files from folders

import tensorflow as tf
import pathlib

dataset_url = "https://storage.googleapis.com/download.tensorflow.org/example_images/flower_photos.tgz"
data_dir = tf.keras.utils.get_file('flower_photos', origin=dataset_url, untar=True)
data_dir = pathlib.Path(data_dir)

image_count = len(list(data_dir.glob('*/*.jpg')))
print(image_count)   # about 3,670 images across 5 flower classes

get_file downloads and unzips the dataset once, into folders named after each class (daisy/, roses/, and so on). That folder-per-class layout is a common real-world format — image_dataset_from_directory reads it directly, no manual labeling needed:

img_height, img_width = 180, 180
batch_size = 32

train_ds = tf.keras.utils.image_dataset_from_directory(
    data_dir,
    validation_split=0.2,
    subset="training",
    seed=123,
    image_size=(img_height, img_width),
    batch_size=batch_size)

val_ds = tf.keras.utils.image_dataset_from_directory(
    data_dir,
    validation_split=0.2,
    subset="validation",
    seed=123,
    image_size=(img_height, img_width),
    batch_size=batch_size)

class_names = train_ds.class_names
print(class_names)   # ['daisy', 'dandelion', 'roses', 'sunflowers', 'tulips']

This does the same job as Project 1 and 2's train/test split (Lesson 16), just with an 80/20 validation_split argument instead of train_test_split. Every photo also gets resized to a consistent 180x180, since real photos come in inconsistent sizes and a CNN needs a fixed input shape.

Build the CNN — same pattern as Lesson 26, one key difference

Fashion MNIST was grayscale, so Lesson 26's Conv2D input shape ended in 1 channel. These are color photos, so the channel dimension is 3 (red, green, blue) instead:

num_classes = len(class_names)

model = tf.keras.Sequential([
    tf.keras.layers.Rescaling(1./255, input_shape=(img_height, img_width, 3)),
    tf.keras.layers.Conv2D(16, 3, activation='relu'),
    tf.keras.layers.MaxPooling2D(),
    tf.keras.layers.Conv2D(32, 3, activation='relu'),
    tf.keras.layers.MaxPooling2D(),
    tf.keras.layers.Conv2D(64, 3, activation='relu'),
    tf.keras.layers.MaxPooling2D(),
    tf.keras.layers.Flatten(),
    tf.keras.layers.Dense(128, activation='relu'),
    tf.keras.layers.Dense(num_classes)
])

model.compile(optimizer='adam',
              loss=tf.keras.losses.SparseCategoricalCrossentropy(from_logits=True),
              metrics=['accuracy'])

model.fit(train_ds, validation_data=val_ds, epochs=10)

Rescaling(1./255, ...) is the same normalize-to-0-1 idea from Project 2 (Lesson 23), just written as a layer instead of a manual division — it now runs as part of the model itself. Everything else is the stacked Conv2D -> MaxPooling2D pattern from Lesson 26, with one more conv+pool pair since these images are bigger and more complex than Fashion MNIST's.

Stretch goal — data augmentation (fighting overfitting on a small dataset)

3,670 photos across 5 classes is far less data than Fashion MNIST's 60,000 images, so this model is more prone to overfitting (Lesson 16) — memorizing quirks of the training photos instead of general flower features. Data augmentation fights this by randomly flipping, rotating, and zooming training images each epoch, so the model effectively sees more variety without collecting more photos:

data_augmentation = tf.keras.Sequential([
    tf.keras.layers.RandomFlip("horizontal", input_shape=(img_height, img_width, 3)),
    tf.keras.layers.RandomRotation(0.1),
    tf.keras.layers.RandomZoom(0.1),
])

Add it as the first layer of the model (before Rescaling), and add a Dropout(0.2) layer right before the final Dense(num_classes) — dropout randomly turns off 20% of neurons each training step, which also reduces overfitting by preventing the network from leaning too hard on any one neuron. Retrain and compare your validation accuracy with and without these two additions.

Path B — extend your Hugging Face pipeline to your own text

Lesson 27 ran pipeline("sentiment-analysis") on one hardcoded sentence. This path runs it on a small set of sentences you write yourself, then tries a second, different pipeline task.

Run sentiment analysis on your own sentences

!pip install transformers

from transformers import pipeline

classifier = pipeline("sentiment-analysis")

my_sentences = [
    "The onboarding process was confusing and slow.",
    "Support fixed my issue within five minutes, amazing!",
    "It's an average product, does the job.",
]

results = classifier(my_sentences)
for sentence, result in zip(my_sentences, results):
    print(sentence, "->", result)

Write your own 5-10 sentences instead of copying the ones above — pick a theme (product reviews, messages from friends, lines from a show you like) so your write-up has something real to say about the results. Pay attention to any sentence the model gets "wrong" by your own judgment, or scores with low confidence — that's useful material for your README's "what I'd improve" section.

Stretch goal — try a different Hugging Face pipeline task

The pipeline() function isn't just for sentiment. Hugging Face's own course lists several ready-made task names, including "zero-shot-classification" and "summarization". Zero-shot classification is a good stretch pick — it sorts text into labels you choose on the spot, without retraining anything:

zero_shot = pipeline("zero-shot-classification")

result = zero_shot(
    "This tutorial explains transformers really well.",
    candidate_labels=["education", "politics", "sports"],
)
print(result)
# {'sequence': '...', 'labels': ['education', 'sports', 'politics'], 'scores': [0.93, 0.04, 0.03]}

If you'd rather try summarization instead, it's the same pattern with a different task name: pipeline("summarization"), called on a longer paragraph, with max_length/min_length arguments controlling how short the summary comes out. Either is a fine stretch goal — pick whichever is more useful for the sentences/text you gathered.

Simple example: think of pipeline("sentiment-analysis") and pipeline("zero-shot-classification") as two different jobs done by the same machine. Both still do Lesson 27's tokenize-then-embed steps first — turning your sentence into vectors — and both still run those vectors through a transformer using attention (Lesson 28) to weigh which words matter. The only real difference is the small "task head" bolted on at the end: one is trained to output a fixed positive/negative label, the other is trained to score your sentence against whatever labels you hand it at request time.

Try it — before looking below

Q1. In Path A, why is data augmentation more useful for the flower photos dataset than it was for Fashion MNIST in Lesson 26?

Fashion MNIST has 60,000 training images; the flower dataset has only about 3,670 across 5 classes. Less training data means a higher risk of overfitting (Lesson 16) — the model memorizing specific training photos instead of learning general features. Data augmentation manufactures extra variety (flips, rotations, zooms) from the same photos, which reduces that risk without collecting more data.

Q2. Both pipeline("sentiment-analysis") and pipeline("zero-shot-classification") start with the same two steps from Lesson 27. What are those two steps?

Tokenization (splitting the text into tokens and mapping each to a token ID) and embedding (turning each token ID into a vector positioned by meaning). Both pipelines share this front end — they only differ in the final task-specific step that turns the processed vectors into a label.

Q3. If you chose Path B, how does Lesson 28's idea of "attention" apply to what the pipeline just did to your sentences?

The pretrained model inside the pipeline is a transformer. As it processes each token in your sentence, attention lets it weigh every other token to understand context — for example, deciding that "not" changes the meaning of the word after it, or that "amazing" late in a sentence should carry more weight than a filler word. That's what lets it score "It's an average product, does the job" differently from a sentence with the word "average" used sarcastically — the same mechanism from the trophy/suitcase example in Lesson 28, just running on your own text.
