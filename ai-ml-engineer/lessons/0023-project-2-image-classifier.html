What you're building

This dataset is called Fashion MNIST: 70,000 images, 28x28 pixels each, built directly into Keras so there's no download or file wrangling. Step 0 — open a fresh notebook

Open a new notebook in your Colab account. Name it something like project-2-image-classifier.ipynb. Every code block below goes in its own cell, run top to bottom.

Step 1 — load Fashion MNIST

Just like scikit-learn ships small built-in datasets, Keras ships a handful of built-in image datasets — no download, no unzip, no folder of files. We'll use fashion_mnist, which loads pre-split into a training set and a test set:

import tensorflow as tf
import numpy as np
import matplotlib.pyplot as plt

fashion_mnist = tf.keras.datasets.fashion_mnist

(train_images, train_labels), (test_images, test_labels) = fashion_mnist.load_data()

class_names = ['T-shirt/top', 'Trouser', 'Pullover', 'Dress', 'Coat',
               'Sandal', 'Shirt', 'Sneaker', 'Bag', 'Ankle boot']

print(train_images.shape)   # (60000, 28, 28) -- 60,000 training images, 28x28 pixels each
print(test_images.shape)    # (10000, 28, 28) -- 10,000 test images

Each image is a 28x28 grid of numbers, one number per pixel, ranging from 0 (black) to 255 (white). Each label is a number 0–9 — class_names is just a lookup list so you can print a human word instead of a digit. Note the labels are plain integers here (0, 1, 2...), not one-hot vectors — that matters for one detail in Step 3.

Simple example: think of each image as a 28x28 spreadsheet where every cell holds one brightness number instead of text. A neural network doesn't "see" a shoe the way you do — it just sees 784 numbers (28 x 28) and learns which patterns of numbers tend to go with the label "Sneaker."

Step 2 — normalize the pixel data

Pixel values come in as integers from 0 to 255. Neural networks train better on small numbers close to 0–1 — large raw values make the weighted sums swing wildly and slow down (or destabilize) training. So we scale every pixel down by dividing by 255:

train_images = train_images / 255.0
test_images = test_images / 255.0

This is the same idea as StandardScaler in Project 1 — put your input numbers on a small, consistent scale before training — just done here with simple division, since we already know the fixed range (0–255) ahead of time.

Step 3 — build a small Sequential model

This is Lesson 19's neurons and layers, written in Keras code. No convolutional layers yet — that's Lesson 26. For now, a plain stack of Dense (fully-connected) layers is enough to get solid results:

model = tf.keras.Sequential([
    tf.keras.layers.Flatten(input_shape=(28, 28)),
    tf.keras.layers.Dense(128, activation='relu'),
    tf.keras.layers.Dense(10)
])

Three layers, three jobs:

  • Flatten — takes the 28x28 grid and lays it out as one flat list of 784 numbers. Not a "real" layer with weights — just reshaping, since Dense layers expect a flat list of inputs, not a 2D grid.
  • Dense(128, activation='relu') — the hidden layer from Lesson 19: 128 neurons, each doing a weighted sum of all 784 inputs plus a bias, then ReLU.
  • Dense(10) — the output layer: one neuron per class (10 clothing categories). No activation function here — it outputs raw scores called logits, which the loss function below converts into probabilities internally.

Step 4 — compile and train

model.compile(optimizer='adam',
              loss=tf.keras.losses.SparseCategoricalCrossentropy(from_logits=True),
              metrics=['accuracy'])

model.fit(train_images, train_labels, epochs=10)

Three pieces, tying back to Lessons 20–21:

  • optimizer='adam' — the algorithm that performs gradient descent (Lesson 14 and 20) and updates every weight after each batch. Adam is a well-tested default, not something you need to tune by hand yet.
  • loss=SparseCategoricalCrossentropy(from_logits=True) — the cost function (Lesson 14) for multi-class classification. "Sparse" means it works directly with plain integer labels (0–9) instead of requiring one-hot vectors. from_logits=True tells it the output layer gave raw scores, not already-converted probabilities — matching the Dense(10) with no activation from Step 3.
  • model.fit(..., epochs=10) — trains for 10 full passes over the 60,000 training images, running backpropagation (Lesson 20) after each batch to nudge every weight toward lower loss.

Run this cell and watch the accuracy climb epoch by epoch — that's gradient descent working in front of you, one step at a time.

Step 5 — evaluate honestly

Same rule as Project 1: check performance only on the test set, images the model never trained on.

test_loss, test_acc = model.evaluate(test_images, test_labels, verbose=2)

print('\nTest accuracy:', test_acc)

The official TensorFlow tutorial this project is based on typically lands around 87–88% test accuracy with this exact setup — but use the number your own run actually produced in your write-up, not this one.

Try it — before looking below

Q1. Why do we divide the pixel values by 255 before training, instead of feeding in the raw 0–255 numbers?

Neural networks train more reliably on small, consistently-scaled numbers. Large raw pixel values (up to 255) make the weighted sums inside each neuron swing much bigger, which slows down and can destabilize gradient descent. Dividing by 255 puts every pixel on a fixed 0–1 scale before the network ever sees it.

Q2. Why does the output layer use Dense(10) with no activation function, instead of a sigmoid like Lesson 19 mentioned?

Sigmoid squashes to a single 0–1 value, which fits yes/no problems. Here there are 10 possible classes, not 2, so the output layer produces one raw score (logit) per class instead. The loss function (SparseCategoricalCrossentropy(from_logits=True)) handles turning those 10 raw scores into probabilities internally — that's what from_logits=True is telling it to do.

Q3. What is backpropagation actually doing during each model.fit() epoch?

It measures how much each weight in the network contributed to the current loss (error), then nudges every weight a small step in the direction that reduces that loss — gradient descent, applied layer by layer backwards through the network. Lesson 20 covers this in depth; here you're watching its result (accuracy going up epoch by epoch) without hand-coding the math.

Step 6 — turn logits into predictions and plot a few

Wrap the trained model with a Softmax layer to convert the raw output scores into probabilities that add up to 1, then use np.argmax to pick the single most likely class:

probability_model = tf.keras.Sequential([model, tf.keras.layers.Softmax()])

predictions = probability_model.predict(test_images)

print(predictions[0])                 # 10 probabilities for the first test image
print(np.argmax(predictions[0]))      # index of the highest probability = predicted class
print(test_labels[0])                 # the actual true label

Now plot a handful of test images with their predicted vs actual label, using matplotlib from Lesson 9:

plt.figure(figsize=(10, 5))
for i in range(9):
    plt.subplot(3, 3, i + 1)
    plt.xticks([])
    plt.yticks([])
    plt.imshow(test_images[i], cmap='gray')

    predicted_label = np.argmax(predictions[i])
    true_label = test_labels[i]
    color = 'green' if predicted_label == true_label else 'red'

    plt.xlabel(f"{class_names[predicted_label]} (true: {class_names[true_label]})",
               color=color)

plt.tight_layout()
plt.show()

Green labels mean the model got it right, red means it didn't — a fast visual gut-check on top of the single test_acc number from Step 5. It's worth looking at a couple of the red ones: often they're genuinely confusing items (a shirt that looks like a coat), which tells you something about the limits of a plain Dense-layer model, not just a bug in your code.
