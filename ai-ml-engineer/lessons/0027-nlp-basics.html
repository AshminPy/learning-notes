NLP: text processing, embeddings, sentiment analysis

NLP (Natural Language Processing) is the branch of AI that works with text — reviews, emails, chat messages, articles. But a model only understands numbers, from Lesson 3 onward. This lesson covers the two-step trick that turns text into numbers a model can actually learn from: tokenization and embeddings.

Simple example: imagine translating a sentence into a language made only of numbers. First you split the sentence into pieces (words). Then you look each piece up in a dictionary that gives you its number. "I love this course" might become [15, 203, 47, 891]. That's tokenization in one sentence.

Step 1: Tokenization — splitting text into pieces

Tokenization is splitting a piece of text into smaller units called tokens. A token is often a whole word, but for many models it's a subword — a chunk smaller than a word, so the model can still handle words it has never seen by breaking them into familiar pieces.

"I love this course"  -->  ["I", "love", "this", "course"]

# a subword tokenizer might split an unfamiliar word like this:
"tokenization"  -->  ["token", "##ization"]

After splitting, each token is looked up in a fixed vocabulary and replaced with a number — its token ID. This is exactly the same idea as the int/str conversion from Lesson 3: text becomes a number so code can work with it.

Step 2: Embeddings — turning token IDs into vectors

A raw token ID like 47 is a problem: it's just an arbitrary index, like a phone book entry number. The ID for "cat" being close to the ID for "car" tells the model nothing about meaning — it's random accident of alphabetical order.

So instead of using the raw ID, the model looks up a word embedding for each token: a vector of numbers (remember vectors from Lesson 10 — a list of numbers describing one thing). Instead of one number, "love" might become something like [0.21, -0.87, 0.44, ...], often with hundreds of positions.

Simple example: think of an embedding as GPS coordinates for a word, but in a space with hundreds of directions instead of 2. Words placed close together in that space have similar meaning. "happy" and "joyful" end up near each other. "happy" and "bicycle" end up far apart. The model learns these coordinates during training — nobody hand-writes them.

Why embeddings beat plain word IDs

This is the whole point of embeddings: they capture meaning and similarity, not just identity.

Token ID (e.g. 47)Word embedding (e.g. [0.21, -0.87, ...])
What it isOne arbitrary numberA vector — many numbers, like Lesson 10's feature vectors
Similar wordsNo relationship between nearby IDsSimilar-meaning words end up close together in the vector space
Can you do math with it?Not meaningfully — 47 and 48 aren't "similar" wordsYes — distance between vectors reflects how related two words are

Because similar words land near each other, a model trained on "I love this movie" can generalize to "I adore this film" even if it never saw that exact sentence — the embeddings for love/adore and movie/film are already close.

Try it — before looking below

Q1. What is the difference between a token ID and a word embedding?

A token ID is a single arbitrary number (a lookup index). A word embedding is a vector — many numbers — positioned so that similar-meaning words are close together in that space. The ID tells you "which word," the embedding tells you "what it means, roughly."

Q2. Why can a model trained on "great service" also handle "excellent service" well, even if it never saw that exact phrase in training?

Because "great" and "excellent" end up with similar embedding vectors (they're close together in the embedding space) — so the model treats them as near-equivalent even without seeing that exact sentence before.

Now write your own

You don't need to build tokenization or embeddings from scratch — Hugging Face's transformers library gives you a ready-made pipeline that does tokenization, embeddings, and prediction in one call. In your Colab notebook:

  • install the library: !pip install transformers
  • import pipeline and create a sentiment-analysis pipeline
  • run it on a sentence of your own choosing, and on "I love this course!"
  • print the result and identify the label and score in the output

Try it before looking at the answer.

Reveal the reference answer

!pip install transformers

from transformers import pipeline

classifier = pipeline("sentiment-analysis")
result = classifier("I love this course!")
print(result)
# [{'label': 'POSITIVE', 'score': 0.99...}]

What just happened: that one call to pipeline("sentiment-analysis") downloads a pretrained model, tokenizes your sentence, converts the tokens to embeddings, runs them through the model, and hands you back a simple label ("POSITIVE"/"NEGATIVE") and score (confidence, 0 to 1). Everything in this lesson happens inside that one line.

Recap
  • Tokenization splits text into tokens (words or subwords), then maps each token to a token ID.
  • A word embedding turns a token ID into a vector — the same kind of "list of numbers" idea as Lesson 10 — positioned so similar-meaning words are close together.
  • Embeddings beat plain IDs because they capture meaning and similarity, letting a model generalize to words/phrases it never saw during training.
  • Hugging Face's pipeline("sentiment-analysis") runs tokenization, embeddings, and prediction for you in one line.
