Evaluation metrics: accuracy, precision, recall, F1

A classifier that is "97% accurate" can still be useless. This lesson teaches you how to actually check whether a model is doing a good job — starting with the four numbers everything else is built from, then the metrics that matter more than accuracy in most real problems.

The confusion matrix

Every time a classifier makes a prediction on a labeled example, there are only four possible outcomes. Take a spam classifier: it looks at an email and predicts "spam" or "not spam."

OutcomeMeaningExample
True Positive (TP)Predicted positive, actually positiveSpam email correctly flagged as spam
False Positive (FP)Predicted positive, actually negativeReal email wrongly flagged as spam
False Negative (FN)Predicted negative, actually positiveSpam email that slipped into the inbox
True Negative (TN)Predicted negative, actually negativeReal email correctly left alone
Simple example: "positive" just means "the thing the model is looking for" — here, spam. It does not mean "good." A false positive (real email marked as spam) can be worse than a false negative, because you might miss an important email entirely.

Say you test your spam classifier on 1,000 emails and get this confusion matrix:

Predicted spamPredicted not spam
Actually spamTP = 40FN = 20
Actually not spamFP = 10TN = 930

We'll reuse these numbers (TP=40, FP=10, FN=20, TN=930) for every metric below.

Accuracy — and why it lies to you

Accuracy is the fraction of all predictions that were correct:

accuracy = (TP + TN) / (TP + TN + FP + FN)

For the spam matrix above: (40 + 930) / 1000 = 0.97, or 97%. That sounds great. But accuracy has a trap: it looks fine even when the model is doing almost nothing useful, as soon as one class is much bigger than the other (an imbalanced dataset).

Simple example: imagine only 1% of emails are actually spam — 990 not-spam, 10 spam, out of 1,000. A lazy model that always predicts "not spam," no matter what it sees, gets 990 correct out of 1,000 — 99% accuracy. And it catches zero spam. Accuracy alone can't tell the difference between a genuinely good model and a model that just predicts the majority class every time.

This is why, for imbalanced problems (fraud detection, disease screening, spam, fault detection — most real-world classification), you need metrics that look specifically at how the model handles the class you actually care about.

Precision — of what I flagged, how much was right?

precision = TP / (TP + FP)

Precision answers: "Of everything the model called positive, what fraction actually was positive?" It only looks at the predicted-positive column. A model with low precision cries wolf a lot — it flags things that turn out to be fine.

Spam example: precision = 40 / (40 + 10) = 40 / 50 = 0.80. Of every 10 emails the model marked as spam, 8 really were spam and 2 were innocent emails wrongly buried in the spam folder.

Recall — of everything real, how much did I catch?

recall = TP / (TP + FN)

Recall (also called sensitivity) answers: "Of everything that was actually positive, what fraction did the model catch?" It only looks at the actually-positive row. A model with low recall misses a lot of the real cases.

Spam example: recall = 40 / (40 + 20) = 40 / 60 = 0.667. Of every 3 spam emails that arrived, the model caught 2 and let 1 through to the inbox.

F1 score — balancing the two

Precision and recall usually trade off against each other — a model tuned to flag more things as positive will catch more real positives (higher recall) but also flag more false alarms (lower precision), and vice versa. F1 is the harmonic mean of the two, giving one number that only stays high when both are reasonably good:

F1 = 2 * (precision * recall) / (precision + recall)

Spam example: F1 = 2 × (0.80 × 0.667) / (0.80 + 0.667) = 1.067 / 1.467 ≈ 0.727. A harmonic mean (unlike a plain average) punishes a big gap between precision and recall — you can't hide a terrible recall behind a great precision.

When to prioritize precision vs. recall

SituationPrioritizeWhy
Cancer screening testRecallMissing a real cancer case (false negative) can cost a life. A false positive just means a follow-up test.
Spam filterPrecisionSending a real, important email to spam (false positive) is worse than one spam email reaching the inbox (false negative).
Fraud detection blocking a transactionBalance / dependsToo low recall lets fraud through; too low precision blocks honest customers. Usually needs F1 or a business-cost-weighted metric.

There is no single "correct" metric — you choose based on which mistake (false positive or false negative) is more expensive in your situation.

Check your understanding

Q1. A medical test is run on 1,000 patients. TP = 8, FP = 2, FN = 12, TN = 978. What is the precision (round to 2 decimals)?

precision = TP / (TP + FP) = 8 / (8 + 2) = 8 / 10 = 0.80. Of everyone the test flagged positive, 80% actually had the condition.

Q2. Same numbers (TP=8, FP=2, FN=12, TN=978). What is the recall (round to 2 decimals), and is that a good number for a cancer screening test?

recall = TP / (TP + FN) = 8 / (8 + 12) = 8 / 20 = 0.40. That's bad for cancer screening — the test misses 60% of real cases (12 out of 20). A screening test should be tuned for much higher recall, even if it means more false alarms (lower precision).

Try it yourself — scikit-learn's metric functions

In practice you never compute these by hand — scikit-learn's sklearn.metrics module does it from two lists: the true labels and the predicted labels. Try this in your Colab notebook (1 = spam, 0 = not spam):

from sklearn.metrics import precision_score, recall_score, f1_score, accuracy_score, classification_report

y_true = [1, 0, 1, 1, 0, 0, 1, 0, 0, 1]
y_pred = [1, 0, 0, 1, 0, 1, 1, 0, 0, 0]

print("accuracy: ", accuracy_score(y_true, y_pred))
print("precision:", precision_score(y_true, y_pred))
print("recall:   ", recall_score(y_true, y_pred))
print("f1:       ", f1_score(y_true, y_pred))
print(classification_report(y_true, y_pred))

Before you run it: go through the 10 pairs by hand and count the TP, FP, FN, TN yourself. Then run the code and check your count matches the scores.

Reveal the reference answer

Counting the 10 pairs: TP = 3, TN = 4, FP = 1, FN = 2.

accuracy:  0.7
precision: 0.75
recall:    0.6
f1:        0.6666...

Check: precision = 3/(3+1) = 0.75. recall = 3/(3+2) = 0.6. f1 = 2×0.75×0.6/(0.75+0.6) ≈ 0.667. accuracy = (3+4)/10 = 0.7. classification_report prints all of these per class plus "support" (how many true examples of each class there were) in one table — that's usually what you'll actually use day to day.

Recap
  • Confusion matrix: TP, FP, FN, TN — every prediction falls into exactly one of these four boxes.
  • Accuracy = (TP+TN)/total, but it's misleading on imbalanced data — a model that always predicts the majority class can score high while catching nothing.
  • Precision = TP/(TP+FP) — of what I flagged, how much was right. Recall = TP/(TP+FN) — of everything real, how much did I catch. F1 balances both.
  • Choose the metric to prioritize based on which mistake costs more: recall for cancer screening, precision for spam filters.
