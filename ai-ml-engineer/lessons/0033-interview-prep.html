Interview prep: explaining your projects & common ML questions

You've built three projects and read 32 lessons of theory. None of that helps in an interview if you freeze when someone says "walk me through one of your projects" or "what's overfitting?" This lesson has no new concepts — it's the opposite: a script for saying out loud, clearly and quickly, everything you already know.

Simple example: knowing something and being able to explain it under pressure are different skills, the same way knowing how to swim is different from staying calm the first time someone throws you in a pool. The fix for both is the same: practice the exact motion enough times that it stops feeling new.

Part 1 — walking through a project in under 2 minutes

Every project you built in this course already has the structure an interviewer wants, because you wrote it that way in Lesson 18 (and reused it in Lessons 23 and 29): problem, dataset/approach, results, what you'd improve next. That README structure isn't just for GitHub — it's also your spoken answer. Say it in the same order, out loud, in under 2 minutes:

README sectionWhat you say out loudRoughly how long
Problem statementWhat question were you answering, and why does it matter? ("Predict whether a tumor is malignant or benign, to support — not replace — a screening decision.")~15 seconds
Dataset / approachWhere the data came from, how big it was, and what you did to it — split, scaled, which model, why that model.~30 seconds
ResultsYour actual numbers — accuracy, precision/recall if it's imbalanced — and one sentence on whether that's good enough for the problem.~30 seconds
What you'd improve nextOne or two honest next steps. This is the question interviewers actually care most about — it shows you understand the model's limits, not just its output.~30 seconds

Common trap: narrating your code line by line ("then I imported sklearn, then I called train_test_split..."). Nobody wants that. An interviewer wants the decisions and the reasoning — why you split before training (Lesson 16), why you picked that metric (Lesson 17) — not a tour of your imports.

Try it now — say it out loud, then time yourself

Pick one project (your Lesson 18 classifier is the easiest to start with). Using the four-part structure above, explain it out loud — actually speak, don't just think it — with a timer running. Most people's first attempt runs 4–5 minutes. That's normal. Cut it down by removing detail from the middle two sections, not the last one — "what I'd improve" is the part that shows judgment.

Do this for at least one project before moving to Part 2. There's no reveal button for this one — the only way to know if 2 minutes is enough is to actually try it.

Part 2 — 8 questions you can now answer

These are common early-career ML interview questions. You already learned the answer to every one of them earlier in this course — this section is not new material, it's a pointer back to where you learned it, plus the answer phrased the way this course explained it (not textbook wording).

1. What is overfitting?

Overfitting is when a model memorizes the training data instead of learning the general pattern — like a student who memorized the exact answer key for one exam instead of learning the subject. It scores great on data it has already seen and badly on new data. You catch it by comparing training accuracy to test accuracy: a big gap (say, 99% on training, 61% on test) is the tell.

→ Taught in Lesson 16 — Train/test split, overfitting & regularization

2. Explain gradient descent.

Gradient descent is how a model gets "less wrong," one small step at a time. Picture standing on a hill in thick fog: you can't see the bottom, but you can feel which direction slopes downward, take a small step that way, then feel again. The "hill" is the cost function (how wrong the model currently is), and each step nudges the weights and bias to make that cost smaller. The learning rate controls the step size — too big and you overshoot the bottom, too small and training crawls.

→ Taught in Lesson 14 — Cost function & gradient descent

3. What's the difference between precision and recall?

Precision answers: "of everything I flagged as positive, how much was actually right?" Recall answers: "of everything that was actually positive, how much did I catch?" A spam filter that wrongly buries real emails in spam has low precision. A spam filter that lets real spam through to the inbox has low recall. Which one matters more depends on which mistake is more expensive — recall matters more for cancer screening (missing a real case is costly), precision matters more for a spam filter (losing a real email is costly).

→ Taught in Lesson 17 — Evaluation metrics

4. What is a neural network?

A neural network is layers of neurons stacked together. Each neuron is just a weighted sum — the same dot product idea from linear regression — plus a bias, passed through an activation function. The input layer holds the raw features, hidden layers each learn their own weighted combination of the layer before them, and the output layer produces the final answer. The activation function is what actually makes stacking layers worth it: without it, ten layers behave exactly like one, because stacked plain weighted sums collapse into a single weighted sum.

→ Taught in Lesson 19 — Neural networks: neurons, layers, activation functions

5. Supervised vs unsupervised learning?

Supervised learning learns from labeled examples — the correct answer is already attached to each one, like emails already tagged spam or not spam. Unsupervised learning gets no labels at all and has to find structure on its own, like grouping customers into segments nobody predefined ahead of time. Supervised learning splits further into two types: regression (predicting a number) and classification (predicting a category).

→ Taught in Lesson 12 — What is machine learning?

6. What's a confusion matrix?

It's a small table that sorts every prediction into one of four boxes: true positive (predicted positive, actually positive), false positive (predicted positive, actually negative), false negative (predicted negative, actually positive), and true negative (predicted negative, actually negative). Every other classification metric — accuracy, precision, recall, F1 — is just a different way of combining those four counts.

→ Taught in Lesson 17 — Evaluation metrics

7. Why do we split data into train/test sets?

Because testing a model on the same data it trained on is like grading a student with the exact homework questions they already saw the answers to — it proves nothing about whether they actually understood the subject. A train/test split holds back a test set the model never sees during training, so the test score is an honest read on how the model handles new, real data. It's also what lets you catch overfitting in the first place.

→ Taught in Lesson 16 — Train/test split, overfitting & regularization

8. What's the difference between classification and regression?

Regression predicts a number that can be anything — a house price, an exam score. Classification predicts a category from a fixed set — spam or not spam, malignant or benign. Under the hood they start from the same weighted-sum idea, but classification (logistic regression, for example) squashes that raw number through something like the sigmoid function into a probability between 0 and 1, then applies a threshold to pick a final category.

→ Regression taught in Lesson 13 — Linear regression  ·  Classification taught in Lesson 15 — Logistic regression

Try it — answer cold, then check yourself

Q1. Without scrolling back up: an interviewer asks, "What is overfitting, and how would you detect it in a model you just trained?" Answer it out loud in one breath, then reveal.

Overfitting is when a model memorizes the training data instead of learning the general pattern behind it — great on data it has seen, bad on data it hasn't. You detect it by comparing training accuracy to test accuracy: a big gap between the two (high on training, much lower on test) is the sign. (Lesson 16)

Q2. Same drill: "Why is accuracy alone sometimes a misleading metric?" Answer cold, then reveal.

On an imbalanced dataset, a model can score very high accuracy just by always predicting the majority class — for example, always predicting "not spam" when 99% of emails aren't spam gets 99% accuracy while catching zero actual spam. Precision, recall, and F1 look at how the model handles the class you actually care about, which accuracy alone can hide. (Lesson 17)
