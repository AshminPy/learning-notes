Logistic regression & classification

Lesson 13 predicted a number (an exam score). A lot of real problems instead ask a yes/no question: is this email spam? Will this customer cancel? Is this tumor malignant? That's a different kind of problem — classification — and it needs a different kind of model.

Simple example: regression is like asking "how many degrees will it be tomorrow?" (a number, could be anything). Classification is like asking "will it rain tomorrow — yes or no?" (a category, one of a fixed set of options). Same data, very different question.

Why not just reuse linear regression?

Say you're predicting pass/fail from hours studied, using 0 = fail and 1 = pass. You could try fitting a straight line through those 0s and 1s with y = w*x + b from Lesson 13. Two problems show up immediately:

  • A straight line keeps going forever. Plug in a big enough x and it predicts 1.4 or -0.3. Those aren't valid probabilities — a probability has to stay between 0 and 1.
  • There's no natural "probability of passing" reading on a raw line output — it's just a number with no upper or lower limit.

We need a model that always outputs something between 0 and 1, so it can represent "how likely is class 1." That's what logistic regression adds.

The sigmoid function: squashing any number into 0–1

Logistic regression starts exactly like linear regression — it computes the same weighted sum, z = w*x + b. But instead of using z directly as the prediction, it feeds z through the sigmoid function:

sigmoid(z) = 1 / (1 + e^(-z))

You don't need to memorize the formula. What matters is what it does: no matter how big, small, positive, or negative z is, sigmoid(z) always comes out between 0 and 1.

  • Very negative z (like -10) → sigmoid squashes it close to 0
  • Very positive z (like 10) → sigmoid squashes it close to 1
  • z = 0 → sigmoid gives exactly 0.5

That output is treated as a probability — "how likely is this to be class 1?" 0.9 means "90% likely class 1." 0.05 means "5% likely class 1 (almost certainly class 0)."

Simple example: think of sigmoid as a dimmer switch, not an on/off switch. Whatever raw number goes in, however extreme, the dimmer output always lands somewhere between fully off (0) and fully on (1) — never past either end.

Despite the name, it's a classifier

"Logistic regression" is a confusing name — it does not predict a number like Lesson 13's regression did. It outputs a probability, and that probability is used to pick a category. In scikit-learn and in the ML field generally, it's classified as a classification algorithm, not a regression algorithm. The name stuck for historical reasons.

Decision boundary: turning a probability into a yes/no

A probability like 0.73 isn't itself an answer to "pass or fail?" — you need a rule to convert it into a final category. The usual rule is a threshold of 0.5:

if probability >= 0.5:
    predicted class = 1  (e.g. "pass")
else:
    predicted class = 0  (e.g. "fail")

The point where the probability crosses 0.5 is called the decision boundary — the line that separates where the model predicts class 0 from where it predicts class 1. 0.5 is the default in scikit-learn, but it can be moved — for example, a cancer-screening model might use a lower threshold like 0.3, so it flags more borderline cases as "possible risk" rather than missing them.

Try it — before looking below

Q1. A logistic regression model outputs a probability of 0.82 for "this email is spam." Using the default 0.5 threshold, what does it predict?

Spam (class 1) — 0.82 is above the 0.5 threshold.

Q2. Why can't you just use plain linear regression (y = w*x + b) to predict yes/no outcomes directly?

A straight line's output is unbounded — it can go below 0 or above 1, which isn't a valid probability. Logistic regression fixes this by passing the line's output through the sigmoid function, which always stays between 0 and 1.

Reveal the reference answer

from sklearn.linear_model import LogisticRegression

hours = [[0.5], [1], [2], [3], [4], [5], [6]]
result = [0, 0, 0, 1, 1, 1, 1]

model = LogisticRegression()
model.fit(hours, result)

prediction = model.predict([[2.5]])
print(prediction)          # [0] or [1] -- the predicted class

probability = model.predict_proba([[2.5]])
print(probability)         # [[prob_of_0, prob_of_1]]

Common trap: .predict_proba() returns two numbers per row: probability of class 0 first, then probability of class 1 — always in that order, and they always add up to 1. Don't mix up which column is which.

Recap
  • Classification predicts a category (e.g. pass/fail); regression predicts a number.
  • The sigmoid function squashes any number into a probability between 0 and 1.
  • Despite the name, logistic regression is a classification algorithm, not a number predictor.
  • A threshold (default 0.5) turns the probability into a final class — this cutoff is the decision boundary.
Confused about why predict_proba gives two numbers instead of one? Ask — it trips people up the first time, and it matters a lot once you get to evaluating classifiers.
