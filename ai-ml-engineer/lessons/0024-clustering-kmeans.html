Clustering (k-means) & dimensionality basics

Back in Lesson 12 you met unsupervised learning: data with no labels, where the model has to find structure on its own. Today you'll actually do it — using an algorithm called k-means to group similar data points together, and you'll meet the idea of dimensionality reduction for shrinking huge feature sets down to something manageable.

Recap: what "no labels" means

In supervised learning (Lessons 13 onward), every training example came with the correct answer attached — a price, a category. In unsupervised learning, there's no correct answer given. You just have data points, and you ask the model: "what groups do you see in here?" Clustering is the most common unsupervised task — sorting similar items into groups (clusters) without anyone predefining what the groups are.

Simple example: imagine dumping a mixed box of red and green marbles on a table, mixed in with a pile of blue buttons. Nobody told you "these are marbles" and "these are buttons" — but just by looking at how the items cluster by color and shape, you'd naturally sort them into three piles. That's clustering: finding natural groups using only how similar items are to each other.

How k-means works

k-means is the most common clustering algorithm. The "k" is a number you choose upfront — it's how many groups (clusters) you want the algorithm to find. The algorithm then repeats a simple loop:

  1. Pick k starting points. Choose k data points to act as the initial "center" of each cluster (called centroids).
  2. Assign. Look at every data point, and assign it to whichever center is closest to it.
  3. Update. For each cluster, move its center to the average (mean) position of all the points now assigned to it — that's why it's called "k-means."
  4. Repeat steps 2 and 3 until the centers stop moving (or barely move). At that point the clusters are stable, and you're done.

Each round, points can switch which cluster they belong to, because the centers shifted. After a handful of rounds, the centers settle into place and every point stays put — that's convergence.

Picking k

k-means needs you to tell it the number of clusters in advance — it doesn't figure that out by itself. If you don't already know how many groups make sense (you rarely do), the common approach is to just try a few different values of k (like 2, 3, 4, 5) and see which one produces clusters that make sense for your data. A more formal version of this is called the elbow method — plotting how tightly-packed the clusters are for each k and looking for the point where adding more clusters stops helping much. You don't need to master the elbow method today — just know the name and that trying a few values of k is the normal starting point.

Dimensionality reduction (PCA) — the idea, not the code

Real datasets often have dozens or hundreds of features (columns) per data point — a customer record might have 200 attributes. Most ML algorithms get slower and less reliable as feature counts grow. Dimensionality reduction techniques, the most common being PCA (Principal Component Analysis), compress many features down into a smaller number of new features, while keeping as much of the important pattern in the data as possible. Think of it as summarizing: instead of tracking 200 separate numbers per customer, PCA might find that 10 new combined numbers capture almost all the useful variation. You don't need to write PCA code today — just recognize the idea: fewer dimensions, same important structure, easier for models (and for humans) to work with.

Try it — before looking below

Q1. You run k-means with n_clusters=3 on a dataset. After the algorithm converges, what has k-means found?

Three cluster centers (centroids), and every data point assigned to whichever center is closest to it. The centers stopped moving because reassigning points and recalculating averages no longer changes anything.

Q2. True or false: k-means figures out the best number of clusters on its own, so you never need to specify k.

False. k-means requires you to specify the number of clusters upfront. You usually try a few values of k and compare results, sometimes using the elbow method to help decide.

Now write your own

In your Colab notebook, install/import scikit-learn's KMeans and run it on a tiny made-up dataset — a handful of 2D points that visually form two or three groups:

from sklearn.cluster import KMeans
import numpy as np

# Six made-up 2D points, visually forming two groups:
# three points clustered near (1,1), three clustered near (8,8)
X = np.array([
    [1, 1],
    [1.5, 2],
    [2, 1.5],
    [8, 8],
    [8.5, 9],
    [9, 8],
])

kmeans_model = KMeans(n_clusters=2, n_init=10, random_state=42)
kmeans_model.fit(X)

print(kmeans_model.labels_)          # which cluster each point belongs to
print(kmeans_model.cluster_centers_) # the two final centroid positions

random_state=42 just makes the result repeatable every time you run it (same starting points). Run it, then look at labels_ — you should see the three points near (1,1) get one cluster number, and the three near (8,8) get the other. Try adding a third group of points and set n_clusters=3 to see it split three ways.

Recap
  • Clustering is unsupervised: no labels, the model finds groups (clusters) using similarity alone.
  • k-means loop: pick k starting centers → assign each point to its nearest center → move each center to the average of its points → repeat until stable.
  • You must choose k yourself — try a few values, or use the elbow method to help decide.
  • PCA (dimensionality reduction) compresses many features into fewer, while keeping the important patterns — useful conceptually even without writing the code yet.
