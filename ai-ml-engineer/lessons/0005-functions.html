Functions & reusable code

In Lesson 4 you wrote code to check if a number is even or odd. If you needed that check in five different places in a program, you'd have to copy-paste it five times. A function lets you write the logic once, give it a name, and reuse it anywhere — just by calling that name.

Simple example: a function is like a kitchen recipe. You write the recipe once ("Pancakes: mix flour + egg + milk, cook 2 min each side"). After that, you just say "make pancakes" — you don't rewrite the recipe every time you're hungry. The recipe can also take ingredients as input (how many eggs?) and hand back a result (a plate of pancakes).

Defining a function: def

You create a function with the def keyword, a name, and parentheses. The code inside runs only when the function is called — not when it's defined.

def greet(name):
    print("Hello, " + name)

greet("Priya")   # this line actually runs the function
greet("Sam")

name here is a parameter — a placeholder variable that receives whatever value you pass in when you call the function. "Priya" and "Sam" are the arguments — the actual values.

Returning a value vs. just printing

This is the single most important distinction in this lesson. Compare these two functions:

def show_double(n):
    print(n * 2)          # displays the result, gives nothing back

def get_double(n):
    return n * 2           # hands the result back to whoever called it

show_double(5) prints 10 to the screen and that's it — the function's result is gone once it's printed. get_double(5) doesn't print anything by itself, but it hands back the value 10, so you can store it, do more math with it, or pass it to another function:

result = get_double(5)
print(result + 1)    # 11 — you can use the returned value

show_double(5)        # prints 10, but show_double(5) itself has no usable value
x = show_double(5)    # x is now None — there was nothing to return

Common trap: if a function has no return statement, Python quietly gives back None instead of raising an error. This is a real, documented rule of the language — not a guess. If your code ever prints None unexpectedly, check whether you forgot a return.

Default argument values

You can give a parameter a default value. If the caller doesn't supply that argument, Python uses the default instead:

def greet(name, greeting="Hello"):
    print(greeting + ", " + name)

greet("Priya")                 # Hello, Priya
greet("Priya", "Namaste")      # Namaste, Priya

This is everywhere in real ML code — for example a model-loading function might have batch_size=32 as a default, so you only override it when you actually need a different value.

Why this matters for AI/ML work

  • No repeated code. Fix a bug once, inside the function, instead of hunting down five copies of the same logic.
  • Every library you'll use is functions. When you later write model.predict(data) or train_test_split(X, y), those are functions someone else already wrote — with parameters, defaults, and return values, exactly like the ones above. Understanding def now means those library calls won't feel like magic.

Try it — before looking below

Q1. def add(a, b): print(a + b) — what does x = add(2, 3) store in x?

None. add only prints, it never returns anything, so Python's default "return nothing" rule (returning None) applies.

Q2. def power(base, exponent=2): return base ** exponent — what does power(5) return?

25. No second argument was given, so Python uses the default exponent=2, and 5 ** 2 == 25.

Now write your own

In your Colab notebook, write a function called is_even(n) that:

  • takes one parameter, n
  • returns True if n is even, False if it's odd (reuse the % logic from Lesson 4)
  • does NOT print inside the function — it must return the result

Then call it a few times to check: print(is_even(4)) and print(is_even(7)).

Try it before looking at the answer.

Reveal the reference answer

def is_even(n):
    return n % 2 == 0

print(is_even(4))   # True
print(is_even(7))   # False

Recap
  • def name(parameters): defines a function; it only runs when called.
  • return hands a value back to the caller so it can be reused; print only displays it and gives nothing back. A function with no return gives back None.
  • Default argument values (def f(x, y=10)) let callers skip arguments they don't need to change.
  • Functions avoid repeated code — and every ML library function you'll call later works the same way: parameters in, a value out.
