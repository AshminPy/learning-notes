Data structures: lists, dicts, tuples, sets

A single variable holds one value. Real data — a dataset, a batch of images, a set of class names — needs to hold many values together. Python gives you four built-in ways to group values, each with a different job. This lesson: list, dict, tuple, and set.

Simple example: think of these like containers in a kitchen. A list is a shopping list — ordered, and you can add or cross things off. A dict is a labeled spice rack — you grab "cumin" by name, not by position. A tuple is a sealed jar — fixed contents, can't change once packed. A set is a bag of unique marbles — no duplicates, order doesn't matter.

List — ordered, and you can change it

A list keeps items in order. Each item has a position (an index), starting at 0.

fruits = ["apple", "banana", "pear"]

print(fruits[0])     # apple  (first item)
print(fruits[-1])    # pear   (last item)

fruits.append("kiwi")
print(fruits)         # ['apple', 'banana', 'pear', 'kiwi']

-1 means "last item", -2 means "second to last", and so on — you don't need to know the list's length to reach the end.

Slicing — grab a chunk

A slice list[start:end] gives you a smaller list. end is not included.

numbers = [10, 20, 30, 40, 50]
print(numbers[1:3])   # [20, 30]   items at index 1 and 2
print(numbers[:2])    # [10, 20]   from the start
print(numbers[2:])    # [30, 40, 50]  to the end

Dict — labeled values, accessed by key

A dict (dictionary) stores key: value pairs. Instead of finding an item by position, you find it by name.

person = {"name": "Priya", "age": 25}

print(person["name"])   # Priya
person["city"] = "Pune"  # add a new key
print(person)             # {'name': 'Priya', 'age': 25, 'city': 'Pune'}

This is why dicts matter for ML: a row of data almost always has named fields — {"age": 25, "income": 50000, "label": "approved"} — and you'll constantly map class names to numbers, e.g. {"cat": 0, "dog": 1}, because models need numbers, not text.

Tuple — like a list, but locked

A tuple looks like a list but uses () instead of [], and once created, it cannot be changed.

point = (10, 20)
print(point[0])   # 10

point[0] = 99      # TypeError: 'tuple' object does not support item assignment

Use a tuple when the values should never change — like an image's fixed (width, height), or a coordinate. It's a small signal to anyone reading your code: "this won't be modified."

Set — unique values, no order

A set keeps only unique values and has no fixed order. Adding a duplicate does nothing.

labels = {"cat", "dog", "cat", "bird", "dog"}
print(labels)   # {'bird', 'cat', 'dog'}  — duplicates removed automatically

This makes sets perfect for de-duplication — e.g. "what are the unique class labels in my dataset?" — set(all_labels) answers that in one line.

Try it — before looking below

Q1. You have colors = ["red", "green", "blue"]. What does colors[-1] give you?

"blue" — -1 always means the last item in the list.

Q2. You need to store a mapping from class name to a number, like "cat" → 0 and "dog" → 1. Which structure should you use, and why?

A dict — {"cat": 0, "dog": 1}. You look up a value by its label (key), which is exactly what a dict is for.

Now write your own

In your Colab notebook, write a program that:

  • builds a dict mapping 3 people's names to their ages, e.g. {"Priya": 25, "Aman": 30, "Zoe": 28}
  • loops over it using .items()
  • prints one sentence per person, e.g. Priya is 25 years old.

Try it before looking at the answer.

Reveal the reference answer

ages = {"Priya": 25, "Aman": 30, "Zoe": 28}

for name, age in ages.items():
    print(name + " is " + str(age) + " years old.")

Recap
  • list — ordered, changeable, access by index ([0], [-1]), grow it with .append().
  • dict — key: value pairs, access by key — the natural fit for labeled data rows and class-name-to-number maps.
  • tuple — like a list but locked after creation; use it for values that must not change.
  • set — unique, unordered values; use it to de-duplicate.
