Cost function & gradient descent

In Lesson 13 you learned that "training" a model means finding the best w (weight) and b (bias). But how does the computer know which w and b are "best"? It needs two things: a way to measure how wrong the current guess is, and a way to improve it step by step. That's this lesson.

Simple example: imagine you're baking bread and adjusting the oven temperature by feel. Each time, you taste the bread (measure how wrong it is) and turn the dial a little in the direction that made it better last time (adjust). You repeat this until the bread tastes right. A model does the same thing with numbers: measure the error, nudge the weights, repeat.

The cost function: measuring how wrong you are

A cost function (also called a loss function) is a single number that says how bad the model's predictions are right now. Small number = good predictions. Big number = bad predictions.

The most common one for regression is Mean Squared Error (MSE). In plain steps:

  • For each data point, find the error: actual - predicted.
  • Square that error (so negative and positive errors don't cancel out, and big errors get punished harder).
  • Average the squared errors across all data points.
MSE = average of (actual - predicted) squared

Example: a model predicts 60 for a student who actually scored 65. The error is 65 - 60 = 5. Squared, that's 25. Do this for every data point, average the results, and you get the MSE — one number that summarizes how good or bad the whole model is.

Common trap: the cost function measures the model, not one prediction. A single wrong guess isn't the "cost" — the cost is the average error across the whole dataset. Change w or b, and the cost changes too.

Gradient descent: walking downhill in fog

Now that we can measure "how wrong," we need a way to get "less wrong." Gradient descent is the algorithm that does this — it's how the model adjusts w and b to make the cost smaller, step by step.

Simple example: imagine you're standing on a hill in thick fog. You can't see the bottom, but you can feel the ground under your feet. To get down, you feel which direction slopes downward, take one step that way, then feel again and take another step. Repeat this enough times and you reach the bottom — the lowest point. Gradient descent does exactly this, except the "hill" is the cost function, and the "position" is the current values of w and b.

Each step of gradient descent:

  1. Look at the current cost (how wrong the model is).
  2. Figure out which direction to nudge w and b to make the cost go down.
  3. Take a small step in that direction.
  4. Repeat, over and over, until the cost stops going down (or barely changes).

The learning rate: how big each step is

The learning rate controls how big each step is. It's a small number you choose before training, like 0.01.

Learning rateWhat happens
Too bigYou overshoot — like taking giant leaps downhill and stepping right past the bottom, maybe even ending up higher than before.
Too smallYou crawl — you do eventually reach the bottom, but it takes a huge number of steps and a long time to train.
Just rightSteady, efficient progress toward the lowest cost.

Picking a good learning rate is one of the first practical tuning decisions you'll make when training real models. There's no calculus needed to understand this — just remember: big steps risk overshooting, tiny steps are slow.

Worked example: minimizing (x - 3)² by hand

Let's watch gradient descent happen on the simplest possible example: a cost function of (x - 3)². This cost is 0 exactly when x = 3, and gets bigger the further x is from 3 — so "3" is the bottom of the hill we're looking for.

We start at x = 0. Each step, gradient descent nudges x a bit closer to 3 — imagine it's using the slope to figure out "closer to 3 means smaller cost," so it moves x in that direction. Here's what a few iterations look like with a reasonable learning rate (using a step size that shrinks the distance to the target by about 20% each time, a common pattern with this cost shape):

Notice the pattern: x moves toward 3 each step, and the cost keeps shrinking (9 → 3.24 → 0.92). The steps also get smaller as x gets closer to 3 — near the bottom of the hill, the "slope" is gentler, so gradient descent naturally takes smaller steps. Given enough iterations, x keeps creeping toward 3 and the cost keeps shrinking toward 0.

Try it — before looking below

Q1. In the worked example above, why does the cost use (actual - predicted)² instead of just actual - predicted?

Squaring makes every error positive, so overestimates and underestimates don't cancel out — and it punishes big errors more heavily than small ones.

Q2. Following the pattern in the table (x moves closer to 3 each step, by a shrinking amount), if step 3 ends at x = 2.51, will step 4 land above 3, below 3, or exactly at 3?

Below 3 — gradient descent keeps closing the gap but takes many small steps to get there, so x would land somewhere around 2.8, still short of 3.

Q3. You train a model and the cost value bounces up and down wildly instead of shrinking smoothly. Is the learning rate most likely too big or too small?

Too big — the steps are overshooting the lowest point of the cost, jumping back and forth instead of settling down.

Now try it yourself

Take the same cost function, (x - 3)², but start at x = 10 instead of x = 0. By hand (or on paper), walk through 3 steps using the same idea: each step, move x about 20% of the remaining distance closer to 3.

  • Step 1: distance to 3 is 10 - 3 = 7. Move 20% of that (1.4) closer. Where does x land?
  • Step 2: repeat from your new x.
  • Step 3: repeat again.

Try it before revealing.

Reveal the reference answer

Step 1: 10 - (0.2 * 7) = 8.6
Step 2: distance is 8.6 - 3 = 5.6, move 1.12 closer → x = 7.48
Step 3: distance is 7.48 - 3 = 4.48, move 0.896 closer → x = 6.58

Same pattern as before: x keeps sliding toward 3, and the steps shrink as it gets closer. It just needs more steps this time because it started further away.

Recap
  • A cost function (like Mean Squared Error) is one number that measures how wrong the model's predictions are — smaller is better.
  • Gradient descent adjusts w and b step by step to make the cost smaller, like walking downhill in fog by feeling the slope.
  • The learning rate controls step size: too big overshoots, too small is slow to train.
  • Steps naturally shrink as you get closer to the lowest cost — progress slows down but keeps going in the right direction.
Confused about why the cost "shrinks slower" near the bottom? Ask — this same pattern shows up in every model you'll train from here on.
