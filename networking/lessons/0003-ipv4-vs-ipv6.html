IPv4 vs IPv6 Basics

IPv4 addresses are 32 bits — about 4.3 billion possible addresses, a number the internet has already exhausted at the registry level. IPv6 was built specifically to solve that: 128 bits, an address space so large that exhaustion isn't a realistic concern. Both protocols run today, often side by side, which is exactly why understanding both matters.

Simple example: An IPv4 address looks like 10.0.1.5 — four decimal numbers. An IPv6 address looks like 2001:0db8:85a3:0000:0000:8a2e:0370:7334 — eight groups of hexadecimal digits, usually shortened by dropping leading zeros and collapsing one run of zero groups with ::.

Shortening IPv6 addresses

Two rules make IPv6 addresses shorter to write: drop leading zeros within each group (0db8 becomes db8), and replace exactly one consecutive run of all-zero groups with ::. 2001:0db8:0000:0000:0000:0000:0000:0001 becomes 2001:db8::1.

:: can only be used once in an address — using it twice makes the address ambiguous (the parser can't tell how many zero groups belong to each gap), so it's invalid and will be rejected by any correct tool.

Why this matters in cloud work

Most cloud VPCs default to IPv4, but IPv6 support is increasingly standard for public-facing resources — and because IPv6 has enough address space for every device to have a real, routable address, NAT (Lesson 12) becomes optional rather than mandatory the way it effectively is for IPv4 private networks.

Try it — before looking below

Q1. Why doesn't IPv6 strictly need private address ranges and NAT the way IPv4 does?

Because the address space is so large that every device can be assigned a globally unique address directly — NAT in IPv4 exists largely to conserve a scarce 32-bit address space, a constraint IPv6's 128 bits don't have.

Now try it yourself

ip -6 addr show          # see any IPv6 addresses this machine already has
ping6 ::1                 # or: ping -6 ::1 — test the IPv6 loopback

Source

RFC 8200 — Internet Protocol, Version 6 (IPv6) Specification — the official IETF specification.

Recap
  • IPv4 is 32 bits (~4.3 billion addresses, exhausted); IPv6 is 128 bits (effectively unlimited for practical purposes).
  • IPv6 addresses shorten by dropping leading zeros per group and collapsing one run of zero groups with :: — usable only once per address.
  • IPv6's address abundance makes NAT optional rather than structurally necessary.
Both protocols will keep running side by side for the foreseeable future — knowing both, not just IPv4, is what "networking fluent" actually means today.
