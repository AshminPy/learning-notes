Routing Fundamentals

A router's whole job is answering one question for every packet: "which direction does this go next?" It answers that by checking the packet's destination IP against a routing table — an ordered list of network ranges and the next hop for each — and forwarding accordingly. Every device with a network connection has its own routing table, not just dedicated routers.

Simple example: Your laptop's routing table has one entry for your local network (send directly) and a "default route" — the catch-all for everything else, which sends the packet to your router to figure out the rest of the journey.

Reading a routing table

ip route show
default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.42
LineMeaning
192.168.1.0/24 dev eth0 ...Anything in this local subnet: send directly out this network interface
default via 192.168.1.1Everything else: send to this gateway IP, and let it figure out the next hop

Routing tables use "longest prefix match" — if a packet's destination matches multiple entries, the most specific one (the longest prefix, like /32 over /24) wins. The default route (0.0.0.0/0) is the least specific possible match, which is exactly why it's the fallback for everything not covered by a more specific entry.

Static vs. dynamic routing

Static routes are manually configured and don't change unless someone changes them — fine for small, stable networks (most cloud VPC route tables are static). Dynamic routing protocols (like BGP, which decides how traffic flows across the internet itself) let routers automatically discover and adapt to network changes — essential at internet scale, generally not something you configure by hand inside a single cloud VPC.

A route existing in the table doesn't guarantee the destination is actually reachable — it just tells the packet where to go next. If that next hop is down, or a firewall blocks it further along, the packet still fails. A route is a direction, not a promise.

Try it — before looking below

Q1. Your routing table has both 10.0.0.0/16 and 10.0.1.0/24 as entries with different next hops. A packet is headed to 10.0.1.5. Which entry wins?

The 10.0.1.0/24 entry — longest prefix match means the more specific route (/24, narrower range) always wins over a broader one (/16) when both match.

Now try it yourself

ip route show               # your machine's own routing table
ip route get 8.8.8.8         # which route would actually be used to reach this address

Source

RFC 1812 — Requirements for IP Version 4 Routers — the official IETF reference for routing behavior.

Recap
  • A routing table maps destination network ranges to a next hop — every network-connected device has one, not just dedicated routers.
  • Longest prefix match wins when multiple routes match — a default route (0.0.0.0/0) is the least-specific fallback.
  • Static routes are manually set (typical for a cloud VPC); dynamic routing protocols like BGP adapt automatically at internet scale.
When traffic mysteriously takes an unexpected path, checking the routing table with longest-prefix-match in mind is usually faster than assuming a firewall issue.
