Part 1 — Command cheat sheet

A. Foundations

  • git init / git config --global user.name/user.email — start a repo, set identity
  • git add <file> / git commit -m "msg" / git status / git log --oneline — the basic cycle

B. Branching & Merging

  • git branch <name> / git checkout -b <name> — create (and switch to) a branch
  • git merge <branch> — join histories, keeps both, may create a merge commit
  • git rebase <branch> — replay commits on top of another branch, linear history, new hashes
  • Conflict markers <<<<<<< / ======= / >>>>>>> — edit to the intended result, git add, then commit (merge) or rebase --continue

C. Remotes & Hygiene

  • git remote add origin <url> / git push -u origin <branch> / git pull / git fetch
  • .gitignore — patterns for files Git should never track

D. Undoing & Rewriting History

  • git restore <file> — discard uncommitted changes (no history rewrite)
  • git reset <commit> — move branch pointer backward (rewrites history — unsafe if shared)
  • git revert <commit> — new commit undoing an old one (safe on shared history)
  • git stash / git stash pop / git stash apply — shelve and restore uncommitted work
  • git rebase -i HEAD~N — squash/reword/reorder/drop recent commits (unsafe if shared)
  • git cherry-pick <commit> — apply one specific commit onto the current branch
  • git tag -a v1.0 -m "msg" — permanent pointer to one commit; git push origin --tags to share
  • git blame <file> — last commit/author per line; git bisect — binary search for a regression
  • git reflog — local log of every place HEAD/branches have pointed — the recovery net for almost everything above

E. GitHub Workflows

  • Pull requests — a live diff + review + CI, merge via merge commit / squash / rebase
  • .github/workflows/*.yml — on (trigger), jobs, steps; actions/checkout always first
  • Branch protection — required approvals, required status checks, "up to date before merge"
  • git submodule add <url> <path> / git submodule update --init --recursive — pinned sub-repositories

Top 7 traps

  1. Rebasing or resetting commits that others have already pulled creates a divergence — use revert, not reset/rebase, on anything shared (Lessons 9, 11).
  2. git stash skips untracked files by default — use -u, or a genuinely new file silently stays behind (Lesson 10).
  3. A cherry-pick or stash pop can conflict exactly like a merge — same resolution steps, not a special case (Lessons 10, 12).
  4. Tags don't push with a normal git push — --tags or the tag name explicitly (Lesson 13).
  5. A PR conflict blocks auto-merge but doesn't disappear on its own — resolve locally, push, the PR updates (Lesson 15).
  6. Every GitHub Actions run starts on an empty filesystem — skip actions/checkout and every later step referencing repo files fails (Lesson 16).
  7. A "lost" commit after reset --hard or a rebase almost always still exists — git reflog finds the hash, before assuming it's gone forever (Lesson 19).

Part 2 — Practical final assessment (timed)

One task per course phase (A-F). Time yourself — targets below are a competent-pace guide, not a hard limit. Attempt fully before revealing the hidden answer.

Task 1 — Branching & Merging (Phase B) · target 6 min
Create a branch, make a conflicting change to the same line on both it and main, merge, and resolve the conflict.

Success criteria: the merge completes with both changes reconciled into one final line, and git log --graph --oneline shows a merge commit.
Verification command: git log --graph --oneline -5

echo a > f.txt && git add f.txt && git commit -m "base"
git checkout -b feature
echo b >> f.txt && git commit -am "feature change"
git checkout main
echo c >> f.txt && git commit -am "main change"
git merge feature
# resolve conflict markers in f.txt to the intended combined result
git add f.txt
git commit
Doc: git-scm.com/docs/git-merge.

Task 2 — Undoing & Rewriting History (Phase D) · target 8 min
Make two commits, hard-reset past both by mistake, then recover them using only the reflog.

Success criteria: both commits are reachable from your branch again, with their original hashes unchanged.
Verification command: git log --oneline -3

echo a > f.txt && git add f.txt && git commit -m "one"
echo b >> f.txt && git commit -am "two"
git reset --hard HEAD~2
git reflog                    # find the hash next to "commit: two"
git reset --hard <that-hash>
Doc: git-scm.com/docs/git-reflog.

Task 3 — Undoing & Rewriting History (Phase D) · target 7 min
Squash three small commits on a scratch branch into one clean commit using interactive rebase.

Success criteria: git log --oneline shows exactly one new commit replacing the original three.
Verification command: git log --oneline -3

echo a > f.txt && git add f.txt && git commit -m "add f"
echo b >> f.txt && git commit -am "wip"
echo c >> f.txt && git commit -am "fix wip"
git rebase -i HEAD~2
# change both "pick" lines after the first to "squash" (or "s"), save,
# then write a combined commit message
Doc: Pro Git — Rewriting History.

Task 4 — Remotes & Hygiene (Phase C) · target 5 min
Push a branch to a remote, then confirm what would happen to an already-tracked file if you added it to .gitignore now.

Success criteria: correctly predict and verify that .gitignore alone does NOT untrack a file Git is already tracking.
Verification command: git status

echo secret.txt > f.txt && git add f.txt && git commit -m "oops, tracked it"
echo "f.txt" >> .gitignore
git status              # f.txt still shows as tracked/modified, NOT ignored
git rm --cached f.txt   # this is the actual fix — untrack without deleting the file
git commit -am "stop tracking f.txt"
git status              # now genuinely ignored
Doc: git-scm.com/docs/gitignore.

Task 5 — GitHub Workflows (Phase E) · target 10 min
Write a GitHub Actions workflow that runs on every push to main, checks out the repo, and fails on purpose if a file named REQUIRED.md doesn't exist.

Success criteria: the workflow YAML is syntactically valid and the job fails with a clear reason if REQUIRED.md is missing.
Verification command: push to a scratch repo and check the Actions tab, or run test -f REQUIRED.md locally to confirm the check's logic first.

name: Require File
on:
  push:
    branches: [main]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: test -f REQUIRED.md || (echo "REQUIRED.md is missing" && exit 1)
Doc: docs.github.com — GitHub Actions quickstart.

Task 6 — Undoing & Rewriting History (Phase D) · target 6 min
Cherry-pick one specific commit from a feature branch onto main without merging the whole branch.

Success criteria: the exact change from that one commit appears on main, as a new commit with a different hash than the original.
Verification command: git log --oneline main -2

git checkout -b feature-y
echo x > g.txt && git add g.txt && git commit -m "the fix"
FIX=$(git rev-parse HEAD)
git checkout main
git cherry-pick $FIX
git log --oneline main -2   # new hash, different from $FIX, same change
Doc: git-scm.com/docs/git-cherry-pick.

Recap
  • History-rewriting commands (reset, rebase) are unsafe on shared branches; revert and cherry-pick are the safe, additive alternatives.
  • Almost every "lost work" scenario in this course has a recovery path — stash for interruptions, reflog for rewound history.
  • Reading this cheat sheet proves recall. Finishing Part 2 under its time targets proves you can actually do the work — do both, don't stop at Part 1.
