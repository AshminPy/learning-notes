Installing & Configuring Git

Before your first real commit, Git needs to know who you are — every commit permanently records an author name and email. Getting this right once, globally, means you never have to think about it again on a new repository.

Simple example: git config --global user.name "Ada Lovelace" and git config --global user.email "ada@example.com" set your identity for every repository on this machine. Without this, Git will refuse to let you commit until it's set.

Config has three levels

LevelFlagApplies toStored in
System--systemEvery user on this machineA system-wide config file
Global--globalEvery repository for the current user~/.gitconfig
Local(no flag, or --local)Just the current repository.git/config inside that repo

More specific always wins — a local setting overrides a global one, which overrides a system one. This is exactly why you can set your personal email globally, then override it with a work email locally inside a work repository, without those two settings conflicting.

Worth setting on day one

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git config --global core.editor "vim"       # or whatever editor you actually use
git config --list                            # see everything currently set, and where it came from

Committing with the wrong email (a common issue when switching between a personal and work machine, or personal and work GitHub accounts) means the commit won't be correctly attributed to your GitHub account in that repo's history — worth checking git config user.email whenever you clone a new repository tied to a different identity, not assuming the global default is always right.

Aliases — small time savers that compound

A Git alias lets you define a shortcut for a longer command: git config --global alias.st status means git st now runs git status. This seems trivial for one command, but compounds fast across the dozens of Git commands you'll run daily throughout this course.

Try it — before looking below

Q1. You set your email globally to your personal address, but this specific repository needs your work email instead. What's the right way to handle that, without changing your global setting?

Run git config user.email "work@example.com" without --global, from inside that specific repository — a local setting overrides the global one only for that repo, leaving your global default untouched everywhere else.

Now try it yourself

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --list --show-origin | head -10   # see what's set and which file it came from

Recap
  • Git config has three levels — system, global, local — with local overriding global overriding system.
  • user.name and user.email are the two essential settings; every commit records them permanently.
  • A repository tied to a different identity (work vs. personal) needs its own local override, not a change to your global default.
Cloning a new repository under a different GitHub account? Check git config user.email in that repo before your first commit — it's a two-second check that avoids a wrongly-attributed commit later.
