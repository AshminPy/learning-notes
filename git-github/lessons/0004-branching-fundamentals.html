Branching Fundamentals

A branch is just a movable pointer to a commit — not a copy of your project. Creating a branch is instant and cheap precisely because of the snapshot model from Lesson 1: Git doesn't duplicate any files, it just adds a new named pointer alongside the ones you already have.

Simple example: git branch shows every pointer you currently have (main, maybe feature-login). git checkout -b feature-login (or the newer git switch -c feature-login) creates a new pointer starting from your current commit, and moves you onto it — from here, new commits advance that branch's pointer, leaving main untouched.

The core branch commands

CommandWhat it does
git branchList branches; current one marked with *
git branch <name>Create a new branch (doesn't switch to it)
git switch <name>Switch to an existing branch
git switch -c <name>Create and switch in one step
git branch -d <name>Delete a branch (safe — refuses if it has unmerged commits)

git switch is the newer, clearer command for changing branches — git checkout still works and is common in older material and habits, but it also does file-restoration duty (Lesson 9), which is exactly the kind of overloaded command switch and restore were introduced to separate.

HEAD — what "current branch" actually means

HEAD is Git's pointer to whatever you currently have checked out — normally, that's a pointer to your current branch, which itself points to a commit. When you commit, HEAD's branch pointer advances to the new commit. Understanding HEAD as "where you are right now" (rather than a fixed location) makes several later topics — detached HEAD state, rebase, reset — click faster.

Committing directly on main for exploratory or risky work is a common habit that's hard to cleanly undo later — a throwaway branch costs nothing to create and everything to skip. Default to branching for anything beyond a trivial one-line fix.

Try it — before looking below

Q1. You create a new branch from main and make 3 commits on it. Does main change at all during this?

No — main's pointer stays exactly where it was. Only the new branch's pointer advances with each commit. This is exactly why branches are safe to experiment on: nothing you do there touches main until you explicitly merge it back.

Now try it yourself

git switch -c my-first-branch
echo "experiment" > scratch.txt
git add scratch.txt
git commit -m "try something"
git log --oneline --all --graph    # see both branches' history visually
git switch main                     # back to main — scratch.txt is gone from view here

Recap
  • A branch is a lightweight, movable pointer to a commit — not a copy of the project, which is why creating one is instant.
  • HEAD tracks where you currently are; committing advances the current branch's pointer, not any other branch.
  • Default to branching for anything beyond a trivial change — it costs nothing and keeps main safe.
git log --oneline --all --graph is worth running often early on — seeing the branch structure visually makes the pointer model concrete instead of abstract.
