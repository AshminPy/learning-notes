3. Mental models that matter more than syntax

  • Idempotency is the core idea the whole course builds on. A properly-written playbook run twice reports changed=0 the second time — the same end-state discipline Terraform applies to infrastructure, applied here to configuration. (Lesson 7)
  • Agentless and push-based. No software pre-installed on managed hosts; you trigger every run from the control node over SSH. (Lesson 3)
  • Precedence has one fixed order, and the higher source wins completely — nothing merges. Role defaults lose to everything; -e beats everything. (Lesson 22)
  • A proper module beats shell/command almost every time — not just for idempotency (Lesson 7), but for real performance at scale, since a module can report "nothing to do" instead of re-running blindly. (Lesson 33)
  • Vault encrypts a file's actual bytes — a real security boundary, not a display filter. Commit the encrypted file; never commit the password. (Lesson 26)
  • A role is the configuration-layer equivalent of a reusable module — one folder, one responsibility, callable from any playbook. (Lesson 16)
  • Dynamic inventory exists because infrastructure that autoscales can't be hand-edited into a static file fast enough. (Lesson 20)
