Keyboard Workflow — Lesson 3 of 4

Warp, from first principles

You run Warp as your daily terminal, pinned to its own AeroSpace workspace. This lesson covers three features that save keystrokes: Blocks, Command Search / Command Palette, and Workflows — the direct fix for retyping the same SSH command, kubectl context switch, and terraform plan flags.

Blocks: the mental model departure

A normal terminal is one long scroll of text — command output runs into the next command with no boundary. Copying just one result means click-dragging and hoping you got the edges right.

Warp groups every command and its output into a Block — one addressable unit. Copy, share, bookmark, re-run, or jump to it directly.

This matters most after a noisy command — terraform plan, a long kubectl describe, a build log. Jump straight to the block boundary instead of scrolling past pages of output.

Command Search vs Command Palette

They sound the same. They're not. Command Search (Ctrl-R, same muscle memory as bash reverse-search) is fuzzy search over things you've done or saved: history, Workflows, env vars, Notebooks, Prompts. Command Palette (Cmd-P) is broader — any Warp action or setting, not just history. Prefix with workflows:, notebook:, or actions: to scope it.

Rule of thumb: something you've run before → Ctrl-R. A Warp feature or setting → Cmd-P.

Workflows: the highest-value feature for you

A Workflow is a saved, named command with optional arguments — the fix for retyping SSH, kubectl, and terraform commands.

Three ways to save one: a block's action menu ("Save as Workflow," pre-filled), the Command Palette ("Create a New Personal Workflow," from scratch), or Warp Drive (Warp's storage panel, "+ > New workflow").

Parameterized arguments

Wrap the variable part in {{argument_name}}. Save ssh {{host}} once — next time, Warp pastes it into your input line with the cursor on host. Names use letters, numbers, hyphens, underscores; can't start with a number.

  • Default values — enter runs something sensible even with no changes.
  • Enum arguments — restrict to a fixed list (static, or generated from a shell command, e.g. your kubectl contexts). Shift-Tab cycles suggestions.

A Workflow never runs silently — it pastes into your input line for review before you press enter. For a terraform apply or kubectl delete, that pause is a feature.

Try it

Run a command you actually retype (SSH, kubectl context, or terraform plan). Block action menu → "Save as Workflow," wrap one part in {{ }}. Open Command Palette (Cmd-P), find it, run it once.

Tabs and panes

AeroSpace gives Warp its own workspace; tabs/panes are the finer split inside it: Cmd-T new tab, Cmd-1…9 jump to tab, Shift-Cmd-{/} previous/next tab, Ctrl-Shift-D split pane, Alt-Cmd+arrows move focus between panes.

Quiz

Q1. What is the core idea behind a Warp Block?

A. Command and output are grouped into one addressable unit — Warp's core departure from a normal scroll.

Q2. Which shortcut jumps you between blocks?

A. B, C, D are real shortcuts, just for different tools (search, palette, new tab).

Q3. What's the practical difference between Command Search and the Command Palette?

A. Palette is the broad, global search for any feature; Search is scoped to history/Workflows/Notebooks/Prompts.

Q4. Where can you save a command as a Workflow?

A. All three are documented entry points — no config editing, no paid gate needed.

Q5. How do you mark part of a saved command as a fill-in argument?

A. Warp's syntax is {{argument_name}} — not shell $var or any other convention.

Recap
  • Blocks group each command with its output into one navigable unit (Cmd-Up/Down).
  • Command Search (Ctrl-R) searches what you've done; Command Palette (Cmd-P) searches any Warp action.
  • Workflows save a command with {{argument}} placeholders and paste for review — never run silently.
