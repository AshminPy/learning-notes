Keyboard Workflow — Lesson 3 of 4

Warp, from first principles

You already run Warp as your daily terminal, pinned to its own AeroSpace workspace. This lesson is about the three features that turn Warp from "a terminal that looks nicer" into a terminal that actually saves you keystrokes on the commands you already run every day: Blocks, Command Search / the Command Palette, and Workflows. Workflows is the one that matters most for you — it's the direct answer to "how do I stop retyping the same SSH command, kubectl context switch, and terraform plan flags."

Blocks: the mental model departure

A traditional terminal is one undifferentiated scroll of text. Command output and the next command's output run together with nothing marking where one ends and the next begins — if you want to copy just one command's result, you click-drag a selection across a wall of text and hope you got the boundaries right.

Warp groups every command and its output into a Block — a distinct, addressable unit. Each block can be individually copied (command only, output only, or both), shared, bookmarked, re-run, or jumped to directly — without touching anything before or after it.

This matters most right after a command that produces a lot of output — terraform plan, a verbose kubectl describe, a long build log. Instead of scrolling past pages of plan output to find the command you ran before it, you jump straight to the block boundary.

Shortcut (macOS)What it does
Cmd-Up / Cmd-DownSelect the previous / next block
Shift-Cmd-Up / Shift-Cmd-DownScroll to the top / bottom of a long block's output
Alt-Up / Alt-DownJump between your bookmarked blocks specifically
Shift-Up / Shift-DownExpand the current block selection

Command Search and the Command Palette: two related search tools

These sound like the same thing. They're not — and knowing the difference is what makes both fast.

Command Search (Ctrl-R — yes, the same muscle memory as bash/zsh reverse-search) is a fuzzy search scoped to things you've done or saved: command history, Workflows, environment variables, Notebooks, and Prompts, all in one search box. This is your fast path to "I ran something like this last week, what was it."

Command Palette (Cmd-P) is broader: it's Warp's global search for finding and launching any Warp action — Workflows, Notebooks, keyboard shortcuts, file search, settings — not just things tied to your history. Prefix your search with workflows:, notebook:, or actions: to scope it directly.

Rule of thumb: reaching for something you've run before → Ctrl-R. Reaching for a Warp feature or setting (or you're not sure which search has it) → Cmd-P. Both get you there without the mouse.

Workflows: the highest-value feature for you

A Workflow is a saved, named command with a description and optional arguments. This is the direct fix for "I keep retyping the same SSH command, kubectl context switch, and terraform plan flags."

Three ways to save a command as a Workflow

  1. From a block's action menu — after running a command, open the block's actions and choose "Save as Workflow." Fastest option: you just ran the exact command, so Warp starts the editor pre-filled with it.
  2. From the Command Palette (Cmd-P) — search "Create a New Personal Workflow" and build one from scratch, no prior run required.
  3. Directly in Warp Drive — Warp's storage/organization panel for saved items — via "+ > New workflow."

Parameterized arguments

Wrap the variable part of a command in double curly braces: {{argument_name}}. Save ssh {{host}} once, and every time you pull that Workflow up, Warp pastes the full command into your input line with the cursor sitting on host, ready for you to type the value and hit enter. Argument names can use letters, numbers, hyphens, and underscores, but can't start with a number.

Two details worth knowing:

  • Default values. Give an argument a default so pressing enter with no changes still runs something sensible — useful for a host or context you use most often.
  • Enum arguments. Instead of free text, restrict an argument to a fixed list of values (static, or generated from a shell command's output — e.g. your actual list of kubectl contexts). Press Shift-Tab while the Workflow is loaded to cycle through suggestions.

A Workflow never runs silently. Selecting it pastes the full command into your input line — you see exactly what will execute, with your argument values filled in, before you press enter. For something like a terraform apply or kubectl delete pattern, that pause-to-review is a feature, not friction.

Try it — right now, on a real command

Pick one command you actually retype often (your real SSH connection, kubectl context switch, or terraform plan). Run it in a block, open the block's action menu, choose "Save as Workflow," and wrap at least one part of it in {{ }} to make it an argument. Then open the Command Palette (Cmd-P), search for the Workflow by name, and run it once to confirm the argument fills in correctly.

Quiz

Q1. What is the core idea behind a Warp Block?

A. This is Warp's core departure from a traditional terminal — command and output are grouped into one distinct, addressable unit. B is wrong: history is a separate feature (Command Search), not what defines a block. C describes the old undifferentiated-scroll behavior Blocks specifically replace. D is unrelated — themes are an appearance setting, not what a block is.

Q2. On macOS, which shortcut jumps you between blocks?

A. Cmd-Up/Cmd-Down select the previous/next block directly. B is a real shortcut but it's for Command Search, not block navigation. C is real but opens the Command Palette, a different tool entirely. D is real but opens a new tab, not related to blocks at all.

Q3. What's the practical difference between Command Search and the Command Palette?

A. The Command Palette is the broad, global search for any Warp feature or setting — not limited to things you've run before. B is false — Command Search isn't tool-specific, it searches history/Workflows/Notebooks/Prompts generally. C is false — you search and select, you don't retype full commands. D is false — Command Search and Blocks are separate features that coexist.

Q4. Where can you save a command as a Workflow?

A. All three are documented entry points: a block's "Save as Workflow" action, the Command Palette's "Create a New Personal Workflow," and Warp Drive's "+ > New workflow." B, C, and D describe paths that don't exist — no config-file editing, no paid gate, and no need to ask anyone.

Q5. How do you mark part of a saved command as a fill-in argument?

A. Warp's argument syntax is {{argument_name}} — double curly braces around the variable part. B describes shell variable syntax, not Warp's Workflow syntax. C describes a different bracket style Warp doesn't use for this. D is an invented convention that isn't how Warp parses arguments.

Q6. You save ssh {{host}} as a Workflow. What happens when you run it later?

A. The command pastes into your input line with the cursor on the host placeholder, waiting for your value (or a default, if you set one). B and C both wrongly imply Warp auto-fills from memory without asking. D is wrong — the placeholder stays until you fill it or accept a default.

Q7. Why does running a Workflow paste it into the input line instead of executing it right away?

A. Pasting instead of auto-running means you see the exact command, with arguments filled in, before it executes — important for anything with real consequences like terraform apply or kubectl delete. B is false — Warp executes commands constantly, that's its whole job. C is false — Workflows are runnable commands, not passive docs. D is false and unrelated to how Workflows behave.

Recap
  • Blocks group each command with its output into one navigable, copyable, shareable unit. Cmd-Up/Cmd-Down jumps between them.
  • Command Search (Ctrl-R) searches things you've done or saved. Command Palette (Cmd-P) searches any Warp action or setting.
  • Workflows save a command with a name and optional {{argument}} placeholders — save from a block's action menu, the Command Palette, or Warp Drive directly.
  • Running a Workflow pastes it into your input line for review, it never executes silently.
  • Your first three: an SSH connection, a kubectl context switch, a terraform plan — parameterize the part that actually changes.

Try solo: save all three of your real repeat commands (SSH, kubectl context, terraform plan) as Workflows this week, each with at least one parameterized argument, and run each once from the Command Palette.
