Keyboard Workflow — Lesson 1 of 8

AeroSpace, from first principles

AeroSpace is a tiling window manager for macOS. This lesson builds a real config from scratch and explains why each part is shaped the way it is — by the end you'll have a working ~/.aerospace.toml and understand every line in it, not just have pasted someone else's.

The one idea that explains everything else

Stock macOS treats windows like papers on a desk — you drag each one where you want. AeroSpace is different: it's a tiling window manager. Windows live in a tree, and the tree decides position and size. You never drag a window by its edge.

Tree, top to bottom: Workspace (a virtual desktop) → Container (a box holding windows or more containers) → Window (a leaf, holds nothing else).

Try it

Install AeroSpace (official guide), then create an empty ~/.aerospace.toml. Add each block below to it as you read about it — you'll have a complete, working config by the end of this lesson.

Two decisions every config starts with

default-root-container-layout = 'accordion'
default-root-container-orientation = 'horizontal'

Layout — how windows share a container:

  • tiles — grid. Every window gets a visible slice.
  • accordion (the example above) — only the focused window is fully visible. The rest collapse to a thin strip, like file folders in a drawer.

Orientation — which way new splits happen. horizontal means left/right.

Try it

Open two windows in one workspace. Press alt-slash and watch accordion switch to side-by-side tiles. Press again to go back.

Focus and move: navigating the tree

ctrl-alt-h/j/k/l = 'focus left/down/up/right'

This is spatial, not "next window" like Cmd-\`. AeroSpace jumps to whatever window sits physically in that direction. Add shift and it moves the window instead of just your focus.

Q1. What does ctrl-alt-shift-l do?

A. shift turns a focus binding into a move binding — same key, different verb.

Modes: a keybinding namespace switch

A full config splits bindings into [mode.main.binding] and [mode.service.binding] — like Vim's normal/insert modes, but for windows. Add a service mode and it gives you esc (reload config), r (flatten tree), f (toggle floating), backspace (close all but current).

"Floating" is the escape hatch — a floating window ignores the tree and drags like normal macOS. Good for dialogs and small utilities.

Workspace-to-monitor: pinning, not switching

[workspace-to-monitor-force-assignment]
"1" = "Built-in Retina Display"
"2" = "External Monitor"

In this example, workspace 1 is pinned to the laptop screen and workspace 2+ to an external monitor (use aerospace list-monitors to get your own monitors' exact names). Combine this with on-window-detected rules to give every app a fixed home, always:

[[on-window-detected]]
if.app-id = 'com.google.Chrome'
run = ['move-node-to-workspace 1']

[[on-window-detected]]
if.app-id = 'dev.warp.Warp-Stable'
run = ['move-node-to-workspace 4']

Try it

Add the two on-window-detected rules above to your config, reload (service mode → esc), then relaunch one of those apps. Confirm it lands on the workspace its rule specifies, not wherever it opened last.

Quiz

Q2. What's the key difference between "tiles" and "accordion" layout?

A. Tiles shows every window at once; accordion shows only the focused one, collapsing the rest.

Q3. What does default-root-container-orientation = 'horizontal' control?

A. Orientation is only about split direction — nothing to do with floating or monitors.

Q4. What is "service mode," conceptually?

A. A mode is just an alternate keybinding set, active only while you're "in" it — same idea as Vim.

Q5. You move Warp to workspace 7 manually, then quit and relaunch it. Where does it open?

A. on-window-detected forces Warp to workspace 4 on every new window — it doesn't remember where you moved it.

Recap
  • Windows live in a tree: workspace → container → window. You arrange it, never drag windows.
  • Layout (tiles vs accordion) controls how windows share space. Focus moves attention; move (shift+) relocates the window.
  • Modes are alternate keybinding sets; on-window-detected auto-routes apps to workspaces.

Try solo: add one new [[on-window-detected]] rule for an app you use often, reload with your service-mode esc binding, confirm it lands right.
