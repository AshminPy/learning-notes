Keyboard Workflow — Lesson 5 of 8

eza, bat, fd: sharper defaults

ls, cat, and find still work. They were just built for a terminal with no color and no idea what a Git repo is. eza, bat, and fd do the exact same three jobs — list, read, search — with better defaults, and no new syntax to memorize for the basic case.

Simple example: same three habits you already have — look at a folder, read a file, search for something — just with more useful information showing up automatically, without extra flags. No new muscle memory, just a better picture.

eza — a sharper ls

eza replaces ls. Long listing is eza -l (add -h for human-readable sizes); add --git to show each file's Git status as an extra column, right in the listing — no separate git status needed.

eza -lh --git
eza -T          # tree view (--tree also works)

Tree view is -T / --tree — one flag, no separate tree install. Icons need a Nerd Font in your terminal; turn them on with --icons=auto.

A couple of aliases people commonly add — optional, only if you'll actually use them:

alias ll='eza -lh --git'
alias lt='eza -T --icons=auto'

bat — cat with syntax highlighting

bat replaces cat. Same basic usage — bat file.py — but the output is syntax-highlighted, and inside a Git repo it adds small markers in the left gutter showing lines added or changed versus the last commit.

If you already have a function like awsbat() { command aws "$@" | bat } in your shell config, it was silently broken before bat was installed — the pipe hit "command not found" and the function just failed. Installing bat fixes it with zero code changes, because the binary the function was always calling now exists.

One default worth knowing: piped into another command or a file, bat detects it isn't a real terminal and quietly falls back to plain output, like cat — so scripts that pipe bat's output elsewhere still get clean text, not color codes.

fd — a simpler find, with one real gotcha

fd replaces find for the common case. Instead of find . -iname "*pattern*", it's just:

fd pattern

The gotcha: fd ignores anything listed in your .gitignore by default. Search inside a repo for a file that's gitignored (build output, node_modules, a log file) and fd will find nothing — find would have shown it every time. This is the one place fd's default behavior is genuinely different from what find trained you to expect, not just shorter syntax. Add -I / --no-ignore to search everything anyway.

Try it

In one directory, run all three back to back: eza -la, then bat on any file in it, then fd for part of a filename you know is there. Compare each against what ls -la, cat, and find . -name would have shown you for the same thing.

Quiz

Q1. Which eza flag turns on tree view?

A. eza's documented flag is -T / --tree — no separate tree binary required.

Q2. What does eza's --git flag add to a listing?

A. --git lists each file's Git status right in the listing — tracked, modified, or ignored.

Q3. What shows up in bat's left gutter inside a Git repo?

A. bat talks to git and shows modification markers against the index — a quick visual diff while just reading a file.

Q4. By default, what does fd skip that find would show?

A. fd respects .gitignore by default — genuinely different from find, not just shorter to type. Use -I to search everything.

Q5. A shell function that pipes output into bat was failing before bat was installed. Why did it start working afterward, with no code change?

A. The function's code was never wrong — it called a command that didn't exist yet. Installing bat put the binary on PATH, so the same pipe now works.

Recap
  • eza replaces ls: -l/-h for long/human sizes, --git for status, -T for tree view.
  • bat replaces cat: syntax highlighting plus Git change markers in the gutter; falls back to plain text when piped.
  • fd replaces find: fd pattern, but it skips anything gitignored unless you pass -I.

Try solo: run all three on a real project directory this week and notice the one moment fd finds nothing where find would have.
