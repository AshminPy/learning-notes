Keyboard Workflow — Lesson 7 of 8

tldr and btop: fast reference, fast monitoring

This is the last tool-specific lesson. Lesson 8 ties everything — AeroSpace, Raycast, Warp, and this — into one daily workflow. Today: two small terminal tools that replace two habits that cost you time — reaching for man, and reaching for top.

Simple example: a man page is the full instruction manual for a power tool — every bolt, every warning, every edge case. Most days you just need the one sentence a coworker would tell you: "hold this button, turn that dial." tldr is that coworker, for the terminal.

tldr: examples instead of the whole manual

man tar opens a long reference document, and the first option it explains is one you'll almost never use. tldr replaces that with a short, community-maintained cheat sheet of the commands people actually run:

tldr tar

- [c]reate an archive and write it to a [f]ile:
    tar cf target.tar file1 file2

- [c]reate a g[z]ipped archive:
    tar czf target.tar.gz file1 file2

- E[x]tract a (compressed) archive [f]ile:
    tar xvf source.tar.gz

Five common invocations, not a full reference. Pages are written and reviewed by the community, so they cover what people actually type.

First run needs a local page cache — there's nothing to show yet. You don't have to fetch it by hand first: the client checks the cache on every run and updates it automatically when it's missing or stale (about every two weeks by default), then shows your page. Force a refresh any time with tldr --update.

Installing on macOS: use brew install tlrc, the current official Rust client. Homebrew's older plain tldr formula was deprecated in late 2025 and now points here.

btop: a terminal UI instead of a text list

top gives you one thing: a scrolling text list, read-only. btop gives you a full keyboard-and-mouse UI for the same job, with three real advantages:

  • Per-core graphs — CPU usage and temperature drawn per core, not just one combined number.
  • Process tree view — see which process spawned which, collapsible, instead of one flat list.
  • Act, don't just watch — send a signal to the selected process from inside the UI. top only shows you the problem; btop lets you fix it without leaving.
KeyWhat it does
Up / DownSelect a process in the list
Left / RightChange which column the list is sorted by
eToggle process tree view
SpaceExpand / collapse the selected process in tree view
tTerminate selected process (SIGTERM)
kKill selected process (SIGKILL)
sChoose a specific signal to send

Try it

Run tldr on a command you use often but always forget the flags for — tldr tar or tldr fd. Then launch btop and, using only the keyboard, find the process using the most memory right now: arrow to the process list, use Left/Right to sort by memory, Up/Down to scroll.

Quiz

Q1. What problem does tldr solve that man pages don't?

A. Man pages aim for completeness; tldr pages are short, example-first, and community-maintained.

Q2. What happens the first time you run tldr on a fresh install?

A. No manual setup step is required — the client checks and updates the cache on its own, and keeps doing so as it goes stale.

Q3. Which of these is something btop does that plain top does not?

A. B, C, D are things top already does. Acting on a process — terminate or kill — without leaving the UI is btop's addition.

Q4. In btop, which key toggles the process tree view?

A. B, C, D are real btop keys, just for sending signals, not for the tree view.

Q5. In btop, which key sends SIGKILL to the selected process?

A. k is SIGKILL (force), t is SIGTERM (ask nicely first) — worth knowing which one you're pressing.

Recap
  • tldr swaps the full man page for a handful of real-world examples — install with brew install tlrc.
  • The page cache fetches and refreshes itself automatically — no setup command needed, tldr --update only to force it.
  • btop adds per-core graphs, a process tree, and the ability to terminate (t) or kill (k) a process without leaving the keyboard.

Try solo: next time you catch yourself opening Activity Monitor with the mouse, open btop instead and find the culprit process with only the keyboard.

Something not matching what you see on screen? Check your installed version — flags and defaults do shift between releases.
