Keyboard Workflow — Lesson 8 of 8

Tying it together: a real daily workflow

Lessons 1–7 covered each tool alone. This one is the payoff: one realistic work session, start to finish, keyboard only. Nothing new to learn here — just your AeroSpace, Raycast, Warp, and CLI toolkit habits chained together.

Simple example: think of it as one relay. Raycast hands off to AeroSpace ("here's the app, go place it"). AeroSpace hands off to you ("it's on the right workspace, go work"). Warp hands you the command you already saved. Atuin, zoxide, eza, bat, fd, delta, lazygit, tldr, and btop each remove one small manual step along the way. Each tool does one job and gets out of the way.

A realistic day, keyboard only

  1. Wake the laptop. Press your Raycast hotkey, type the project or app name, hit Enter — Raycast launches it or focuses it if it's already open.
  2. Your AeroSpace on-window-detected rule (Lesson 1) fires automatically and places that app on its home workspace. You never drag it.
  3. Use your AeroSpace workspace-switch binding to jump to the workspace where Warp lives.
  4. Jump straight to the project directory with z projectname (Lesson 4) instead of typing the full path.
  5. Instead of retyping a command, press Ctrl-R in Warp and pull up either a saved Workflow (Lesson 3) or an Atuin history match filtered to this exact directory (Lesson 4).
  6. Review the pasted command, press enter to run it.
  7. Forgot a flag? tldr the command (Lesson 7) instead of scrolling a man page.
  8. Look around the directory with eza -la --git instead of ls, read a file with bat instead of cat, find one with fd instead of find (Lesson 5).
  9. Check what changed with git log -p through delta's side-by-side view, then stage and commit in lazygit without typing individual git commands (Lesson 6).
  10. Something using too much memory? Glance at btop (Lesson 7) instead of opening Activity Monitor.
  11. Two windows open on one workspace — use your ctrl-alt hjkl focus bindings to move between them, no click.
  12. Copy something along the way. A few steps later, pull it back with Raycast's Clipboard History — even if it's not the last thing you copied.
  13. Task done. The mouse only came out for something genuinely mouse-native.

Common friction points

  • New app, no placement rule yet. Find the app's bundle ID (Raycast can show you this) and add one AeroSpace rule (Lesson 1). One-time fix, permanent payoff.
  • Don't let Raycast and AeroSpace fight over windows. If AeroSpace already owns tiling, use Raycast only for launching, focusing, and clipboard (Lesson 2).
  • A command you retype without a Workflow. Run it, then save it right after (Lesson 3) — next time it's one search away.
  • Reaching for cd/ls/cat/find out of habit. Muscle memory takes a week or two to shift to z/eza/bat/fd (Lessons 4–5). Give it time before deciding it's not worth it.

Build your own

Write out your actual daily workflow, in your own notes app or on paper, in the same numbered-step format as above. Name the exact tool and keystroke pattern at each step. If a step feels clunky to write down, that's usually the step worth fixing first.

Recap
  • Raycast launches and focuses. AeroSpace places and arranges. Warp and Atuin remember your commands and history.
  • eza/bat/fd replace ls/cat/find; delta/lazygit make git readable and keyboard-fast; tldr/btop replace man/top for quick answers.
  • Missing AeroSpace rule → add one on-window-detected entry, don't fix it by hand every day.
  • Any command you type twice is a Workflow (or an Atuin search) you haven't used yet.
Something not clicking, or your desktop is doing something the lessons didn't cover? Go back to the tool's own docs, linked throughout this course — that's the habit worth building anyway.
