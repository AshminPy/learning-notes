YubiKey for SSH & GPG on macOS

A well-made Ed25519 key from Lesson 12 is strong cryptography — but the private key file still sits on disk, decrypted in your agent's memory while you're working. A fully compromised laptop can, in principle, get at it. A YubiKey changes that math: the private key is generated on the hardware and never leaves it, not even to the machine it's plugged into.

Mental model: a YubiKey is a padlock that can only be opened by physically pressing it. The key that unlocks your servers is generated inside a small, tamper-resistant chip and stays there. Malware on your laptop can steal a file. It cannot steal a physical touch.

What actually changes with hardware-backed keys

With a normal file-based key, the private key bytes live in ~/.ssh/id_ed25519 — encrypted at rest by your passphrase, but decrypted in your agent's memory while you're using it. With a FIDO2 hardware-backed key, the signing operation itself happens on the YubiKey's chip. What sits on your disk is a "key handle" — a reference telling OpenSSH which credential on the device to use, not the key itself. There's nothing on disk to steal.

FIDO2 resident keys: the current recommended path

Yubico's own guidance is direct on this: FIDO2 is the simplest option for most people — one hardware key covers SSH and your other FIDO2 logins, and it's built into current OpenSSH with no extra software required. The older alternative — routing SSH authentication through gpg-agent, using an OpenPGP-format key — still exists and still works for people already invested in a GPG signing workflow, but it's more moving parts for the same result. This lesson teaches the FIDO2 path.

Common mistake: running the FIDO2 command below against the OpenSSH that ships with macOS. Apple's bundled OpenSSH is not built with FIDO2 support, so it can't create or use -sk key types — you'll get a confusing error that looks like a typo, not a missing feature. Install OpenSSH from Homebrew and make sure it's ahead of the system one on your PATH before you start.

brew install openssh
export PATH="$(brew --prefix openssh)/bin:$PATH"   # add this line to your shell profile

Generate a FIDO2-backed key

ssh-keygen -t ed25519-sk -O resident -O verify-required -C "generic-example@example.com"

-t ed25519-sk is the FIDO2-backed key type. -O resident stores the credential on the YubiKey itself, so it's recoverable on a different machine later with ssh-keygen -K — you're not stuck if this laptop is gone. -O verify-required means every use needs your FIDO2 PIN (or a fingerprint, on a Bio-series key) in addition to a touch, not touch alone. This creates id_ed25519_sk (a handle file, not the private key) and id_ed25519_sk.pub (the public key, same as any other).

Day to day: why the touch is a feature

Every time this key is used, the YubiKey blinks and waits for a physical touch. That's not friction for its own sake — it's proof of physical presence. Malware that has fully compromised your unlocked laptop and its running agent still cannot fake a finger on a piece of hardware. The touch (and PIN, with verify-required) is the one thing a remote attacker categorically cannot forge.

Troubleshooting: key not detected

brew install ykman
ykman list

If nothing shows up: try a different USB-C port, cable, or hub first — a surprising number of "driver" problems are a bad physical connection. If ykman commands fail with a permissions error around the OTP interface, macOS may be blocking it — grant your terminal app Input Monitoring access under System Settings → Privacy & Security.

Security note: a lost or destroyed YubiKey with no backup means locked-out access, not just an inconvenience. Register a second YubiKey as a backup authenticator before you rely on this for anything production-facing, and treat a lost key the same way you'd treat a lost physical office key — revoke it, don't just hope no one finds it.

Try it

Plug in a YubiKey and run ykman list to confirm it's detected. Then generate a real FIDO2 resident key with the command above, using a throwaway comment. Touch the device when it blinks, enter a PIN if prompted, and confirm the two output files exist: ls ~/.ssh/id_ed25519_sk*.

Quiz

Q1. What's different about a FIDO2 hardware-backed key vs. a normal file-based key?

A. Only a key handle sits on disk — the actual private key is generated on, and never leaves, the YubiKey's chip.

Q2. Per Yubico's own docs, what must you do before generating an -sk key on macOS?

A. macOS's bundled OpenSSH has no FIDO2 support — Homebrew's OpenSSH, ahead on PATH, is required for -sk key types.

Q3. Why does authentication require a physical touch on the device?

A. The touch is proof-of-presence — the one thing malware on a fully compromised machine still can't fake.

Q4. What does the -O resident flag do when generating an -sk key?

A. A resident key lives on the device itself, so ssh-keygen -K can recover it on a new machine later.

Q5. Is pcscd required to run ykman list and see your YubiKey on macOS?

A. Yubico's own YubiKey Manager docs scope pcscd to Linux specifically — macOS handles smart-card communication natively, so chasing a pcscd install on a Mac is chasing the wrong problem.

Recap
  • FIDO2 resident SSH keys (ssh-keygen -t ed25519-sk) are Yubico's own recommended default — the private key never leaves the hardware.
  • macOS needs Homebrew's OpenSSH ahead of the system one on PATH — the bundled version has no FIDO2 support at all.
  • The touch (and PIN, with -O verify-required) proves physical presence — it's the one thing remote malware can't forge.

Try solo: register a second YubiKey as a backup authenticator on one real account, so a lost or broken key isn't a lockout.
