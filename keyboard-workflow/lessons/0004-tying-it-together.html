Tying it together: a real daily workflow

Lessons 1–3 covered each tool alone. This one is the payoff: one realistic work session, start to finish, keyboard only. Nothing new to learn here — just your AeroSpace, Raycast, and Warp habits chained together.

Simple example: think of the three tools as one relay. Raycast hands off to AeroSpace ("here's the app, go place it"). AeroSpace hands off to you ("it's on the right workspace, go work"). Warp hands you the command you already saved, instead of making you type it again. Each tool does one job and gets out of the way.

A realistic day, keyboard only

  1. Wake the laptop. Press your Raycast hotkey, type the project or app name, hit Enter — Raycast launches it or focuses it if it's already open.
  2. Your AeroSpace on-window-detected rule (Lesson 1) fires automatically and places that app on its home workspace. You never drag it.
  3. Use your AeroSpace workspace-switch binding to jump to the workspace where Warp lives.
  4. Instead of retyping a command, press Ctrl-R or Cmd-P in Warp and pull up a saved Workflow — e.g. your kubectl context switch or terraform plan (Lesson 3).
  5. Review the pasted command (arguments filled in), press enter to run it.
  6. Need to check a doc or dashboard mid-task — jump workspaces again with your AeroSpace binding, or open a Raycast Quicklink straight to the page.
  7. Two windows open on one workspace — use your ctrl-alt hjkl focus bindings to move between them, no click.
  8. Copy something along the way (a log line, an ID). A few steps later, pull it back with Raycast's Clipboard History — even if it's not the last thing you copied.
  9. Back on Warp's workspace, run the next Workflow. Use Cmd-Up to jump to the previous block and compare its output before running the next command.
  10. Task done. The mouse only came out for something genuinely mouse-native — an image, a drag-to-resize, whatever isn't worth a keybinding.

Common friction points

  • New app, no placement rule yet. If an app isn't in your AeroSpace on-window-detected list, it lands wherever AeroSpace defaults it — not where you want. Don't fight this by hand every day: find the app's bundle ID (Raycast can show you this) and add one rule (Lesson 1). One-time fix, permanent payoff.
  • Don't let Raycast and AeroSpace fight over windows. Raycast's window-management commands and AeroSpace's tiling do the same job. If AeroSpace already owns tiling on your machine, keep it that way — use Raycast only for launching, focusing, and clipboard (Lesson 2). Two systems resizing the same window is worse than one.
  • A command you retype without a Workflow. Mid-task isn't the time to build one. Just run it, then use the block's action menu to save it as a Workflow right after (Lesson 3) — next time it's one search away instead of a retype.

Build your own

Write out your actual daily workflow, in your own notes app or on paper, in the same numbered-step format as above. Name the exact tool and keystroke pattern at each step — not vague ("open my project") but concrete ("Raycast hotkey → type name → Enter"). If a step feels clunky to write down, that's usually the step worth fixing first.

Recap
  • Raycast launches and focuses. AeroSpace places and arranges. Warp remembers your commands so you don't retype them.
  • Missing AeroSpace rule → add one on-window-detected entry, don't fix it by hand every day.
  • Raycast and AeroSpace shouldn't both manage window size — pick one (AeroSpace, if you already use it for tiling).
  • Any command you type twice is a Workflow you haven't saved yet.
Something not clicking, or your desktop is doing something the lessons didn't cover? Go back to the tool's own docs, linked in Lessons 1–3 — that's the habit worth building anyway.
