k9s and stern: a cockpit and a log scanner for your cluster

kubectl get pods, then kubectl describe pod, then kubectl logs -f — one pod at a time, typed by hand, switching contexts in between. It works, but it's slow, and it's easy to lose track of what you're actually looking at. This lesson adds two small, keyboard-driven tools that remove that friction: k9s, a full terminal UI for a live cluster, and stern, which tails logs from many pods at once instead of one. Neither replaces kubectl — both just make the parts you do constantly faster.

Mental model: plain kubectl is like checking on a building by phoning one room at a time — get pods, hang up, dial logs, hang up, dial describe. k9s is walking into the building's control room, where every floor is already on screen and you press a button to look closer. stern is a scanner that listens to every phone matching a name pattern simultaneously, instead of you dialing them one by one.

k9s: a terminal UI for a running cluster

Launch it with k9s (install: brew install k9s, actively maintained — latest release this year), and you land on a live, auto-refreshing pod list for your current context. Everything below is keyboard-only:

KeyWhat it does
:pod ⏎ (or :svc, :deploy, …)Jump to a resource type by name, singular or plural
:ctx ⏎List contexts and switch — same idea as kubectx, from lesson 21
:ns ⏎List namespaces and switch
/pattern ⏎Filter the current list with a regex
dDescribe the selected resource
lView logs for the selected pod
yView the resource's YAML
sOpen a shell inside the selected container
?Show every key mapping available right now
escBack out of the current view or filter

That's the whole loop: type : and a resource name to go there, / to narrow the list, one letter to act on what's selected. No mouse, no separate terminal windows.

Safety inside k9s: it can delete things

k9s isn't read-only by default — it can edit and delete exactly what kubectl can, from inside the same view you're using to browse:

  • ctrl-d deletes the selected resource, but asks you to confirm with TAB then ENTER first.
  • ctrl-k kills it immediately — no confirmation step at all.

Common mistake: browsing a live cluster with normal navigation muscle memory and landing a finger on ctrl-k instead of ctrl-c or ctrl-d. While you're still learning the keys, launch with k9s --readonly — it disables every modification command and turns k9s into a pure viewer, exactly the safe way to build muscle memory before trusting yourself with the real keys.

stern: tailing many pods at once

kubectl logs only ever looks at one pod per invocation — you'd need a separate terminal, or -f restarted by hand, for each replica. stern tails several pods and containers in parallel from one command, color-coding each source so you can tell them apart:

stern api-                       # tails every pod whose name matches "api-"
stern api- -c app                # ...only the "app" container in each
stern -l release=canary          # tails pods matching a label selector
stern --all-namespaces auth      # tails across every namespace at once

api- here is a regular expression, not a literal pod name — it matches api-frontend-7f8d and api-backend-2c1a at once, in the same scrolling, color-coded stream. Install with brew install stern (also actively maintained, current release this year).

Try it

Point at the practice kubeconfig from lesson 21 (KUBECONFIG=~/.kube/config-practice) and launch k9s --readonly. Type :pod to list pods, / plus a few letters to filter, then l on any result to view its logs, and esc to back out. Quit with :q. Separately, once you have a real sandbox cluster to point at, run stern against a made-up pattern like web- and watch several pods' logs interleave in one stream.

Quiz

Q1. What is k9s, in one sentence?

A. It's a live, keyboard-driven view over whatever kubectl can already see — not a separate product or a browser dashboard.

Q2. Inside k9s, which key deletes a resource with no confirmation step at all?

A. ctrl-k is the fast, no-confirmation kill — worth knowing which finger reaches for it before it happens by accident.

Q3. How do you switch which namespace k9s is showing, from inside the UI?

A. :ns lists and switches namespaces; :ctx does the same job for contexts, not namespaces.

Q4. What can stern do that plain kubectl logs cannot?

A. B is what plain kubectl logs already does; C and D aren't things either tool does. Aggregating many pods into one stream is stern's actual job.

Q5. In a command like stern api-, what does "api-" actually mean?

A. The pod-query argument is a regex, so it matches every pod name containing that pattern — not one specific pod.

Recap
  • k9s (brew install k9s) is a live terminal UI: : jumps to a resource type, / filters, d/l/y/s describe, view logs, view YAML, and shell in.
  • k9s can also delete or kill from inside the UI — ctrl-d confirms first, ctrl-k doesn't. Use k9s --readonly while you're still learning the keys.
  • stern (brew install stern) tails logs from every pod matching a regex or label selector at once, color-coded, in one stream — something plain kubectl logs can't do.

Try solo: next time you'd normally open three terminal tabs to watch three replicas' logs separately, run one stern command against their shared name pattern instead.
