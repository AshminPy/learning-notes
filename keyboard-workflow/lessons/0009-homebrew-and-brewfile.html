Homebrew and the Brewfile: install once, reproduce anywhere

Every lesson from here on installs something — Karabiner next, then a long list of CLIs later in the course. Right now, if your Mac died today, none of that would come back on its own: you'd remember maybe half the tools you use daily, and none of the exact versions. This lesson fixes the root problem — how you install software on a Mac, and how you turn your whole install list into one file you can hand to a brand-new machine.

Mental model: Homebrew is a package manager for macOS, the same job apt does on Debian or yum does on Red Hat — except everything it installs lives under one directory it owns (/opt/homebrew on Apple Silicon), never scattered across the system.

Formula, cask, tap: three nouns you'll see constantly

Homebrew's own docs define three terms that show up in every command you run:

  • Formula — a package definition for a command-line tool, usually built from source. Install one with brew install <name>.
  • Cask — a package definition for a GUI app distributed as a pre-built binary (something you'd otherwise drag into /Applications). Install one with brew install --cask <name>.
  • Tap — a Git repository of formulae and/or casks, beyond the default set Homebrew ships with. You add one with brew tap <user/repo> before its packages become installable.

Try both of the first two now. jq is a formula — a small command-line JSON processor genuinely useful for reading API responses and log lines:

brew install jq

Docker Desktop is a cask — a full GUI application:

brew install --cask docker

No Homebrew yet? Install it with the official one-line installer, then restart your terminal: /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Brewfile: snapshot your whole setup into one file

Installing tools one at a time is fine the first time. It doesn't scale to "set up a second Mac" or "recover after a wipe." brew bundle solves that by reading and writing a single file — a Brewfile — that lists everything you've installed:

brew bundle dump --file=~/Brewfile

This writes every installed formula, cask, and tap into ~/Brewfile, in plain text:

tap "homebrew/bundle"
brew "jq"
brew "git"
cask "docker"

On a new Mac — or after a wipe — one command reads that same file and installs everything it lists:

brew bundle install --file=~/Brewfile

This is the reproducibility foundation the rest of this course builds on. Lesson 11 puts this exact file under version control alongside your other dotfiles, so "set up a new Mac" becomes a handful of commands instead of a half-remembered checklist.

brew doctor: your first troubleshooting step

When something Homebrew-related misbehaves — a formula won't build, a command isn't found after install — run this before anything else:

brew doctor

It checks your Homebrew installation for common problems and exits non-zero if it finds any. Not every warning it prints means something is actually broken — Homebrew's own docs note that if your installation is working, some warnings are safe to ignore. Read what it reports before acting on it.

Try it

Install one real formula and one real cask (or reuse jq and docker above). Then run brew bundle dump --file=~/Brewfile and open the file — confirm both entries are in it. Finally, run brew doctor and read whatever it reports, even if it says everything's fine.

Quiz

Q1. What's the difference between a formula and a cask?

A. A formula is typically built from a source recipe; a cask installs a binary someone else already compiled and signed.

Q2. What does brew bundle dump do?

A. It's a snapshot command — it reads your current install state and writes it to a file, nothing gets removed or uploaded anywhere.

Q3. What does brew bundle install --file=~/Brewfile do on a fresh Mac?

A. It's the restore half of the pair — it reads the file and installs everything listed, by default upgrading anything already present.

Q4. What does brew doctor check for?

A. It's a diagnostic scan of your Homebrew setup itself — not a version log, speed test, or disk report.

Q5. Why does this course care about the Brewfile specifically?

A. Lesson 11 version-controls this exact file — it's the first piece of your reproducible, backed-up setup.

Recap
  • Formula = CLI tool, usually built from source. Cask = GUI app, pre-built binary. Tap = a repo of either, beyond Homebrew's defaults.
  • brew bundle dump --file=~/Brewfile snapshots everything installed; brew bundle install --file=~/Brewfile restores it, anywhere, in one command.
  • brew doctor is the first thing to run when Homebrew itself is misbehaving.

Try solo: next time you install any tool with Homebrew, re-run brew bundle dump --file=~/Brewfile right after — make it a reflex, not a once-a-year cleanup task.

Command output look different from what's shown here? Homebrew updates constantly — run brew --version and check the linked docs before assuming something's broken.
