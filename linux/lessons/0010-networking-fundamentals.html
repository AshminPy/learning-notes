Networking Fundamentals

Every Linux box needs to answer three questions to be reachable on a network: what's my address, how do I reach other networks, and how do I turn a name into an address. Three tools answer those three questions directly.

Simple example: ip addr show tells you the machine's own IP address. ip route show tells you where traffic goes when it isn't local. ss -tulnp tells you which services are actually listening for connections right now.

The essential toolkit

CommandAnswers
ip addr showWhat IP address(es) does this machine have?
ip route showWhere does non-local traffic go (the default gateway)?
ss -tulnpWhich ports are listening, and which process owns them?
ping hostCan I reach this host at all (ICMP)?
curl -v host:portCan I actually complete a TCP connection and get an application response?
dig host / nslookup hostWhat does DNS resolve this name to?

ip is the modern tool; ifconfig, netstat, and route are older commands still seen in tutorials but deprecated on most current distros — ip and ss are the ones actually maintained today.

A simple diagnosis order

When something "isn't working" over the network, working outward from the machine itself finds the failure point fastest: confirm the local IP exists (ip addr) → confirm a route exists (ip route) → confirm you can reach the host at all (ping) → confirm the specific port responds (curl or ss on the remote end) → confirm DNS resolves correctly if you used a hostname (dig). Each step rules out one whole category of cause.

Try it — before looking below

Q1. ping to a server succeeds, but curl to its web port times out. What does that combination tell you?

Basic network reachability is fine (ping got a response), so the problem is higher up — likely the service isn't listening on that port, or a firewall is blocking that specific port while still allowing ICMP.

Now try it yourself

ip addr show               # your own IP addresses
ip route show               # your default gateway
ss -tulnp                   # what's listening locally right now
dig example.com             # DNS resolution for a real hostname

Source

ip(8) man page — the official reference for the modern Linux networking toolkit.

Recap
  • ip addr, ip route, and ss -tulnp answer "what's my address," "where does traffic go," and "what's listening."
  • Diagnose outward in order: local address → route → reachability (ping) → port (curl) → DNS (dig) — each step isolates a different cause.
  • ip/ss are the current tools; ifconfig/netstat are older and largely deprecated.
"The network is down" almost always means one specific step in that diagnosis chain failed — find which one before assuming the whole network is the problem.
