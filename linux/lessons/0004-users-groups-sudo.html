Users, Groups & Sudo

Every user has a unique ID (UID) and belongs to a primary group plus zero or more supplementary groups. Regular users can't touch system files or other users' data — sudo is the controlled way to run one specific command as another user (almost always root), without logging in as that user.

Simple example: sudo systemctl restart nginx runs just that one command as root, then you're back to your normal user. That's different from su, which switches your whole shell session to another user until you exit it.

Where this lives

FileWhat's in it
/etc/passwdEvery user account: username, UID, home directory, default shell
/etc/groupEvery group and its members
/etc/sudoersWho's allowed to run sudo, and what they're allowed to run — edit only with visudo, which validates syntax before saving

Editing /etc/sudoers directly with a normal editor is a real way to lock yourself out of sudo entirely if you introduce a syntax error — visudo checks the file before it's saved, a plain editor doesn't.

Try it — before looking below

Q1. What's the difference between sudo command and su?

sudo command runs just that one command as root (usually), then returns you to your own user. su switches your entire shell session to another user until you explicitly exit.

Now inspect your own system

whoami                    # your current username
id                         # your UID, primary group, and supplementary groups
cat /etc/passwd | grep $(whoami)   # your own entry in the user database
groups                     # every group you belong to

Source

sudoers(5) man page — the official reference for sudo configuration.

Recap
  • Every user has a UID, a primary group, and optional supplementary groups.
  • sudo runs one command as another user (usually root); su switches your whole session.
  • /etc/passwd = users, /etc/group = groups, /etc/sudoers = who can sudo — always edit sudoers with visudo.
Locked yourself out of sudo before? It happens to everyone once — that's exactly why visudo exists.
