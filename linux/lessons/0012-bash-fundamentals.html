Bash Scripting Fundamentals

A bash script is just a text file of commands you'd otherwise type one by one, saved so you can run them together, repeatably. The core building blocks — variables, conditionals, loops — are the same ideas from any programming language, just with bash's own syntax.

Simple example: A script starts with a shebang line, #!/bin/bash, telling the system which interpreter to run it with. Make it executable (chmod +x script.sh) and run it directly (./script.sh) instead of typing bash script.sh every time.

Variables and arguments

#!/bin/bash
NAME="prod-web-1"
echo "Checking host: $NAME"
echo "First argument passed to this script: $1"
echo "All arguments: $@"
echo "Number of arguments: $#"

No spaces around = when assigning a variable — NAME="prod-web-1" works, NAME = "prod-web-1" fails, because bash reads the second form as trying to run a command called NAME.

Conditionals

if [ -f /etc/nginx/nginx.conf ]; then
    echo "config exists"
else
    echo "config missing"
fi
TestMeaning
-f fileFile exists and is a regular file
-d dirDirectory exists
-z "$var"String is empty
"$a" == "$b"Strings are equal

Loops

for host in web1 web2 web3; do
    echo "Pinging $host"
    ping -c 1 "$host"
done

Exit codes — how success or failure is reported

Every command returns an exit code when it finishes: 0 means success, anything else means some kind of failure. $? holds the exit code of the last command run — checking it is how a script reacts to a command failing instead of blindly continuing.

Try it — before looking below

Q1. A command in your script fails (returns exit code 1), but the script keeps running the next lines as if nothing happened. Why?

Bash doesn't stop on a failed command by default — it just moves to the next line. You have to check $? yourself, or add set -e near the top of the script to make it exit automatically on any failure.

Now try it yourself

echo '#!/bin/bash
echo "Hello, $1"
echo "Exit code of last command was: $?"' > hello.sh
chmod +x hello.sh
./hello.sh World

Source

GNU Bash Reference Manual — the official Bash documentation.

Recap
  • Every script starts with #!/bin/bash and needs chmod +x to run directly.
  • No spaces around = in variable assignment — this trips up almost everyone once.
  • Bash doesn't stop on failure by default — check $? or use set -e if a failure should halt the script.
