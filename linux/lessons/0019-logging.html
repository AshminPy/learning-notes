Logging

On systemd-based distros, most system and service logs go through journald instead of (or alongside) plain text files in /var/log. You already used journalctl -u <service> in Lesson 7 — this lesson covers the rest of what it can do, plus where the older plain-text logs still live.

Simple example: journalctl -k shows only kernel messages — the same content dmesg shows, but with full timestamps and searchable like any other journal query.

journalctl — the main tool

CommandWhat it shows
journalctlEvery log entry, oldest first
journalctl -fFollow live, like tail -f
journalctl -u nginxJust one service's logs
journalctl -kKernel messages only
journalctl --since "1 hour ago"Time-bounded — also accepts exact dates/times
journalctl -p errOnly entries at error priority or worse
journalctl -bOnly logs since the current boot

These combine: journalctl -u nginx --since "10 min ago" -p err narrows to exactly what you need instead of scrolling through everything.

/var/log — still relevant

Not everything goes through journald. Application logs that were never integrated with systemd, and some distros' auth/security logs, still write plain text to /var/log/.

FileContents
/var/log/auth.log (Debian) / /var/log/secure (RHEL)Authentication attempts, sudo usage
/var/log/syslog (Debian)General system messages on non-journald-only setups
/var/log/<app>/Application-specific logs (nginx, postgresql, etc.)

journald logs aren't permanent by default on every distro — some configurations keep logs only in memory or clear them across reboots (journalctl -b -1 shows the previous boot's logs, if kept). Check /etc/systemd/journald.conf's Storage= setting if you need logs to persist long-term.

Try it — before looking below

Q1. You want to see only error-level (or worse) log lines from the nginx service in the last 30 minutes. What single command gets you exactly that?

journalctl -u nginx --since "30 min ago" -p err — combining the unit filter, time filter, and priority filter in one query.

Now try it yourself

journalctl -k -n 20            # last 20 kernel messages
journalctl --since "1 hour ago" -p err   # recent errors, any service
ls /var/log/                    # see what plain-text logs exist on this system

Source

journalctl(1) man page — the official systemd documentation.

Recap
  • journalctl is the primary log tool on systemd distros — filter by unit (-u), time (--since), priority (-p), or boot (-b), and combine filters freely.
  • /var/log/ still holds plain-text logs for auth and many applications not integrated with journald.
  • Journal persistence depends on journald.conf's Storage= setting — don't assume logs survive a reboot without checking.
When investigating an incident, always narrow with --since and -u first — scrolling through the full unfiltered journal wastes time the incident doesn't have.
