Storage & Disks

A raw disk (/dev/sda) is useless until it's partitioned, formatted with a filesystem, and mounted somewhere in the directory tree. Those are three separate, ordered steps — and understanding them is what turns "disk full" or "where did my drive go" into a two-minute fix instead of a mystery.

Simple example: /dev/sda is the whole disk. /dev/sda1 is its first partition. Format that partition with a filesystem (mkfs.ext4 /dev/sda1), then mount it (mount /dev/sda1 /data) to make its contents appear at /data.

The three layers

LayerWhat it isCommon tool
PartitionA logical slice of a physical diskfdisk, parted, lsblk to view
FilesystemThe structure written onto a partition so files can actually be stored (ext4, xfs)mkfs.ext4, mkfs.xfs
MountAttaching that filesystem to a directory so you can use itmount, umount, /etc/fstab for persistence

Checking what you have

lsblk              # tree view of every disk and partition
df -h              # disk usage per mounted filesystem, human-readable
mount | grep sda1  # is this partition currently mounted, and where

A mount command done by hand disappears on reboot. To make a mount permanent, add a line to /etc/fstab — otherwise you'll find the mount point empty again after the next restart, with no error to explain why.

LVM — one more layer of flexibility

Logical Volume Manager (LVM) sits between partitions and filesystems. Instead of formatting a partition directly, you group one or more partitions into a Volume Group, then carve out Logical Volumes from that group. The payoff: you can grow a logical volume later (add more disk to the group, extend the volume, resize the filesystem) without unmounting or reformatting anything — something a plain partition can't do without much more disruption.

Try it — before looking below

Q1. You manually run mount /dev/sdb1 /data and it works. After the next reboot, /data is empty. Why?

A manual mount only lasts for the current boot — it was never written to /etc/fstab, the file that tells the system which filesystems to mount automatically at every startup.

Now try it yourself

lsblk                    # see every disk and partition on this machine
df -h                    # see usage per mounted filesystem
cat /etc/fstab           # see what's configured to mount at boot

Source

fstab(5) man page — the official reference for the filesystem table.

Recap
  • Disk setup is three ordered layers: partition, then filesystem, then mount.
  • A manual mount doesn't survive reboot — /etc/fstab is what makes a mount permanent.
  • LVM adds a flexible layer between partitions and filesystems, letting you resize storage without reformatting.
"Disk full" is often really "one filesystem full" — df -h shows usage per mount point, not per physical disk, so check the right line.
