Text Processing

Logs, config files, command output — almost everything on Linux is plain text, and three tools cover most of what you'll ever need to search, transform, or extract from it: grep to find lines, sed to change them, awk to pull fields out of them.

Simple example: grep "ERROR" app.log prints every line containing "ERROR." Pipe it further — grep "ERROR" app.log | wc -l — and you get a count instead, one command doing what would otherwise take a script.

grep — find lines

FlagWhat it does
-iCase-insensitive match
-rSearch recursively through a directory
-vInvert — show lines that do NOT match
-cCount matching lines instead of printing them
-nShow line numbers alongside matches

sed — transform lines

sed 's/foo/bar/' file.txt        # replace first "foo" per line with "bar"
sed 's/foo/bar/g' file.txt       # replace every "foo" per line (g = global)
sed -i 's/foo/bar/g' file.txt    # do it in-place, editing the file directly

sed -i edits the file in place with no confirmation and no backup by default. Test the command without -i first, confirm the output looks right, then add -i — or use sed -i.bak to keep a backup copy automatically.

awk — extract fields

awk treats each line as a row of space-separated fields ($1, $2, ...), which makes it the natural tool for pulling one column out of structured output.

ps aux | awk '{print $2, $11}'   # print just PID and command from ps output
df -h | awk '$5+0 > 80 {print}'  # print filesystems over 80% used

Chaining them together

These tools are built to pipe into each other — that's the real power. Find the errors, then count the unique ones, then sort by frequency:

grep "ERROR" app.log | awk '{print $5}' | sort | uniq -c | sort -rn

Try it — before looking below

Q1. You want to see how many times each unique error message appears in a log file, most frequent first. Which three commands would you chain together with grep?

sort | uniq -c | sort -rn — sort groups identical lines together (required before uniq can count them), uniq -c counts each group, and the final sort -rn orders by count, highest first.

Now try it yourself

ps aux | awk '{print $11}' | sort | uniq -c | sort -rn | head
# Shows every running command, counted and ranked by frequency

Source

GNU Awk User's Guide — the official reference.

Recap
  • grep finds lines, sed transforms them, awk extracts fields from them.
  • Test sed without -i first — in-place edits have no built-in undo.
  • sort | uniq -c | sort -rn is the standard pattern for "count and rank" on any text stream.
If a one-liner is getting past three or four pipes and hard to read, that's usually the signal to drop into a small bash script instead — Lessons 12-13 cover that.
