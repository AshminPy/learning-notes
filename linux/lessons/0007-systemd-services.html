systemd & Services

systemd is the init system on nearly every modern Linux distro — it's PID 1, the first process the kernel starts, and it manages every other service: starting them in the right order, restarting them on failure, and logging their output.

Simple example: systemctl restart nginx restarts the nginx service using its unit file — a small config file telling systemd exactly how to start it, what to do if it crashes, and what it depends on.

The core commands

CommandWhat it does
systemctl status nginxIs it running, when did it start, recent log lines
systemctl start/stop/restart nginxControl it right now
systemctl enable nginxStart it automatically on boot (doesn't start it now)
systemctl enable --now nginxEnable on boot AND start it now
journalctl -u nginxFull logs for that specific service
journalctl -u nginx -fFollow logs live, like tail -f

systemctl start alone doesn't survive a reboot — that's what enable is for. The two are independent: you can enable without starting (queued for next boot) or start without enabling (running now, gone after reboot).

Try it — before looking below

Q1. A service is running fine right now, but after the server reboots tonight, it's gone. What's the likely cause?

It was started but never enabled — systemctl start runs it now; systemctl enable is the separate step that makes it start automatically on boot.

Now try it yourself

systemctl status sshd            # check a service that's almost always installed
systemctl is-enabled sshd        # is it set to start on boot?
journalctl -u sshd -n 20         # last 20 log lines for it

Source

systemctl(1) man page — the official systemd documentation.

Recap
  • systemd is PID 1 on nearly every modern distro — it starts, stops, and restarts every other service.
  • start/stop control it right now; enable/disable control whether it survives a reboot — independent settings.
  • journalctl -u <service> is your first stop for a service's logs.
A service stuck restarting in a loop? journalctl -u <service> -n 50 almost always shows exactly why on the first read.
