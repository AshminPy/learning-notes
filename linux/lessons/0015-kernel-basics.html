Kernel Basics

Back in Lesson 1 you learned the kernel is the layer that talks directly to hardware. Now the practical side: the kernel exposes its internal state as files you can read directly, no special tool required — /proc and /sys are the two windows into that state.

Simple example: cat /proc/cpuinfo shows exactly what CPU the kernel sees — model, core count, flags — read straight out of a live kernel data structure, not a static config file.

/proc — process and kernel state, live

PathWhat it shows
/proc/cpuinfoCPU details
/proc/meminfoMemory details
/proc/<pid>/statusLive state of one specific process
/proc/loadavgSystem load average
/proc/versionExact running kernel version

Every number in /proc reflects the kernel's actual live state at the moment you read it — this is exactly what tools like top, ps, and free read from under the hood. There's no special API; they're reading these same files.

/sys — device and driver configuration

/sys exposes the kernel's view of devices and drivers, and in many cases you can write to these files to change settings in real time. For example, some drivers expose tunables under /sys/class/ that take effect immediately, without a reboot.

Loaded kernel modules

lsmod                    # list currently loaded kernel modules
modinfo <module>         # details about a specific module
uname -r                 # exact kernel version running right now

Try it — before looking below

Q1. top shows you live CPU and memory numbers. Where does top actually get that data from?

It reads the same files you can read yourself — /proc/stat, /proc/meminfo, and per-process data under /proc/<pid>/. There's no separate hidden API; /proc is the actual source.

Now try it yourself

cat /proc/version           # exact kernel build info
cat /proc/loadavg           # current system load
lsmod | head                # kernel modules currently loaded

Source

proc(5) man page — the official reference for the /proc filesystem.

Recap
  • /proc and /sys expose live kernel state as plain readable files — no special tool needed.
  • Familiar tools like top, ps, and free are just reading these same files for you.
  • lsmod and uname -r tell you what modules are loaded and exactly which kernel is running.
When a monitoring tool reports a confusing number, checking the raw /proc file it's reading from is often the fastest way to tell if the tool is wrong or the system really is in that state.
