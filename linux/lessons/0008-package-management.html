Package Management

Installing software on Linux almost never means downloading an installer — it means asking a package manager to fetch a package from a repository, resolve its dependencies, and install it in the standard system locations. The package manager you use depends on the distro family.

Simple example: On Debian/Ubuntu, apt install nginx fetches nginx and every library it needs, then registers it so apt remove nginx can cleanly undo it later. On RHEL/Fedora/Rocky, the equivalent is dnf install nginx.

The two families

FamilyLow-level toolHigh-level tool (resolves dependencies)
Debian/Ubuntudpkg (installs a single .deb file)apt (fetches from repos, resolves deps)
RHEL/Fedora/Rocky/Almarpm (installs a single .rpm file)dnf (fetches from repos, resolves deps) — yum on older versions

The low-level tool (dpkg/rpm) installs a package file you already have but does nothing about dependencies — if a library is missing, it just fails. The high-level tool (apt/dnf) talks to a repository, downloads the package plus everything it depends on, and installs all of it together. In daily work you almost always want the high-level tool.

Everyday commands

TaskDebian/UbuntuRHEL/Fedora

Which package owns this file?dpkg -S /path/filerpm -qf /path/file

Forgetting to update the package index (apt update) before installing is a common source of "package not found" or "404" errors — the index is just a local cache of what's available, and it can go stale.

Try it — before looking below

Q1. You're handed a lone .deb file with no internet access. Will apt install ./file.deb work if the package has dependencies you don't already have?

No — without repository access, nothing can fetch missing dependencies. dpkg -i file.deb (or apt install ./file.deb) will install the package itself but fail or leave it broken if a dependency isn't already on the system.

Now try it yourself

# On a Debian/Ubuntu system:
apt list --installed | head       # see what's already installed
dpkg -S /bin/ls                   # find which package owns a file

# On a RHEL/Fedora system:
dnf list installed | head
rpm -qf /bin/ls

Source

apt(8) man page — the official reference for the Debian/Ubuntu package manager.

Recap
  • Debian family uses dpkg/apt; RHEL family uses rpm/dnf (or yum on older systems).
  • The low-level tool installs a package file you already have; the high-level tool fetches from a repo and resolves dependencies — use the high-level tool day to day.
  • Keep the package index updated (apt update) before installing, or you'll chase stale "not found" errors.
