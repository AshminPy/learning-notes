Performance Tuning & Monitoring

"The server is slow" has four possible root causes — CPU, memory, disk I/O, network — and guessing wastes time. One command, run once, tells you which of the four to actually investigate: vmstat.

Simple example: vmstat 1 5 prints 5 samples, one second apart. High numbers in the us/sy columns point to CPU; a high wa column points to disk I/O; consistent si/so activity points to memory pressure (swapping).

vmstat — the fastest first look

vmstat 1 5
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
ColumnHigh value points to
r (run queue)More processes waiting for CPU than you have cores — CPU pressure
wa (I/O wait)CPU sitting idle waiting on disk — disk I/O bottleneck
si/so (swap in/out)Active swapping — memory pressure (see Lesson 16)
us/sy (user/system time)Genuine CPU-bound work — CPU bottleneck

Following up per bottleneck

  • CPU: top -o %CPU to find which process, then Lesson 17's nice values if it's a background job stealing priority.
  • Memory: free -h and ps aux --sort=-%mem to find which process holds the most.
  • Disk I/O: iostat -x 1 (per-device) or iotop (per-process) to find which disk or process is the bottleneck.
  • Network: ss -s for a connection summary, or Lesson 10's tools for reachability.

Don't jump straight to top when someone reports "slow" — top only shows CPU and memory clearly, and if the real bottleneck is disk I/O or network, you'll stare at a mostly-idle CPU and conclude nothing's wrong. Run vmstat first to know which direction to dig.

Try it — before looking below

Q1. vmstat shows us/sy near zero but wa consistently high. Where's the bottleneck, and what would you check next?

Disk I/O — the CPU is mostly idle, just waiting on storage. Next step: iostat -x 1 or iotop to identify which disk or process is generating the I/O load.

Now try it yourself

vmstat 1 5           # 5-second snapshot — check which column stands out
free -h               # cross-check memory pressure
top -o %CPU            # cross-check which process is using CPU, press q to quit

Source

vmstat(8) man page — the official reference.

Recap
  • "Slow" has four usual causes: CPU, memory, disk I/O, network — vmstat tells you which one in one command.
  • Don't start with top — it only shows two of the four categories clearly, and can mislead you into thinking nothing's wrong.
  • Follow up per bottleneck: top for CPU, free/ps --sort=-%mem for memory, iostat/iotop for disk, ss for network.
"Slow" is a symptom, not a diagnosis — always narrow to one of the four categories before changing anything.
