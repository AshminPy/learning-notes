4. Mental models that matter more than syntax

  • Declarative, not imperative. You describe the end state; Terraform figures out the steps. (Lesson 3)
  • State is Terraform's memory. Plan/apply compare config, state, and real infrastructure — a three-way diff, not just config vs. reality. (Lesson 13)
  • Resource vs. data: resource = Terraform owns and changes it; data = Terraform only reads it. (Lesson 9)
  • count vs. for_each: prefer for_each — a stable key avoids the "removing one item shifts every index after it" trap. (Lesson 11)
  • State must never be committed to git — it can contain plaintext sensitive values even when a variable is marked sensitive = true. (Lessons 13, 24)
  • Remote backend + locking in production, always. Local state is for learning only. (Lessons 14, 15)
  • A module you use once, with no reuse benefit, doesn't need to be a module. Indirection has a cost. (Lesson 20)
