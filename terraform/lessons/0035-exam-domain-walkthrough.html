Terraform / Zero to Expert — Lesson 35 of 37

Exam domain walkthrough & self-check

You've now got 34 lessons of hands-on Terraform behind you — a state file you broke and fixed yourself, a module you wrote and versioned, a CI/CD pipeline that plans on PR and applies on merge, a full capstone stack. This lesson doesn't teach anything new. It does one job: map every one of the exam's 8 official domains back to the exact lessons that covered it, so you can spot-check any domain that feels shaky before you book the real thing. Treat it as a mirror, not a textbook — if a question below stops you cold, that's useful information, not a failure.

The one thing to remember: this lesson is a self-test, not a lecture. There's no new syntax here. Read a domain, ask yourself the checklist questions honestly, and only open the linked lesson if you can't answer instantly. If you can answer everything below without opening a single linked lesson, you're ready for Lesson 36's practice scenarios.

The 8 official exam domains — reconfirmed

Re-checked directly against HashiCorp's own exam content outline (fetched 2026-07-30), same source already cited in Lesson 1 and MISSION.md: Terraform Associate 004 exam objectives. The 8 domains, in the order HashiCorp lists them:

  1. Infrastructure as Code (IaC) with Terraform
  2. Terraform fundamentals
  3. Core Terraform workflow
  4. Terraform configuration
  5. Terraform modules
  6. Terraform state management
  7. Maintain infrastructure with Terraform
  8. HCP Terraform

Self-check: can you do this without looking?

Go domain by domain. Read each question, answer it out loud or on paper before you check the lesson. If you hesitate more than a few seconds, that's your signal — not a failure, just where to spend the next 20 minutes.

1. Infrastructure as Code (IaC) with Terraform

  • Can you explain declarative vs. imperative infrastructure management without looking? → Lesson 3
  • Can you say why Terraform works across multiple clouds instead of locking you into one? → Lesson 3

2. Terraform fundamentals

  • Can you explain what a provider is and why every config declares one? → Lesson 4
  • Can you say, in one sentence, why Terraform needs state at all? → Lesson 13

3. Core Terraform workflow

  • Can you name the core workflow commands in order and what each one does — init, plan, apply, destroy? → Lesson 5
  • Can you explain the difference between what terraform fmt checks and what terraform validate checks? → Lesson 25
  • Can you say what you're actually looking for when you review a plan before typing "yes"? → Lesson 26

4. Terraform configuration

  • Can you write a for_each loop from memory? → Lesson 11
  • Can you explain the difference between a resource block and a data block? → Lesson 8, Lesson 9
  • Can you write a custom precondition or postcondition from memory? → Lesson 12
  • Can you explain why marking a variable sensitive = true doesn't keep it out of the state file? → Lesson 24

5. Terraform modules

  • Can you explain how variable scope inside a module differs from the root module? → Lesson 18
  • Can you say why an unpinned module version is a real production risk, not just tidiness? → Lesson 19

6. Terraform state management

  • Can you explain the three-way comparison Terraform runs on every plan — config, state, real infrastructure? → Lesson 13
  • Can you explain concretely what state locking prevents? → Lesson 15
  • Can you write a backend block from memory? → Lesson 14

7. Maintain infrastructure with Terraform

  • Can you explain when you'd reach for terraform import instead of just deleting and recreating a resource? → Lesson 16
  • Can you name the CLI commands that inspect state without changing it — the ones that list every tracked resource and show one resource's full attributes? → Lesson 16
  • Can you name the environment variable that turns on verbose debug logging, and when you'd actually reach for it? → Lesson 33

8. HCP Terraform

  • Can you explain why an HCP Terraform workspace and a CLI terraform workspace are two unrelated concepts that happen to share a name? → Lesson 28
  • Can you say what "remote execution" means concretely, and what problem it solves that plain remote state storage doesn't? → Lesson 28
  • Can you describe the plan-on-PR / apply-on-merge pattern end to end? → Lesson 29, Lesson 30
