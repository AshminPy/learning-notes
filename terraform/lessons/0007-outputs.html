Outputs

Lesson 6 gave you a way to get values into a config — input variables. This lesson is the mirror image: getting values out. An output is how Terraform tells you (or another piece of config) something it learned during apply — an IP address it was assigned, an ID it generated, a name it randomized. Without outputs, that information is buried inside the state file where nothing outside Terraform can easily see it.

Mental model: if input variables are the parameters you hand to a function, outputs are its return value. The function runs (apply), does its work, and outputs are the one sanctioned way it hands something back to whoever called it — you at the terminal, or a parent module in Lesson 17 onward.

The output block

An output block lives in your .tf files, usually grouped in an outputs.tf file once a config grows past a couple of resources. Its name is a label you choose, and it needs exactly one required argument:

output "pet_name" {
  description = "The randomly generated pet name"
  value       = random_pet.example.id
}
  • value — required. Any expression Terraform can evaluate: a resource attribute (like random_pet.example.id above), a variable, a computed expression, even a whole object or list.
  • description — optional, but write it anyway. It documents what the value means and shows up when someone runs terraform output or inspects the config — the same discipline as the description you gave input variables in Lesson 6.
  • sensitive — optional boolean, default false. Set it to true and Terraform redacts the value from normal plan/apply output, printing <sensitive> instead.
output "database_password" {
  description = "Auto-generated password for the database instance"
  value       = aws_db_instance.main.password
  sensitive   = true
}

Best practice — sensitive is not real security. It only redacts the value from the CLI's normal plan/apply text. Run terraform output -json or terraform output -raw database_password and the plaintext comes right back — and the value is always stored in plaintext inside the state file, sensitive or not. Treat sensitive = true as a courtesy that stops a password scrolling past on a shared screen, not as encryption. Real secrets need a secrets manager (Lesson 27+ territory) with state itself locked down.

Why outputs matter

Two separate jobs, both solved by the same block:

  • Surfacing values to you. Some values don't exist until apply runs — a cloud provider assigns an IP, Terraform generates a random ID. An output is how that value gets printed for you to actually use, instead of staying locked inside terraform.tfstate.
  • Passing values between configs. When a module is called from another config (Lessons 17–20), the calling config can only see what the module explicitly outputs — everything else stays private to that module. Outputs are the module's public interface, the same way a function's return value is the only thing its caller gets to see. You're not using modules yet, but every output you write today is practice for that exact pattern.

Viewing outputs — terraform output

After an apply, outputs print automatically at the bottom of the run. To see them again any time afterward, without re-running apply:

$ terraform output

pet_name = "climbing-mudfish"

Ask for one specific output by name:

$ terraform output pet_name
"climbing-mudfish"

Two flags worth knowing now, because you'll reach for them constantly once outputs feed into scripts or other tools:

  • terraform output -json — every output as machine-readable JSON, including sensitive ones in plaintext. Used to hand values to another program.
  • terraform output -raw <name> — the bare value with no quotes, useful for piping straight into a shell command.

Try it — before looking below

Q1. Which argument is required inside every output block?

value — description and sensitive are both optional.

Q2. You mark an output sensitive = true. Does that stop the value from ever appearing in plaintext anywhere?

No. It only redacts the value from normal plan/apply CLI output. terraform output -json, terraform output -raw, and the state file itself all still hold the plaintext value.

Now write your own

In the same main.tf you've been building since Lesson 4, which already has your resource "random_pet" "example" {} block:

  • add an output block that exposes the pet name, referencing the resource's id attribute (the same attribute you saw as (known after apply) back in Lesson 5)
  • run terraform apply and type yes — watch the output print at the bottom of the run
  • run terraform output and confirm you see the same value without re-applying anything
  • run terraform output with the specific output name to fetch just that one value

Recap
  • An output block needs one required argument, value; description documents it, sensitive = true redacts it from normal CLI output only.
  • Outputs surface values that don't exist until apply runs, and are the only values a module exposes to whatever calls it — the same mechanism does both jobs.
  • terraform output re-prints outputs any time without re-applying; -json and -raw give machine-readable or bare-value forms.
