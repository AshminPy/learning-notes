Expressions & built-in functions

So far you've written literal values (length = 2) and simple references (var.name, random_pet.example.id). Both of those are expressions — anything on the right-hand side of an argument that Terraform evaluates to produce a value. This lesson covers the three expression tools you'll reach for constantly: building strings out of other values, calling Terraform's built-in functions, and choosing between two values with a conditional.

String templates and interpolation

A quoted string like "hello" is just a literal. But put a ${ ... } sequence inside a string, and Terraform evaluates the expression between the braces, converts the result to a string, and splices it into the surrounding text — this is called interpolation.

"Hello, ${var.name}!"
# if var.name is "Ashmin" -> "Hello, Ashmin!"

Mental model: ${...} is only needed inside a larger string, where Terraform has to know which parts are literal text and which parts are code to evaluate. If your entire argument value is nothing but a single reference — no surrounding text — write the bare reference instead of wrapping it:

# modern style — write it directly
length = var.pet_length

# old style — still works, but the wrapping is redundant
length = "${var.pet_length}"

Older Terraform (pre-0.12, and its ancestor HCL1) required the ${...} wrapper almost everywhere. Since Terraform 0.12, any expression — a reference, a function call, a conditional — can be used directly as an argument value. Reserve ${...} for what it's actually for: inserting a value into the middle of a longer string, like the file content you'll build in this lesson's hands-on.

Built-in functions

Terraform ships with a fixed set of built-in functions for transforming values — string manipulation, list/map operations, type conversions, math, and more. There is no way to define your own function in the Terraform language itself (that's a common surprise if you're coming from a general-purpose language) — you compose the built-ins instead. Call one like function_name(arg1, arg2).

Try functions live: run terraform console in a folder with a Terraform config. It opens a REPL that evaluates any expression you type — including calling functions with real values from your variables and state — without applying anything. Type exit or Ctrl+D to leave.

The full reference lists dozens of functions across categories like string, collection, numeric, type conversion, encoding, filesystem, date/time, hash, and IP-network functions. Here are the handful you'll use most often, one from each of four core categories, confirmed against HashiCorp's function reference.

String functions

FunctionSignatureExample
formatformat(spec, values...)format("Hello, %s!", "Ander") → "Hello, Ander!"
joinjoin(separator, list)join("-", ["foo","bar","baz"]) → "foo-bar-baz"
splitsplit(separator, string)split(",", "foo,bar,baz") → ["foo","bar","baz"]

format works like C's printf: %s inserts a string, %d an integer, %v a value in its default format. join and split are inverses of each other — join turns a list into one string, split turns one string back into a list.

Collection functions

FunctionSignatureExample
lengthlength(value)length(["a","b"]) → 2 · length("hello") → 5
concatconcat(list1, list2, ...)concat(["a"], ["b","c"]) → ["a","b","c"]
mergemerge(map1, map2, ...)merge({a="b",c="d"}, {c="z"}) → {a="b",c="z"}

length works on lists (element count), maps (key count), and strings (character count). concat chains lists together in order. merge combines maps into one — when the same key appears in more than one map, the value from the later argument wins, which is exactly the pattern you'll use for layering default tags with resource-specific overrides.

Type conversion functions

FunctionSignatureExample
tostringtostring(v)tostring(1) → "1"
tonumbertonumber(v)tonumber("1") → 1

Terraform converts types automatically wherever it safely can, so you'll reach for these rarely — mainly when a variable's declared type doesn't match what a resource argument expects, or a value came in as a string from somewhere (like an environment variable or a CSV file) and needs to be a real number.

Numeric functions

FunctionSignatureExample
minmin(number, ...)min(12, 54, 3) → 3
maxmax(number, ...)max(12, 54, 3) → 54

Both accept either a plain list of numbers, or a single list expanded with the ... spread operator: min([12, 54, 3]...).

Conditional expressions

The conditional operator picks between two values based on a boolean condition — every language calls this the "ternary" operator:

condition ? true_val : false_val

If condition evaluates to true, the whole expression evaluates to true_val; otherwise it evaluates to false_val. A common use is filling in a default:

var.a == "" ? "default-a" : var.a

Both branches should produce the same type — Terraform will try to convert one side to match the other (for example a number to a string), but it's clearer to keep both branches the same type on purpose.

Try it — before looking below

Q1. You write environment = "${var.env}" for an argument that is nothing but that one reference. Is this wrong?

Not wrong — it still works — but it's unnecessary. Since Terraform 0.12, a bare reference is a valid expression on its own. Write environment = var.env instead; save ${...} for when the reference sits inside a longer string.

Q2. What does merge({env = "dev", team = "sre"}, {env = "prod"}) return?

{env = "prod", team = "sre"}. The second map is later in the argument list, so its env value overwrites the first map's env value. Keys that only appear in one map pass through unchanged.

Now write your own

Building on the folder from Lesson 5, you'll add a random_pet whose length depends on a bool variable, and use format() to write a description of it to a local file.

This needs a second provider — hashicorp/local — because local_file is a real resource that writes an actual file to disk (still free, still no cloud account needed). Add it to your terraform block in main.tf:

terraform {
  required_providers {
    random = {
      source  = "hashicorp/random"
      version = "~> 3.6"
    }
    local = {
      source  = "hashicorp/local"
      version = "~> 2.5"
    }
  }
}

provider "random" {}
provider "local" {}

Add two variables:

variable "team_name" {
  description = "Name to embed in the generated file"
  type        = string
  default     = "platform-team"
}

variable "use_short_pet" {
  description = "If true, generate a 1-word pet name instead of 3"
  type        = bool
  default     = false
}

Update your random_pet resource to use a conditional expression for length, and add a local_file resource whose content is built with format():

resource "random_pet" "example" {
  length = var.use_short_pet ? 1 : 3
}

resource "local_file" "pet_info" {
  filename = "${path.module}/pet-info.txt"
  content  = format("Team %s adopted a pet named: %s\n", var.team_name, random_pet.example.id)
}
  • run terraform init (you added a new provider, so this is required, not optional this time)
  • run terraform plan — check length shows 3, since use_short_pet defaults to false
  • run terraform apply, type yes
  • open pet-info.txt in the same folder and confirm it reads something like Team platform-team adopted a pet named: happy-raccoon-bass
  • run terraform apply -var="use_short_pet=true", type yes — notice the plan shows random_pet.example being replaced, not updated in place, because a different word count means a freshly generated name
  • re-check pet-info.txt — it now has a 1-word pet name
  • run terraform destroy, type yes, and confirm both resources and the file are gone

Recap
  • ${...} interpolates an expression inside a larger string. A bare reference used as a whole argument value doesn't need the wrapper — modern Terraform evaluates it directly.
  • Terraform's built-in functions cover strings (format, join, split), collections (length, concat, merge), type conversion (tostring, tonumber), and numbers (min, max) — there are no user-defined functions, only these built-ins composed together. Try any of them instantly with terraform console.
  • condition ? true_val : false_val picks one of two values based on a boolean — useful for defaults and small on/off switches like the pet-length example.
