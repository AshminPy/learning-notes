Tools setup: install Terraform, editor, first provider

Three things, once, before any code: the Terraform CLI itself, an editor that understands Terraform files, and a working folder you commit to as you go. Do all three now — every later lesson assumes they exist.

Simple example: the Terraform CLI is a single command-line program, terraform. You write plain-text files describing the infrastructure you want, and the CLI reads them and does the work — nothing to run in the cloud yet, just a program on your own machine.

1. Install the Terraform CLI

Pick the row for your operating system. These are the current official methods from HashiCorp's own install page.

OSMethodCommand
macOSHomebrewbrew tap hashicorp/tap
brew install hashicorp/tap/terraform
Linux (Ubuntu/Debian)apt repositorywget -O - https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt update && sudo apt install terraform
WindowsBinary downloadDownload the .zip for your architecture (AMD64 or ARM64) from the official install page, unzip it, and put terraform.exe somewhere on your PATH

HashiCorp's install page does not currently list a package-manager option (winget, Chocolatey) for Windows — only signed binary downloads. macOS and Debian/Ubuntu Linux both have proper package-manager methods, which auto-update more easily. If you're on Windows, the binary-download step is normal, not a workaround.

2. Confirm the install

Open a terminal (or PowerShell on Windows) and run:

terraform -version

You should see a line like Terraform v1.x.x on darwin_arm64 — the exact version number will be whatever is current when you install, and that's fine. If the command isn't found, your terminal can't see the terraform binary on its PATH yet — close and reopen the terminal, or re-check the install step above.

3. Editor setup — VS Code + the Terraform extension

  1. Install VS Code from code.visualstudio.com if you don't already have it
  2. Open the Extensions panel (the four-squares icon in the sidebar) and search for HashiCorp Terraform
  3. Install the one published by HashiCorp — it gives you syntax highlighting, auto-formatting, and inline validation as you write .tf files

You don't need any other editor plugin for this course. Syntax highlighting alone will save you from a lot of silly typos once we start writing real configuration files.

4. Working folder + your GitHub repo

Same pattern as every course on this site: one repo, committed to as you go.

  1. Create a folder on your machine, e.g. terraform-learning-log
  2. Create a free account at github.com if you don't have one
  3. Follow GitHub's own "Hello World" quickstart to turn that folder into a repository and push your first commit

Most hands-on exercises in this course use Terraform's local and random providers — they create files and random values on your own machine, not real cloud resources. That means you can follow along with zero cloud account and zero cost. A free-tier cloud account (AWS is the most common) becomes useful later, once we reach the lessons that deploy to a real provider — but you don't need one today.

Try it — before looking below

Q1. Why do most lessons in this course not require a cloud account?

The hands-on examples mostly use the local and random providers, which only touch your own machine — no real cloud infrastructure is created, so nothing to sign up for or pay for.

Recap
  • Terraform CLI installed via Homebrew (macOS), apt (Linux), or a binary download (Windows).
  • terraform -version is how you confirm the install worked.
  • VS Code + the official HashiCorp Terraform extension gives you syntax highlighting and validation.
  • Your working folder is a GitHub repo, committed to as you go — most exercises need no cloud account at all.
