Workload autoscaling

Lesson 4's Deployment holds replica count fixed until you edit it by hand. A HorizontalPodAutoscaler (HPA) edits that number for you, based on real load — more Pods when busy, fewer when idle.

Simple example: the HPA is a thermostat, not a temperature sensor. It doesn't measure CPU itself — it reads numbers from metrics-server (Lesson 23) and adjusts spec.replicas on your Deployment to hit a target. Same reconcile-loop idea as everything else in this course: watch, compare, adjust.

Creating one

kubectl autoscale deployment my-app --cpu-percent=50 --min=1 --max=10

Or the manifest form, which is what the exam usually expects you to write:

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: my-app
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: my-app
  minReplicas: 1
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 50

scaleTargetRef is the only part that points at your Deployment — everything else describes the target and the bounds. This only ever changes replica count (horizontal) — it never changes a single Pod's CPU/memory requests. Resizing an individual Pod's resources is a different, separate feature (Vertical Pod Autoscaler), not part of this lesson.

Reading it

kubectl get hpa
NAME     REFERENCE          TARGETS   MINPODS   MAXPODS   REPLICAS
my-app   Deployment/my-app  35%/50%   1         10        2

If TARGETS shows <unknown>/50% instead of a real number, the HPA has nothing to read from — metrics-server (Lesson 23) isn't installed or isn't reporting yet. That's the single most common HPA failure, and it looks nothing like an error.

Try it — before looking below

Q1. You create an HPA and traffic spikes hard, but kubectl get hpa shows <unknown>/50% and replica count never moves. What's actually broken?

Nothing about the HPA object itself — it's waiting on metrics it never receives. Check kubectl top pods works at all; if it doesn't, metrics-server isn't installed or isn't healthy, and the HPA has no data to act on.

Q2. Write an HPA manifest by hand for a Deployment called web, targeting 70% CPU, min 2 / max 6 replicas. Try it before revealing.

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: web
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web
  minReplicas: 2
  maxReplicas: 6
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70

Recap
  • An HPA only adjusts replica count — it reads metrics, it doesn't produce them.
  • scaleTargetRef points at the Deployment; metrics defines what to watch and the target.
  • TARGETS showing <unknown> means metrics-server is missing or unhealthy — not a bug in the HPA.
