Workload autoscaling

Lesson 4's Deployment holds replica count fixed until you edit it by hand. A HorizontalPodAutoscaler (HPA) edits that number for you, based on real load.

Mental model: the HPA is a thermostat, not a temperature sensor. It doesn't measure CPU itself — it reads numbers from metrics-server (Lesson 23) and adjusts spec.replicas on your Deployment to hit a target. Same watch/compare/adjust loop as Lesson 4's ReplicaSet controller and Lesson 19's Operators. That predicts its single most common failure: a thermostat with a disconnected sensor doesn't error loudly, it just stops adjusting anything.

Where this fits

metrics-server (Lesson 23)  → real CPU/memory numbers
   │
   ▼
HorizontalPodAutoscaler  ← you are here (reads metrics, writes replicas)
   │
   ▼
Deployment.spec.replicas  (Lesson 4 — HPA edits this field, nothing else)

Creating one

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: web
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web
  minReplicas: 2
  maxReplicas: 6
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70

scaleTargetRef is the only field pointing at your Deployment. This only ever changes replica count (horizontal) — never a single Pod's resource requests; resizing an individual Pod is a separate feature (Vertical Pod Autoscaler), not covered here.

Reading it

kubectl get hpa
NAME   REFERENCE          TARGETS   MINPODS   MAXPODS   REPLICAS
web    Deployment/web     35%/70%   2         6         2

If TARGETS shows <unknown>/70% instead of a real number, the HPA has nothing to read from — metrics-server isn't installed or isn't reporting yet. The single most common HPA failure, and it looks nothing like an error.

Try it

Q1. Traffic spikes hard, but kubectl get hpa shows <unknown>/70% and replica count never moves. What's actually broken?

Nothing about the HPA object itself — it's waiting on metrics it never receives. Check kubectl top pods works at all; if not, metrics-server isn't installed or isn't healthy.

Now write your own, by hand: an HPA for a Deployment api, targeting 60% CPU, min 1 / max 8. Try before revealing.

Reveal the reference answer

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: api
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: api
  minReplicas: 1
  maxReplicas: 8
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 60

Common mistake: not setting resource requests (Lesson 11) on the target Deployment — averageUtilization is a percentage of the request, so without one the HPA has no baseline to compute a percentage against.

A controlled failure

kubectl autoscale deployment web --cpu-percent=50 --min=1 --max=5
kubectl get hpa web

Predict first: if metrics-server isn't installed on this cluster, what does TARGETS show? Observe: <unknown>/50%, permanently — the HPA object is valid and created successfully, it just has no data source, the same silent-failure shape every earlier lesson's controlled failure produced.

Production best practices

Production note: set minReplicas above 1 for anything serving production traffic — an HPA scaling down to a single replica during a quiet period removes the redundancy Lesson 4's Deployment was supposed to guarantee.

Recap
  • An HPA only adjusts replica count — it reads metrics, it doesn't produce them.
  • scaleTargetRef points at the Deployment; metrics defines what to watch and the target.
  • TARGETS showing <unknown> means metrics-server is missing or unhealthy — not a bug in the HPA.

Confidence check — answer without looking back:

  • Why does an HPA need a resource request set on the target Deployment to work at all?
  • When would you deliberately set a higher minReplicas than "just enough"?
  • What happens to replica count if metrics-server crashes mid-traffic-spike?
  • How would you verify an HPA is reading real numbers, not just that the object exists?
