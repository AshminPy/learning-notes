PersistentVolumeClaim → Pod

A container's filesystem dies with the container. Anything that must survive a restart needs real, persistent storage. Kubernetes splits this into three layers.

Simple example: think of a PersistentVolume (PV) as an actual storage locker. A PersistentVolumeClaim (PVC) is the request form: "I need a locker this size." A Pod never touches the locker directly — it only holds the claim form.

The three layers

  • PersistentVolume (PV) — the real storage. Cluster-scoped, not namespaced.
  • PersistentVolumeClaim (PVC) — a namespaced request for storage. The cluster binds it to a matching PV.
  • Pod — mounts the PVC, never the PV directly.
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: standard
  resources:
    requests:
      storage: 1Gi

Most clusters (GKE included) auto-create the PV for you — this is dynamic provisioning, triggered by storageClassName. The older pattern, static provisioning, is an admin hand-creating PVs ahead of time.

Try it — before looking below

Q1. Does a Pod's spec.volumes reference a PV or a PVC?

A PVC — always. The Pod never mounts a PV directly.

Q2. Which accessMode lets many nodes mount a volume read-write at the same time?

ReadWriteMany (RWX) — most cloud block storage only supports ReadWriteOnce, so this needs a backend like NFS.

Now write your own

Write a Pod that mounts the PVC above.

  • mounts my-pvc as a volume
  • mounts it at a path in the container, e.g. /usr/share/nginx/html

Reveal the reference answer

apiVersion: v1
kind: Pod
metadata:
  name: pvc-pod
spec:
  containers:
    - name: app
      image: nginx
      volumeMounts:
        - name: data
          mountPath: /usr/share/nginx/html
  volumes:
    - name: data
      persistentVolumeClaim:
        claimName: my-pvc

Source

kubernetes.io/docs/concepts/storage/persistent-volumes

Recap
  • PV = real storage, cluster-scoped. PVC = namespaced request. Pod mounts the PVC, never the PV.
  • Dynamic provisioning (PVC + StorageClass) auto-creates the PV — the default on GKE/cloud.
  • accessModes: ReadWriteOnce (one node), ReadOnlyMany (many, read-only), ReadWriteMany (many, read-write).
