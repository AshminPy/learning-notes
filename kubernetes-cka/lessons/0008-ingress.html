Ingress → Service

A Service gives you a stable address inside the cluster. It has no path in from outside. Ingress is that last hop — it routes outside traffic to the right Service.

Simple example: think of Ingress like a building receptionist. One door, one address. The receptionist reads where you want to go and sends you to the right room — the right Service — based on the hostname and path you asked for.

The shape of an Ingress

An Ingress is a list of rules. Each rule says: for this host and path, send traffic to this Service.

rules:
  - host: nginx.example.com
    http:
      paths:
        - path: /
          pathType: Prefix
          backend:
            service:
              name: nginx-service
              port:
                number: 80
  • host — the hostname this rule matches
  • path / pathType — the URL path, and how strictly it must match
  • backend.service — which Service, and which port, gets the traffic

Notice: an Ingress rule only ever points at a Service, never at Pods directly.

The trap: an Ingress is only routing rules. It does nothing by itself. Something called an Ingress controller has to run in the cluster and read those rules. Apply an Ingress with no controller installed, and nothing happens — no error, just silence.

Try it — before looking below

Q1. You apply a correct Ingress. No traffic gets routed. What's missing?

An Ingress controller. The Ingress object is just rules — a controller has to be running to read them and configure a real proxy or load balancer.

Q2. What field says which controller should handle a given Ingress?

spec.ingressClassName — it names an IngressClass, which maps to a specific controller.

Now write your own

Write an Ingress by hand (no copy-paste) that routes to a Service called nginx-service, with:

  • kind: Ingress, API group networking.k8s.io/v1
  • an ingressClassName of your choice
  • one rule: any host, path /, pathType: Prefix
  • a backend pointing at nginx-service, port 80

Try it before you look at the answer below.

Reveal the reference answer

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: nginx-ingress
spec:
  ingressClassName: nginx
  rules:
    - host: nginx.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: nginx-service
                port:
                  number: 80

Source

kubernetes.io/docs/concepts/services-networking/ingress — the exact page you can search in the real exam.

Recap
  • Ingress routes outside traffic to Services by host and path — it never points at Pods directly.
  • An Ingress does nothing without an Ingress controller running in the cluster.
  • ingressClassName picks which controller handles a given Ingress.
