ConfigMap & Secret → Pod

ConfigMap and Secret pull config out of your image, so the same image runs in dev, staging, and prod unchanged.

Simple example: think of both as a labeled box of key-value pairs sitting in the cluster. A ConfigMap box is see-through — anyone can read it. A Secret box looks locked, but it's really just base64 wrapping, not a real lock.

Same mechanism, different intent

  • ConfigMap — plain-text key-value data. Non-sensitive: flags, URLs, config files.
  • Secret — same shape, but values are base64-encoded, not plain text.

Base64 is not encryption. It's reversible with no key (base64 -d), and a Secret is not encrypted at rest by default — it sits in etcd as base64 text. Real encryption at rest needs a separate EncryptionConfiguration, off by default.

Two ways a Pod reads it

  • Environment variable — valueFrom.configMapKeyRef / secretKeyRef. Simple, but read once at container start — a change needs a restart.
  • Mounted volume — each key becomes a file. Updates after a delay, but your app must watch the file to notice.

Try it — before looking below

Q1. Is a Kubernetes Secret encrypted at rest by default?

No. It's base64-encoded, not encrypted, unless an admin configures EncryptionConfiguration.

Q2. An env var pulled from a ConfigMap — does it update if the ConfigMap changes later?

No. It's read once at container start. The Pod needs a restart to pick up the new value.

Now write your own

Write two manifests by hand:

  • a ConfigMap with one key
  • a Pod that reads that key as an environment variable

Reveal the reference answer

apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  greeting: "hello from configmap"
---
apiVersion: v1
kind: Pod
metadata:
  name: config-env-demo
spec:
  containers:
    - name: app
      image: busybox
      command: ["sleep", "3600"]
      env:
        - name: GREETING
          valueFrom:
            configMapKeyRef:
              name: app-config
              key: greeting

Source

kubernetes.io/docs/concepts/configuration/secret

Recap
  • ConfigMap and Secret are the same mechanism — Secret values are base64-encoded, not encrypted.
  • Secrets aren't encrypted at rest by default; that needs a separate EncryptionConfiguration.
  • Env vars are simple but frozen at start; mounted volumes update later but need the app to watch the file.
