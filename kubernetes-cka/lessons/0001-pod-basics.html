The Pod, bare minimum

Every workload in Kubernetes — Deployment, StatefulSet, Job, whatever sits on top — ultimately runs as one or more Pods. This is the smallest thing the scheduler places on a node. Get this one right and every layer above it (Service, Deployment, RBAC…) is just "more fields on top of a Pod."

Tied to your mission: the CKA's biggest single domain is Troubleshooting (30%), and almost every troubleshooting task starts with "read the Pod spec and figure out what's wrong with it." Fluency here pays off everywhere else.

The mental model

A Pod is a thin wrapper around one or more containers that share a network namespace (same IP, can talk over localhost) and a lifecycle (they start and die together). Most of the time you'll run exactly one container per Pod — multi-container Pods are the exception, not the rule.

Every Kubernetes object you'll ever write — Pod, Deployment, Service, all of them — starts with the same four top-level fields. Learn them once here, and you never re-learn them.

Try it first — before reading on

Q1. What are the four top-level fields every Kubernetes manifest needs (not just Pod)?

apiVersion, kind, metadata, spec

Q2. Inside spec, what's the one field a Pod absolutely cannot exist without — the thing that actually runs?

containers (a list, with at least one entry — name + image are required per container)

Now build it — in your terminal, not here

Open a terminal (or your editor) and write a Pod manifest by hand — no copy-paste. Give it:

  • a name
  • the nginx image
  • a container name

Don't peek at the answer below until you've written something — even a wrong attempt teaches more than reading the answer first.

Reveal the reference answer

apiVersion: v1
kind: Pod
metadata:
  name: my-nginx
spec:
  containers:
    - name: nginx
      image: nginx

Bring what you wrote back to your notes — check it field-by-field against the docs above and confirm what's right, what's missing, and why.

Primary source

Read (or at least skim) the official docs on this — it's the exact page you're allowed to search during the real exam: kubernetes.io/docs/concepts/workloads/pods.

Recap
  • Every manifest: apiVersion, kind, metadata, spec
  • A Pod's spec.containers is the one field it can't live without
  • Most Pods run one container — multi-container is the exception
