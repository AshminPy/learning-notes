The Pod

A Pod is the smallest thing Kubernetes runs. Everything bigger (Deployment, Service, Job) is just "a Pod, plus extra rules."

Simple example: think of a Pod like one shipping container. Inside it: one or more apps that share the same address and the same fate — they start together, they stop together. Most Pods hold just one app.

What's inside a Pod manifest

Every Kubernetes object (Pod, Deployment, Service — all of them) is written the same shape:

apiVersion: v1
kind: Pod
metadata:
  name: my-nginx
spec:
  containers:
    - name: nginx
      image: nginx

Four parts, always:

  • apiVersion — which version of the Kubernetes API this object uses
  • kind — what kind of object this is (here: Pod)
  • metadata — its name and labels
  • spec — what you actually want (here: run the nginx image)

Learn these four once. Every object you write from here on reuses the same shape.

Recap
  • A Pod = one or more containers that share an IP and a lifecycle.
  • Every object: apiVersion, kind, metadata, spec.
  • spec.containers is the part a Pod can't exist without.
