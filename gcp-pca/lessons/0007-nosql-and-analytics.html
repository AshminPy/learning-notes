Firestore vs Bigtable vs BigQuery

Three GCP data services with similar-sounding names, different jobs. The exam loves testing them against each other.

Simple example: Firestore is a filing cabinet for one app's user data — fast, small lookups. Bigtable is a conveyor belt built for a firehose of incoming data — sensors, clicks, ticks. BigQuery is a research library — ask a big question over huge piles of data, wait a few seconds for the answer.

Firestore

Serverless NoSQL document database. Built for mobile and web apps — user profiles, sessions, real-time sync, works offline. Strongly consistent queries. You pay per read/write/delete, not per server.

Bigtable

Wide-column NoSQL database for massive scale. Built for time-series, IoT, adtech clickstreams — anything with huge write volume and simple key-value lookups. No SQL, no joins. You provision nodes, and throughput scales linearly with node count.

BigQuery

Serverless data warehouse. Built for SQL analytics over huge datasets — dashboards, ad-hoc queries, logs at petabyte scale. Query latency is seconds, not milliseconds. You pay per byte scanned (or a flat rate for reserved capacity).

Exam trap: a scenario asking for "fast, low-latency point lookups" is never a BigQuery answer — BigQuery is built for scanning, not point lookups, and its latency is seconds. If the scenario also says "no SQL/joins needed, just raw throughput," that's pointing at Bigtable, not BigQuery.

Quiz — Lesson 7

Q1. A mobile app needs offline sync and real-time updates for user profiles. Which service fits?

A. Firestore is built exactly for this — mobile/web apps, offline support, real-time sync.

Q2. An IoT pipeline needs to ingest millions of sensor writes per second with simple key lookups. Which service fits?

B. Bigtable's node-linear throughput and key-value model is built for exactly this write volume.

Q3. An analytics team wants ad-hoc SQL over 50TB of logs, no servers to manage. Which service fits?

C. Ad-hoc SQL, no ops burden, large scale — that's BigQuery's on-demand model.

Q4. Which of these three does not support SQL or joins?

B. Bigtable has no SQL and no joins — it's pure key-value at scale.

Recap
  • Firestore = app data, document reads, real-time sync.
  • Bigtable = huge write volume, key-value, no SQL.
  • BigQuery = SQL analytics over huge datasets, seconds latency, pay per scan.
