VMware Engine, patch management & intrusion protection

Three named-but-narrow exam-guide items that don't fit neatly into earlier lessons: a service for VMware shops, an operational feature for patching fleets of VMs, and a network-layer threat detector distinct from Cloud Armor (Lesson 9).

Simple example: Cloud Armor is the bouncer at the front door, checking who comes in. Cloud IDS is a guard walking the halls once people are already inside, watching for anyone acting suspiciously.

Google Cloud VMware Engine (GCVE)

A fully managed service that runs the actual VMware stack — vSphere, vCenter, vSAN, NSX, HCX — on Google Cloud infrastructure. The point isn't performance or cost, it's operational continuity: your existing VMware-based applications, security procedures, DR backups, audit practices, and compliance tooling keep working unchanged, because it's genuinely VMware underneath, not an emulation.

Exam trap: "we have a huge VMware estate and can't re-platform right now, but need to exit the data center" is a VMware Engine scenario, not a Compute Engine rehost. Compute Engine means converting every VM and retraining ops on a new toolchain; VMware Engine means the same vSphere skills and tools, just pointed at Google's infrastructure.

Patch management (VM Manager)

Part of VM Manager, this automates OS-level patching across a fleet of Compute Engine VMs (Windows and Linux) — schedule one-time or recurring patch jobs, and get compliance reporting that categorizes each VM's patch status by severity (Critical, Important/Security, Other, Up to date) in a central dashboard. This is fleet-wide OS hygiene, distinct from Lesson 17's Cloud Build/Cloud Deploy (which patches your application, not the underlying OS).

Cloud IDS — network-layer threat detection

Cloud IDS monitors network traffic inside your VPC and alerts on malicious activity — it's powered by Palo Alto Networks' threat detection engine. The distinction that matters for the exam:

Cloud Armor (Lesson 9)Cloud IDS
LayerApplication (L7), at the edgeNetwork, inside the VPC
JobBlocks/allows traffic (WAF, DDoS)Detects and alerts on threats already past the edge
Typical trafficNorth-south (internet-facing)East-west (service-to-service) and north-south

Cloud Armor stops known-bad traffic at the door. Cloud IDS watches for suspicious behavior once traffic is already inside — they answer different questions and a mature design often uses both.

Try it — before looking below

Q1. A company has 2,000 VMs on vSphere, tight compliance requirements tied to their existing VMware tooling, and a data-center-exit deadline. Rehost to Compute Engine, or VMware Engine?

VMware Engine. A hard deadline plus compliance tooling tied to VMware itself means re-platforming 2,000 VMs to Compute Engine is both slower and riskier — VMware Engine hits the deadline while keeping the existing tools and audit trail intact.

Quiz — Lesson 27

Q1. What does Cloud IDS actually do that Cloud Armor doesn't?

A. That's Cloud Armor's job. Cloud IDS's distinct value is internal/east-west visibility — traffic that never touches the edge at all.

Q2. A fleet of 500 Compute Engine VMs needs OS-level security patches applied on a monthly schedule, with a compliance report afterward. What closes this gap?

A. Cloud Build handles application CI, not OS-level patching across a VM fleet — that's exactly what VM Manager's patch deployment and compliance reporting are for.

Recap
  • VMware Engine runs the real VMware stack on GCP for operational continuity, not a re-platform to Compute Engine.
  • VM Manager's patch management is fleet-wide OS patching + compliance reporting, distinct from application CI/CD.
  • Cloud Armor guards the edge (L7, north-south). Cloud IDS watches traffic already inside the VPC (network layer, east-west too) — powered by Palo Alto Networks.
