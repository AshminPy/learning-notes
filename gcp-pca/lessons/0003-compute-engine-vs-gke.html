GCP PCA — Lesson 3 of 28

Compute Engine vs GKE

Both run your code on servers. The exam question is never "can this work" — both usually can. It's "which one needs the least babysitting for this scenario."

Simple example: Compute Engine is an empty apartment — you get full control, but you fix your own leaks. GKE is a serviced building — staff (Google, especially in Autopilot mode) patch and manage the common parts, you still furnish and run your own unit.

Compute Engine — plain VMs

This is GCP's raw virtual machine (IaaS). AWS equivalent: EC2.

  • Use when: you need OS/kernel-level control, per-core licensed software, dedicated/sole-tenant hardware for compliance, or long-running stateful processes.
  • You own: OS patching, scaling (via Managed Instance Groups), and high availability.
  • Cost shape: per-second billing. Spot VMs give up to 91% off with no fixed runtime cap. Sustained- and committed-use discounts exist too.

GKE — managed Kubernetes

GKE runs containers for you, orchestrated by Kubernetes.

  • Use when: the workload genuinely needs Kubernetes features — StatefulSets, DaemonSets, sidecars, custom schedulers, CRDs — or must be portable across clouds.
  • Autopilot: Google manages the nodes; you pay per Pod resource request.
  • Standard: you provision and pay for nodes directly, whether Pods are using them or not.
  • Cost shape: a flat $0.10/cluster/hour management fee applies to every cluster, both modes. The free tier gives $74.40/month credit, covering one zonal cluster's fee.
Exam trap: "pick the managed option" is not a safe default. If the scenario names a constraint only a VM can solve — custom kernel modules, per-core licensing, sole-tenant compliance — Compute Engine is correct, and GKE (even Autopilot) is the wrong, over-managed answer.

Quiz — Lesson 3

Q1. A scenario requires per-core licensed software that must run on dedicated hardware for compliance. What's the correct pick?

A. Sole-tenant hardware and per-core licensing are constraints only Compute Engine solves directly. Managed platforms don't give you that level of hardware control.

Q2. In GKE Autopilot, what are you billed for?

A. Autopilot bills per Pod resource request. Standard mode is the opposite — you pay for provisioned nodes, whether Pods use them or not.

Q3. Which clusters pay the $0.10/hour GKE cluster management fee?

A. The fee is flat and applies to every cluster regardless of mode or size. One zonal cluster's fee is covered by the $74.40/month free-tier credit.

Q4. How does a Spot VM's runtime cap compare to the older preemptible VM?

A. Spot VMs removed the fixed runtime cap that preemptible VMs had. The old 24-hour limit doesn't carry over — don't assume it still applies.

Recap
  • Compute Engine = full control, you patch and scale it yourself. Right answer only when a stated constraint needs VM-level control.
  • GKE = right when the scenario genuinely needs Kubernetes features or portability. Autopilot bills per Pod, Standard bills per node — both pay the same flat cluster fee.
  • "Managed is usually better" is a bias, not a rule — read the constraint sentence first.
