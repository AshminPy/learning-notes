8. Common exam traps

#Trap
1Technically correct ≠ best — check it fits the WAF pillar the scenario is testing.
2"Autopilot" reads as fully managed and pulls you toward GKE — a single stateless HTTP service with no K8s-specific need is Cloud Run's job.
3Cloud SQL HA protects a zone failure only, never a region — multi-region durability signals Spanner.
4Global LB and Cloud CDN require Premium Tier — never on Standard Tier, however the scenario is worded.
5IAM = who; Org Policy = what/how. A named resource property (region, key creation, sharing) is Org Policy, not IAM.
6"Audit logs" isn't one bucket — Data Access logs are off by default, 30-day retention. If never enabled, the answer is "not available," not "check the logs."
7A multi-/dual-region Cloud Storage bucket alone is not a DR strategy — says nothing about your compute or DB tier's recovery plan.
8WAF Cost pillar means max value per dollar, not least spend — an all-Spot fleet ignoring a stated SLA is a trap even though it's cheapest.
9A hard deadline overrides "architecturally better" — Rehost beats Refactor when the scenario states a time constraint.
10The 2026 AI branding shift (Gemini Enterprise/Agent Platform) isn't a clean rename — it adds agent orchestration/governance scope on top of Vertex AI, and "Vertex AI" is still live in current docs/SDKs. Answer by what the service does, not which brand name appears in the stem.

11. Top facts to remember

Distinct, testable facts not already fully covered above. Grouped by topic, one line each.

Compute

  • Custom machine types (N/E series only): 5% premium over predefined pricing.
  • Spot VM: up to 91% off, no min/max runtime, 0s default preemption notice (configurable to 120s). Legacy preemptible capped at 24h — Spot has no cap.
  • GKE cluster mgmt fee: flat $0.10/cluster/hr, any mode/size. Free tier: $74.40/mo credit covers one zonal cluster's fee.
  • Autopilot bills per Pod resource request; Standard bills per provisioned node.
  • Cloud Run: idle instances kept warm up to 15 min (10 for GPU). Two billing models — request-based (default, throttles after response) vs instance-based (CPU stays allocated).
  • Cloud Functions renamed Cloud Run functions on Aug 21, 2024. Up to 16 GiB RAM / 4 vCPU per instance.

Storage & databases

  • Cloud Storage: strong consistency for read-after-write, metadata-update, delete, listing — all classes, including multi-region.
  • Filestore tiers: Basic (legacy), Zonal, Regional, Enterprise (multishare for GKE).
  • Cloud SQL HA failover: ~60s via a shared static IP.
  • Spanner uses TrueTime for external consistency — stronger than plain strong consistency.
  • Bigtable SSD: ~17,000 reads/sec, ~14,000 writes/sec per node (1KB rows); scans up to 220 MBps/node.
  • BigQuery: 90-day-unmodified data gets a long-term storage discount automatically.

Networking

  • GCP subnets are regional, spanning all zones — unlike AWS's zonal subnets.
  • Cloud DNS forwarding (on-prem↔GCP) and DNS peering (GCP net↔GCP net) are different mechanisms — don't swap them.
  • Shared VPC attachment needs compute.xpnAdmin plus resourcemanager.projectIamAdmin.
  • Cloud NAT requires a Cloud Router as its config holder, even with no BGP peering.
  • Cloud CDN only works with the global external (or classic) Application Load Balancer.

IAM & security

  • 3 IAM role types: Basic (Owner/Editor/Viewer — avoid), Predefined (Google-maintained), Custom (static, no auto-update).
  • IAM inheritance is a union down the hierarchy — a child can only add access, never revoke a parent's grant. Deny policies are the one mechanism that overrides an inherited allow.
  • Workload Identity Federation: Pool + Pool Provider + Attribute Mapping, exchanged via OAuth 2.0 token exchange.
  • Service account impersonation issues short-lived tokens (hours or less, not auto-refreshed).
  • Cloud Build supports SLSA Level 3 build provenance.
  • Sensitive Data Protection (formerly DLP): PII/credit-card discovery and classification.

Ops, reliability & DR

  • _Default log bucket: 30-day retention. _Required bucket: 400 days, not configurable.
  • 4 audit log types: Admin Activity (always on, 400d), System Event (always on, 400d), Data Access (off by default except BigQuery, 30d), Policy Denied (on by default, 30d).
  • Error Reporting has no separate ingestion pipeline — it scans Cloud Logging for formatted stack traces.
  • Cloud Trace samples by default — Cloud Run's documented default is ~0.1 requests/sec/instance.
  • No prior Google notification or permission required to pen-test your own GCP projects (within the Acceptable Use Policy).
  • Rolling update is GKE's default deployment strategy.
  • 4 DR patterns (AWS-style naming): Backup & restore, Pilot light, Warm standby, Multi-site active-active — Google's own docs use cold/warm/hot instead.
  • Persistent Disk snapshots are incremental by default; a globally-scoped snapshot can create a disk in any region.
  • Cloud SQL backup retention: 1 day–10 years depending on edition. PITR: Enterprise 1–7d (default 7), Enterprise Plus 1–35d (default 14).
  • Spanner backups retain up to 1 year; restore mounts the backup directly (low RTO). Spanner PITR is separate, up to 7 days.
  • Cloud Storage dual-region turbo replication bounds RPO to within 15 minutes.
  • Cloud SQL Enterprise Plus offers advanced DR with near-zero-data-loss cross-region failover.

Cost

  • Resource-based CUD: up to 55% off (1yr/3yr blended) standard families, up to 70% memory-optimized (3yr). Also covers OS licenses: SLES up to 79%, RHEL up to 20%.
  • Spend-based (Compute Flexible) CUD: general/compute-optimized 28% (1yr) / 46% (3yr); memory-optimized (M1–M4) 63% (3yr only).
  • SUD still active, not deprecated: up to 30% (N1/M1/M2/f1-micro/g1-small), up to 20% (N2/N2D/C2). Applies automatically after >25% of a billing month. Excludes App Engine, Dataflow, anything already on a CUD.
  • Cloud Storage lifecycle order: Standard → Nearline (<1×/mo) → Coldline (<1×/quarter) → Archive. Coldline minimum duration 90 days — early deletion/transition costs a fee.
  • Compute Engine rightsizing recommender: watches ~trailing 8 days of CPU/memory, recommends within 24h, suppresses savings under $10/mo.

Migration

  • Google's 6-way migration framework: rehost, replatform, refactor, re-architect, rebuild, repurchase.
  • Migration Center handles discovery, cost/TCO estimation, assessment, and planning — it doesn't touch or move workloads. Organizes work into waves and move groups (R&D → pre-production → production).
  • Windows Server BYOL with a dedicated-hardware requirement needs sole-tenant nodes; most Linux BYOS and Microsoft app licensing don't.
  • Google's 4-phase migration methodology: Assess → Plan → Deploy → Optimize.
  • Hybrid = public cloud + at least one private environment. Multicloud = 2+ public CSPs together.
  • Current guidance favors gcloud storage over legacy gsutil — gsutil lacks soft delete and managed folders.
  • Bigtable, Spanner, Pub/Sub, and Firestore all ship official local emulators.
  • Terraform on GCP has two providers: google (GA APIs) and google-beta (beta APIs).
  • A single migration can mix strategies — e.g. database replatformed while the app layer is rehosted.

AI & eventing

  • Gemini Enterprise/Agent Platform (2026) is not purely a Vertex AI rename — it's expanded scope (agent orchestration, governance) layered on top; "Vertex AI" persists in current docs/SDKs. Both terms may appear on the exam.
  • Model Garden: catalog of 200+ foundation models (Gemini, Claude, Gemma, Llama).
  • Agent Builder bundles the Agent Development Kit, Agent Studio, Agent Garden, and Model Garden.
  • AI Hypercomputer is the infrastructure layer (TPUs/GPUs, networking, storage, frameworks) under large-scale training — not provisioned per app.
  • Pub/Sub: at-least-once delivery, no ordering guarantee by default (ordering keys available if needed).
  • Eventarc uses a Pub/Sub topic as transport under the hood — a routing/management layer on top of event sources.
  • Cloud Scheduler: Unix cron syntax, at-least-once delivery, targets HTTP endpoints, Pub/Sub topics, or App Engine.
  • Cloud Tasks is for app-scheduled work queues you control the rate of — distinct from Eventarc (platform events) and Pub/Sub (arbitrary messaging).

Process & implementation

  • Apigee manages API access (auth, quota, monetization, portal) — it never hosts the backend itself.
  • Cloud Build = CI (build/test). Cloud Deploy = CD (progressive rollout, canary, approval gates).
  • gcloud storage is current guidance over legacy gsutil for Cloud Storage CLI operations.
  • Root cause ≠ trigger. A blameless postmortem explains why a failure wasn't caught, not just what broke.
  • Business continuity is broader than disaster recovery — it covers people/process continuing to operate, not just systems failing over.
  • A technically ideal architecture the team can't operate (no training plan mentioned) is a common exam trap — readiness matters as much as the design.
  • SOC 2 / compliance certification of the platform (GCP) does not make an application built on it automatically compliant — shared responsibility.

12. Top architecture patterns

Pattern 1 — Global low-latency, read-heavy web app (static assets)

Cloud Storage multi-region bucket, fronted by a global external Application Load Balancer (Premium Tier) with Cloud CDN for edge caching.

Pattern 2 — Regulated data with strict residency

Org Policy gcp.resourceLocations to pin location, a VPC Service Controls perimeter to stop authorized-but-risky exfiltration, Cloud KMS CMEK for customer-controlled encryption at rest.

Pattern 3 — Event-driven microservices (file lands, gets processed)

Cloud Storage object-finalize event → Eventarc trigger → Cloud Run function/service validates/transforms → writes to BigQuery. No custom polling anywhere.

Pattern 4 — Lift-and-shift under deadline pressure

Migration Center discovery/assessment first, then Rehost to hit the hard deadline; defer Replatform/Refactor to an unfunded, undated phase 2.

Pattern 5 — Multi-region DR for a critical database

Near-zero RPO/RTO: Spanner multi-region (external consistency, 99.999% SLA). Minutes-scale RPO/RTO: Cloud SQL HA (zone-level) plus a cross-region read replica kept warm as a promotable standby.

Pattern 6 — Global, zero-downtime-tolerant platform (fintech-style)

Multi-site active-active: Spanner multi-region instance, GKE clusters in multiple regions behind Multi-cluster Gateway, global external LB routing to the nearest healthy region. Expensive — that's the point.

Pattern 7 — Secure CI/CD pipeline deploying to GCP

Workload Identity Federation (no downloaded service account key) impersonating a scoped service account, Binary Authorization + Artifact Registry attestations gating what's allowed to deploy.

Pattern 8 — Cost-optimized mixed workload (steady API + batch job)

Resource-based or spend-based Committed Use Discount (plus automatic SUD) for the always-on, SLA-bound API; Spot VMs for the checkpointable, fault-tolerant nightly ETL batch. Never the reverse.
