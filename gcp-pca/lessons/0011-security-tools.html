GCP PCA — Lesson 11 of 24

Security tools: Secret Manager, KMS, VPC-SC, Org Policy

Four tools, four different jobs. Mixing them up is the exam's favorite trap.

Simple example: think of a house. Secret Manager is a locked drawer holding your spare key — you can open the drawer and take the key out. KMS is a locksmith — he encrypts and decrypts for you, but he never hands you the key itself. VPC Service Controls is a fence around the yard — even someone allowed inside the house can't carry things past the fence. Organization Policy is a house rule that applies even to the owner — like "no smoking indoors," no exceptions.

Secret Manager vs KMS

Secret Manager stores a value — a password, an API key, a certificate. If you're allowed to read it, you get the real value back.

KMS (Key Management Service) stores encryption keys. You never get the key itself back — you only ask it to encrypt or decrypt something for you.

  • Rotating a database password? Secret Manager.
  • Encrypting a whole Cloud Storage bucket with a key you control? KMS.

VPC Service Controls (VPC-SC)

VPC-SC draws a boundary around your GCP services (like Cloud Storage or BigQuery). Even a user with valid access cannot copy data out across that boundary.

This is different from IAM. IAM says who can read the data. VPC-SC says data cannot leave this fence — it stops an authorized person from walking off with it.

Organization Policy vs IAM

IAM controls who can do something. Organization Policy controls what configurations are allowed, no matter who you are.

Exam trap: "stop an authorized user from copying data out, even though their IAM access is correct" always means VPC-SC — not a tighter IAM role. IAM already said yes to reading the data; only VPC-SC can still say no to it leaving.

Try it — before looking below

Q1. A scenario needs to stop anyone — even project Owners — from creating service account keys. What do you use?

A. Org Policy blocks the action for everyone, including Owners. IAM roles only control who has access — they can't block the action itself.

Q2. Which tool lets an authorized caller read back the actual plaintext value?

A. Secret Manager returns the real value. KMS only encrypts/decrypts on request — the key itself never leaves KMS.

Q3. A contractor has valid read access to a BigQuery dataset but must never export the results outside the org. What closes that gap?

A. IAM already grants the read. VPC-SC is the only one of these that blocks data leaving the boundary, regardless of valid IAM access.

Recap
  • Secret Manager stores a value you can read back. KMS manages keys you never see.
  • VPC-SC blocks data from crossing a boundary, even for an authorized user.
  • Org Policy controls what's allowed for everyone, including Owners. IAM controls who.
