Agent Platform Pipelines & AI Hypercomputer

Lesson 16 covered the Vertex AI → Gemini Enterprise Agent Platform rename and Model Garden. This lesson is the operational half the exam guide names separately under provisioning (Section 2.4/2.5): how ML workflows actually get orchestrated and run at scale, not just which model to pick.

Simple example: Model Garden (Lesson 16) is choosing a recipe. Agent Platform Pipelines is the kitchen's actual production line — prep, cook, plate, repeatably, the same way, every time a new batch is ordered.

Agent Platform Pipelines — orchestrating the ML lifecycle

A pipeline defines the ML workflow as a sequence of steps — prepare data, train, evaluate, deploy — as a reproducible, versioned graph, the same underlying idea as Kubeflow Pipelines. The value isn't running one training job once; it's re-running the exact same workflow later with different data and getting a comparable, auditable result.

Exam trap: "we trained a good model once" is not the same as "we have a reproducible pipeline." If a scenario needs repeatable, auditable retraining — not a one-off experiment — that's a pipelines answer, not just a Model Garden answer.

AI Hypercomputer

Google's term for the integrated system behind large-scale AI workloads — optimized hardware (TPUs and GPUs), the software stack, and flexible consumption models, designed to work together rather than be assembled piece by piece. The exam-relevant takeaway: recognize it as the answer when a scenario needs large-scale training/serving infrastructure, not a specific command or config to memorize.

Choosing GPUs vs. TPUs

  • TPUs — Google's own accelerator, optimized for large-scale training of TensorFlow/JAX-style models at high throughput.
  • GPUs — broader framework support (PyTorch and others), often the more flexible default when the workload or team's tooling isn't TPU-specific.

Consumption model matters as much as the chip: on-demand for unpredictable workloads, reserved for steady long-running training, spot/preemptible for interruption-tolerant batch training at lower cost.

Prebuilt AI APIs & Gemini Enterprise features

For common tasks, Google's prebuilt AI APIs (Vision, Video, Audio, Conversation, Search) skip training entirely — call an API, get a result, no model of your own to manage. Separately, Gemini Enterprise bundles agent-building tools and NotebookLM-style features for teams building on top of the platform rather than training from scratch.

Try it — before looking below

Q1. A team needs to retrain a fraud-detection model weekly on fresh data, with a repeatable, auditable process. Model Garden alone, or Agent Platform Pipelines?

Pipelines. Model Garden picks a starting model; a recurring, auditable, repeatable retraining workflow is exactly what pipeline orchestration exists for.

Quiz — Lesson 23

Q1. A scenario just needs to extract text from scanned documents — no custom model, no training data of their own. What's the fastest fit?

A. A common, well-defined task with no custom model requirement is exactly what prebuilt APIs are for — training your own model here would be unnecessary cost and time.

Q2. A batch training job can tolerate being interrupted and resumed, and cost matters more than guaranteed availability. Which consumption model fits?

A. Interruption-tolerant, cost-sensitive batch work is the textbook fit for spot/preemptible capacity.

Recap
  • Model Garden picks a model; Pipelines orchestrate the repeatable workflow around it.
  • AI Hypercomputer = the integrated hardware+software+consumption-model system behind large-scale AI, not a single product to configure.
  • TPUs: throughput at scale, Google-framework-optimized. GPUs: broader framework flexibility.
  • A well-defined task with no custom data need often fits a prebuilt API better than training a model.
