GCP PCA — Lesson 4 of 24

Serverless compute: Cloud Run, App Engine, Cloud Run functions

No servers to manage on any of these three. The exam question is which one fits the shape of the workload — a full service, a whole app, or one small event-triggered task.

Simple example: Cloud Run is a food truck — show up, serve, pack up when there's no line (scale to zero). App Engine Flexible is a restaurant with the lights always on, even with no customers. Cloud Run functions is a vending machine — one small job, triggered by one event, nothing else.

Cloud Run — serverless containers

AWS equivalent: App Runner / Fargate.

  • Use when: stateless HTTP(S) or gRPC services, bursty traffic, you want true scale-to-zero, and you want to bring any language in a container.
  • Cost shape: scale-to-zero by default, up to 60-minute request timeout, concurrency up to 1000 requests/instance. Default billing throttles CPU right after the response is sent — switch to instance-based billing for background work.

App Engine — the original PaaS

AWS equivalent: Elastic Beanstalk. Two environments, very different:

  • Standard: sandboxed runtime, cold start in seconds, true scale-to-zero.
  • Flexible: runs your Docker container on VMs, cold start in minutes, no scale-to-zero — minimum 1 instance always on.

Cloud Run functions (formerly Cloud Functions)

Renamed from Cloud Functions on August 21, 2024 — same product, same APIs, new name.

  • Use when: small, single-purpose, event-triggered code — a file lands in Cloud Storage, a Pub/Sub message arrives, glue code with no Dockerfile needed.
  • Limit: event-triggered runs are capped at 9 minutes, a hard ceiling. HTTP-triggered functions can go up to 60 minutes.
Exam trap: App Engine Flexible runs Docker, so it looks like the "managed, container-friendly" answer — but it cannot scale to zero. If a scenario says "minimize cost for a rarely-used containerized app," the correct answer is Cloud Run, not App Engine Flexible.

Quiz — Lesson 4

Q1. By default, what happens to a Cloud Run service with no traffic?

A. Scale-to-zero is Cloud Run's default. It's the main cost-shape difference from App Engine Flexible, which always keeps at least one instance on.

Q2. Which App Engine environment can scale all the way down to zero instances?

A. Standard scales to zero. Flexible is VM-backed and always keeps a minimum of 1 instance running.

Q3. An event-triggered Cloud Run function needs more than 9 minutes to finish. What's the fix?

A. The 9-minute event-trigger cap isn't tunable. An HTTP-triggered function (up to 60 min) or a full Cloud Run service/job is the correct fix, not raising a setting that doesn't exist.

Q4. What is the current official name for the former Cloud Functions product?

A. Renamed to Cloud Run functions on August 21, 2024. If an older question bank still says "Cloud Functions," it's the same product.

Recap
  • Cloud Run = scale-to-zero by default, 60-min timeout, any container.
  • App Engine Flexible cannot scale to zero (min 1 instance); only Standard can.
  • Cloud Run functions = single-purpose event glue code, 9-min cap on event triggers, renamed from Cloud Functions in Aug 2024.
