AI platform naming shift, and the event-driven glue

Flag this clearly: Google's AI platform branding changed in 2026 — but it is not just a rename. Google Cloud's own materials describe Gemini Enterprise and Agent Platform as new offerings for agent development, orchestration, and governance, built on top of Vertex AI's existing capabilities (train/deploy/predict, Model Garden) rather than a like-for-like swap of one name for another. "Vertex AI" still appears throughout the current technical docs and SDK/API names — it hasn't disappeared, it's now positioned as the underlying layer under the newer umbrella branding. (Verified against docs.cloud.google.com/vertex-ai and Google Cloud's Gemini Enterprise announcement, 2026-07-26 — verify again before the exam, as this naming is still actively evolving.)

Simple example: not a new sign on the same restaurant — more like the restaurant added a new tasting menu and a maître d' (agent orchestration, governance), while keeping the original kitchen (Vertex AI's train/deploy/predict) running underneath. Don't assume everything just got relabeled; some of it is genuinely new scope.

Vertex AI, Gemini Enterprise, and Agent Platform

LayerWhat it covers
Vertex AI (still the underlying term in docs/SDKs)Managed ML platform: train, deploy, predict; still referenced directly in API/SDK names
Model GardenCatalog of foundation models (Gemini, Claude, Gemma, Llama) — part of Vertex AI's original scope
Agent Builder / Agent PlatformToolkit and orchestration layer to build, run, and govern multi-step agents — the newer, expanded scope
Gemini EnterpriseThe broader enterprise umbrella (agents + Workspace integration + governance) announced alongside Agent Platform

Model Garden vs Agent Builder

Model Garden — pick a ready-made foundation model, no training needed. Agent Builder — build something that reasons, calls tools, and does multi-step work, not just one prompt in, one answer out.

Pub/Sub vs Eventarc vs Cloud Scheduler

ServiceTrigger typeTypical use case
Pub/SubMessage, published by your appDecouple services; fan out one event to many consumers
EventarcEvent, from a GCP serviceReact to a resource change (file uploaded) with no custom polling
Cloud SchedulerTime, cron scheduleNightly batch job, recurring cleanup

Fast filter: named moment in time → Scheduler. Something happened to a GCP resource → Eventarc. Your own app publishing data → Pub/Sub.

Exam trap: "trigger a Cloud Run function when a file lands in Cloud Storage" is Eventarc, not raw Pub/Sub — even though Eventarc uses Pub/Sub as transport underneath. You didn't build that plumbing, so it's not the Pub/Sub answer.

Try it — before looking below

Q1. Is "Vertex AI" simply a retired name that's been fully replaced by "Gemini Enterprise Agent Platform"?

B. Treating this as "just a rename" is the trap — the branding expanded to cover agent development and governance, and "Vertex AI" is still live terminology in the technical docs. Expect multiple names on the exam; answer by what the service does.

Q2. A scenario needs a multi-step agent that calls tools and reasons over documents. Best fit?

C. Agent Builder is for tool-using, multi-step agents. Model Garden just gives you a model to call.

Q3. A file lands in Cloud Storage and must trigger a Cloud Run function automatically, no custom polling. Best fit?

B. Eventarc standardizes the Storage event and routes it for you, retries included.

Recap
  • Not just a rename — Gemini Enterprise/Agent Platform adds agent orchestration and governance scope on top of Vertex AI's original train/deploy/predict capabilities; "Vertex AI" is still live terminology in current docs and SDKs.
  • Model Garden = pick a model. Agent Builder = build a multi-step agent.
  • Pub/Sub = message you publish. Eventarc = GCP resource event. Scheduler = fixed time.
