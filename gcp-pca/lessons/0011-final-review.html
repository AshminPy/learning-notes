8. Common exam traps — one per session

The single highest-value trap from each session. Full explanation is in the linked file.

#TrapSession
1A technically-correct answer can still be wrong if it optimizes the wrong WAF pillar for the scenario.0001
2Autopilot reads as "fully managed" and tempts you to pick GKE for everything — but a single stateless HTTP service with no K8s-specific need is Cloud Run's job, not GKE's.0002
3Cloud SQL HA protects against a zone failure only, never a region failure — multi-region durability signals Spanner.0003
4Global load balancers and Cloud CDN require Premium Tier — they cannot exist on Standard Tier no matter how the scenario is worded.0004
5IAM governs who; Organization Policy governs what/how — a scenario naming a resource property (region, key creation, sharing) is Org Policy, not IAM, even if it feels like an access question.0005
6"Audit logs" is not one bucket — Data Access logs are off by default and only 30-day retention; if they were never enabled, the answer is "that data isn't available," not "check the logs."0006
7A multi-region or dual-region Cloud Storage bucket is not, by itself, a DR strategy — it says nothing about your compute or database tier's recovery plan.0007
8The WAF Cost Optimization pillar means "maximize value per dollar," not "spend the least" — an all-Spot fleet that ignores a stated SLA is a trap answer even though it's cheapest.0008
9A hard deadline always overrides "architecturally better" — Rehost beats Refactor when the scenario states a time constraint, even though Refactor is a real best practice for a different scenario.0009
10Vertex AI was renamed Gemini Enterprise Agent Platform (April 2026) — answer by what the service does, not which brand name appears in the question stem.0010

10. Last-minute revision notes

Exam format: 2 hours, 50–60 questions, $200, online-proctored or testing center.

6 exam sections (weight): Design & plan 25% · Managing/provisioning infrastructure 17.5% · Security & compliance 17.5% · Analyzing/optimizing processes 15% · Managing implementation 12.5% · Ops excellence 12.5%.

6 WAF pillars: Operational Excellence · Security, Privacy & Compliance · Reliability · Cost Optimization · Performance Optimization · Sustainability (6, not 5 — a recent addition, don't answer from stale memory).

4 case studies (skim before the exam): Altostrat Media · Cymbal Retail · EHR Healthcare · KnightMotives Automotive. Up to 20–30% of questions reference one. Several already use Google's generative AI — don't assume "traditional industry" means AI-averse.

Elimination algorithm:

  1. Underline constraint keywords ("minimal ops," "strict compliance," "unpredictable traffic") — they name the WAF pillar being tested.
  2. Eliminate options that violate that pillar outright, even if technically functional.
  3. Eliminate options solving the wrong problem (a real best practice, just for a different scenario).
  4. Between the last two: default to less custom engineering, unless the scenario explicitly demands the control only the complex option provides.

11. Top facts to remember

100 compact, exam-relevant facts pulled from Sessions 1–10. Session tag in parentheses.

  1. PCA exam: 2 hours, 50–60 questions, $200, online-proctored or testing center. (S1)
  2. Case studies referenced in up to 20–30% of questions: Altostrat Media, Cymbal Retail, EHR Healthcare, KnightMotives Automotive. (S1)
  3. 6 WAF pillars, not 5 — Sustainability is a recent addition. (S1)
  4. Exam section weights: Design & Plan 25%, Provisioning 17.5%, Security 17.5%, Analyzing/Optimizing 15%, Managing Implementation 12.5%, Ops Excellence 12.5%. (S1)
  5. Several case-study companies already use Google's generative AI. (S1)
  6. Custom machine types (N/E series only) carry a 5% premium over predefined on-demand/commitment pricing. (S2)
  7. Spot VMs: up to 91% discount, no min/max runtime, 0-second default preemption notice (up to 120s configurable). (S2)
  8. GKE cluster management fee: flat $0.10/cluster/hour, applies to every cluster regardless of mode or size. (S2)
  9. GKE free tier: $74.40/month credit, covers one zonal Standard or Autopilot cluster's management fee. (S2)
  10. Autopilot bills per Pod resource request; Standard bills per provisioned node. (S2)
  11. Cloud Run request timeout: up to 60 minutes; concurrency configurable up to 1000/instance (default 80, or 80×vCPU via gcloud/Terraform). (S2)
  12. Cloud Run cold-start queuing: up to 3.5× average container startup time or 10 seconds, whichever is greater. (S2)
  13. Cloud Run keeps idle instances warm up to 15 minutes (10 for GPU) to reduce repeat cold starts. (S2)
  14. Cloud Run has two billing models: request-based (default, CPU throttles after response) and instance-based (CPU stays allocated). (S2)
  15. App Engine Flexible always keeps a minimum of 1 instance running — cannot scale to zero; Standard can. (S2)
  16. Cloud Functions was renamed Cloud Run functions on August 21, 2024. (S2)
  17. Event-triggered Cloud Run functions cap at 9 minutes; HTTP-triggered functions get up to 60 minutes. (S2)
  18. Cloud Run functions: up to 16 GiB RAM / 4 vCPU per instance, up to 1000 concurrent requests per instance. (S2)
  19. Legacy preemptible VMs were hard-capped at 24 hours; Spot VMs have no cap. (S2)
  20. Cloud Storage gives strong global consistency for read-after-write, metadata-update, delete, and listing — across all storage classes, including multi-region. (S3)
  21. Cloud Storage IAM/ACL grant and revoke propagation is eventually consistent, ~1 minute, sometimes longer. (S3)
  22. Persistent Disk is zonal by default — up to 64 TiB per disk, up to 257 TiB combined across up to 127 disks per VM. (S3)
  23. Regional Persistent Disk costs roughly 2x zonal for the same type. (S3)
  24. Filestore tiers: Basic (legacy), Zonal, Regional, Enterprise (multishare for GKE) — spanning GB to 100+ TiB. (S3)
  25. Cloud SQL storage up to 64 TB on dedicated-core instances; enabling HA roughly doubles instance cost. (S3)
  26. Cloud SQL HA replicates synchronously across 2 zones within one region only — no region-failure protection. (S3)
  27. Spanner uses TrueTime for external consistency — a stronger guarantee than plain strong consistency. (S3)
  28. Firestore's "500/50/5" rule: new collections should start at 500 ops/sec, increasing 50% every 5 minutes. (S3)
  29. Bigtable SSD clusters: up to ~17,000 reads/sec and ~14,000 writes/sec per node (1 KB rows); scans up to 220 MBps/node. (S3)
  30. Bigtable multi-cluster instances default to eventual consistency; single-cluster instances are strongly consistent. (S3)
  31. BigQuery on-demand = pay per TB scanned; flat-rate/Editions = provisioned slot capacity; 90-day-unmodified data gets a long-term storage discount. (S3)
  32. GCP subnets are regional, spanning all zones in a region — unlike AWS's zonal subnets. (S4)
  33. Cloud DNS forwarding (on-prem ↔ GCP) and DNS peering (GCP network ↔ GCP network) are different mechanisms — don't swap them for each other. (S4)
  34. Shared VPC attachment requires compute.xpnAdmin plus resourcemanager.projectIamAdmin. (S4)
  35. Cloud NAT requires a Cloud Router as its config holder, even with no BGP peering configured. (S4)
  36. HA VPN: up to 99.99% SLA with dynamic BGP; Classic VPN: static routes only, 99.9% SLA. (S4)
  37. Each Cloud VPN tunnel handles up to 250,000 pps (roughly 1–3 Gbps depending on packet size). (S4)
  38. Dedicated Interconnect: 10 Gbps or 100 Gbps circuit links, up to 8x bundled (80/800 Gbps), 400 Gbps also available; requires colocation presence. (S4)
  39. Partner Interconnect: 50 Mbps–50 Gbps VLAN attachments, no colocation presence required. (S4)
  40. Cloud Armor's L3/L4 volumetric DDoS protection is always-on; L7 WAF/rate-limiting needs an explicitly attached security policy. (S4)
  41. Global external LB and Cloud CDN require Premium Tier — unavailable on Standard Tier. (S4)
  42. Standard Tier includes a free 200GB/month egress allowance per region. (S4)
  43. Cloud CDN only works with the global external (or classic) Application Load Balancer. (S4)
  44. Three IAM role types: Basic (Owner/Editor/Viewer — avoid), Predefined (Google-maintained), Custom (static, no auto-update). (S5)
  45. IAM policy inheritance is a union down the hierarchy — a child resource can only add access, never revoke a parent's grant. (S5)
  46. Deny policies are the one mechanism that can override an inherited IAM allow. (S5)
  47. Org Policy constraint iam.disableServiceAccountKeyCreation blocks key creation org-wide, even for project Owners. (S5)
  48. Org Policy constraint gcp.resourceLocations enforces data residency at the API layer. (S5)
  49. Workload Identity Federation uses a Workload Identity Pool + Pool Provider + Attribute Mapping, exchanged via OAuth 2.0 token exchange. (S5)
  50. Service account impersonation issues short-lived tokens (hours or less, not auto-refreshed). (S5)
  51. Secret Manager stores a retrievable plaintext value; Cloud KMS never exposes key material, only encrypts/decrypts on request. (S5)
  52. VPC Service Controls blocks data movement across a perimeter regardless of valid IAM grants. (S5)
  53. IAP replaces VPN/bastion for human access to App Engine, Cloud Run, Compute Engine, and GKE. (S5)
  54. Cloud Build supports SLSA Level 3 build provenance; Binary Authorization enforces that only attested images deploy. (S5)
  55. Sensitive Data Protection (formerly DLP) handles PII/credit-card data discovery and classification. (S5)
  56. The _Default log bucket retains entries 30 days; the _Required bucket retains 400 days, not configurable. (S6)
  57. 4 audit log types: Admin Activity (always on, 400d), System Event (always on, 400d), Data Access (off by default except BigQuery, 30d), Policy Denied (on by default, 30d). (S6)
  58. Data Access audit logs require roles/logging.privateLogViewer — standard Logs Viewer excludes them. (S6)
  59. Error Reporting has no separate ingestion pipeline — it scans Cloud Logging for formatted stack traces. (S6)
  60. Cloud Trace samples by default — Cloud Run's documented default is 0.1 requests/sec/instance (~once every 10 seconds). (S6)
  61. No prior Google notification or permission is required to penetration-test your own GCP projects (within the Acceptable Use Policy). (S6)
  62. Rolling update is GKE's default deployment strategy — gradual replacement with a brief mixed-version window. (S6)
  63. Cloud SQL HA failover takes about 60 seconds via a shared static IP. (S7)
  64. Spanner multi-region SLA is 99.999%, versus 99.99% for a regional configuration. (S7)
  65. 4 DR patterns (AWS-style naming): Backup & restore, Pilot light, Warm standby, Multi-site active-active — Google's own docs use cold/warm/hot instead. (S7)
  66. Persistent Disk snapshots are incremental by default; a globally-scoped snapshot can create a new disk in any region. (S7)
  67. Cloud SQL automated backup retention is configurable from 1 day up to 10 years depending on edition/option. (S7)
  68. Cloud SQL PITR: Enterprise edition 1–7 days (default 7); Enterprise Plus 1–35 days (default 14). (S7)
  69. Spanner backups retain up to 1 year; restore mounts the backup directly without copying data (low RTO). Spanner PITR is separate, up to 7 days. (S7)
  70. Cloud Storage dual-region turbo replication bounds RPO to within 15 minutes. (S7)
  71. Cloud Storage Object Versioning does not protect against bucket deletion — use Soft Delete for that. (S7)
  72. A multi-region or dual-region Cloud Storage bucket alone is not a DR strategy for compute or database tiers. (S7)
  73. Cloud SQL Enterprise Plus offers advanced DR with near-zero-data-loss cross-region failover. (S7)
  74. Resource-based CUDs: up to 55% off (1yr/3yr blended) for standard families, up to 70% for memory-optimized on a 3-year term. (S8)

12. Top architecture patterns

Pattern 1 — Global low-latency, read-heavy web app (static assets)

Cloud Storage multi-region bucket for the objects, fronted by a global external Application Load Balancer (Premium Tier) with Cloud CDN enabled for edge caching. (S1, S4)

Pattern 2 — Regulated data with strict residency

Organization Policy gcp.resourceLocations to pin resource location, a VPC Service Controls perimeter to stop authorized-but-risky exfiltration, and Cloud KMS CMEK for customer-controlled encryption at rest. (S5)

Pattern 3 — Event-driven microservices (file lands, gets processed)

Cloud Storage object-finalize event → Eventarc trigger → Cloud Run function (or service) validates/transforms → writes to BigQuery. No custom polling anywhere in the chain. (S10)

Pattern 4 — Lift-and-shift under deadline pressure

Run Migration Center discovery/assessment first, then Rehost the estate to hit the hard deadline (e.g. data center lease expiry); defer Replatform/Refactor to an unfunded, undated phase 2 once the pressure is off. (S9)

Pattern 5 — Multi-region DR for a critical database

If RPO/RTO is near-zero: Spanner multi-region configuration (external consistency, 99.999% SLA). If RPO/RTO is minutes-scale: Cloud SQL HA (zone-level) plus a cross-region read replica kept warm as a promotable standby. (S3, S7)

Pattern 6 — Global, zero-downtime-tolerant platform (fintech-style)

Multi-site active-active: Spanner multi-region instance, GKE clusters in multiple regions behind Multi-cluster Gateway, global external Load Balancer routing to the nearest healthy region. Expensive — that expense is the point. (S7)

Pattern 7 — Secure CI/CD pipeline deploying to GCP

Workload Identity Federation (no downloaded service account key) impersonating a scoped service account, with Binary Authorization + Artifact Registry attestations gating what's allowed to deploy. (S5)

Pattern 8 — Cost-optimized mixed workload (steady API + batch job)

Resource-based or spend-based Committed Use Discount (plus automatic SUD) for the always-on, SLA-bound API; Spot VMs for the checkpointable, fault-tolerant nightly ETL batch job. Never the reverse. (S8)
