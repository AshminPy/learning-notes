Cloud SQL vs Spanner

Both are relational databases. The exam question is never "which is better" — it's "does this scenario need global scale, or not."

Simple example: Cloud SQL is one strong database in one region — like one HQ office. Spanner is the same data kept in sync, correctly, across many regions at once — like several offices that always agree, instantly.

Cloud SQL

AWS analogue: RDS. Managed MySQL, PostgreSQL, or SQL Server. One primary, scales up (bigger machine) or out with read replicas. Good for a normal app in one region.

High availability (HA) means a standby copy in a second zone, same region. Roughly doubles the cost.

Cloud Spanner

No direct AWS match. Relational SQL that scales horizontally and stays strongly consistent across regions at the same time — most databases only give you one of those two. Built for global scale, not for small single-region apps.

Costs more than Cloud SQL at small size. Pick it only when the scenario truly needs global, strongly-consistent writes.

When each wins

ScaleConsistencyCost
Cloud SQLOne region, vertical + read replicasStrong, single regionCheaper, simple
SpannerGlobal, horizontal, no reshardingStrong, across regionsHigher, priced for scale
Exam trap: Cloud SQL HA survives a zone failure, not a region failure — primary and standby are both in the same region. "Must survive a region outage" or "global write path" points to Spanner, not "just enable HA."

Try it — before looking below

Q1. App needs a relational database in one region, normal traffic, lowest cost. Pick one.

A. Cloud SQL. Single region, normal scale — Spanner's global strength is not needed and costs more.

Q2. Scenario says "must keep serving strongly-consistent writes even if a whole region goes down." Pick one.

B. Cloud SQL HA only covers a zone failure inside one region. A region failure needs Spanner's multi-region design.

Q3. True or false: Cloud SQL HA replicates the standby to a different region.

B. False. The standby is a second zone in the same region — this is the exact exam trap above.

Source

docs.cloud.google.com/sql/docs/mysql/high-availability and docs.cloud.google.com/spanner/docs/true-time-external-consistency

Recap
  • Cloud SQL = one region, cheaper, simpler. Spanner = global, horizontal, strongly consistent, pricier.
  • Cloud SQL HA protects against a zone failure only — not a region failure. That gap is the classic exam trap.
