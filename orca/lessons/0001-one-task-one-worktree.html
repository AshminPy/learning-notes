Orca: Many Agents, Many Tasks — Lesson 1 of 23

One task, one worktree, one agent

Today's win: you run two agents at the same time, on two different tasks, in one of your own repos. Neither agent can touch the other's files.

Why this matters

Two agents in one folder edit the same files. They overwrite each other, and you cannot tell who broke what. Orca solves this with one simple rule: every task gets its own folder.

Mental model — separate desks. Your repo is an office. Each task gets its own desk (a worktree): a full copy of the project with its own branch. One worker (an agent) sits at each desk. You are the manager who walks between desks and decides what ships.

What this predicts: while they work, agents cannot overwrite each other. Problems appear only later, when you combine their branches — just like two people's paper drafts only clash when you staple them together.

repo: my-app (base ref: main) ├── desk 1 worktree "fix-tests" branch fix-tests ← agent: Claude Code ├── desk 2 worktree "update-docs" branch update-docs ← agent: Codex └── desk 3 worktree "explore-ci" branch explore-ci ← agent: Claude Code you: review each diff → merge the good ones → delete the rest

Two ways to use many agents

Fan-out

Different tasks, one agent each. Three bugs → three worktrees → three agents.

Rule: the tasks must be independent — they should not change the same files, or you will fight merge conflicts later.

This is your main goal.

Race

Same task, several agents. Compare the diffs, keep the best one.

Orca's tip: "Where three agents agree, the answer is probably right." If they disagree, you found the hard part. (Recipe)

Lesson 2.

Common mistake: fanning out tasks that touch the same file (for example, two agents both editing README.md). The worktrees protect you while they work — but at merge time you get a conflict to fix by hand. Split work by files or modules, not just by "topic".

Check yourself — before the hands-on

Q1. Two agents in two Orca worktrees both edit README.md. When do they collide?

Each worktree is its own folder and branch, so nothing clashes during work. The clash shows up when both branches are combined into main.

Q2. You want three different bugs fixed today. Which pattern fits?

Different tasks → fan-out. Race is for one hard task where you want several attempts. One agent for everything is the slow, serial way Orca replaces.

Q3. You delete a losing worktree in Orca. What is removed?

Orca docs: deleting a worktree removes both the directory and the branch, after a confirmation. So keep anything you want before you delete.

Q4. In your own words: why can two agents in two worktrees not overwrite each other's files while they work?

Because each worktree is a separate folder on disk with its own branch. Each agent only sees and edits its own copy.

Hands-on: your first fan-out

Try it — about 10 minutes, nothing to merge

Two read-only tasks, so there is nothing to break and nothing to merge.

1. Predict first. Write down: after you start two agents, will any file in the folder you are working in now change? Yes or no — and why?

2. Launch agent A (UI way). In Orca's sidebar, click + next to your repo (use any repo with a tests/ folder and a README; adjust folder names in the prompts if yours differ). Name it explore-tests, start from main, pick Claude Code. Paste:

Read the tests/ folder. List the 5 test files that look slowest or most fragile, with one reason each. Do not edit any files.

3. Launch agent B (CLI way). From any terminal:

orca worktree create --repo path:/path/to/your/repo \
  --name explore-docs --no-parent --agent claude --activate \
  --prompt "Read README.md and docs/. List 5 places where the docs look out of date, with the file name. Do not edit any files."

--agent starts the agent in the first terminal, --prompt sends the task, --no-parent marks it as independent work, --activate shows it in the app.

4. Watch both. Drag one worktree's tab to the right edge of the pane to split the view. Or check from a terminal:

orca worktree ps
git -C /path/to/your/repo worktree list

5. Check your prediction. Run git status in the folder you were working in before. Was your guess right?

6. Clean up when both agents finish (copy any answer you want to keep first). Use the delete action on each worktree in the sidebar, or:

orca worktree rm --worktree name:explore-tests --force
orca worktree rm --worktree name:explore-docs --force

Safety net: if a branch has commits that are not merged, Orca keeps the branch. --force forces the folder removal, not the branch deletion.

Done when: both agents worked at the same time, git worktree list showed two extra folders while they ran, and the folder you started in did not change.

Quick reference: Glossary · CLI cheat sheet

  • One task = one worktree = one agent. Worktrees are real git worktrees: own folder, own branch.
  • Isolation protects you during work. Conflicts appear only at merge time.
  • Fan-out = different independent tasks. Race = same task, pick the winner.
  • Deleting a worktree deletes its folder and branch.
