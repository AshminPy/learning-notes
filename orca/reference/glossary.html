Orca: many agents, many tasks — Reference

Glossary

Every lesson uses these words with exactly these meanings. Checked 2026-10-12 against Orca 1.4.224 and onorca.dev/docs.

Core

TermMeaning
RepoA local git checkout you added to Orca (Add Repo).
Base ref"The ref every new worktree branches from" — usually origin/main. Set per repo.
Start-from refThe point one specific worktree branches off. Defaults to the base ref.
WorktreeA real git worktree: its own folder, branch, terminals and browser tabs. One per task.
Worktree idTwo-part address <repoId>::<worktreePath>. A bare repo id is not a worktree id.
SelectorHow the CLI names a worktree: id:, name:, path:, branch:, issue:, or active.
AgentA coding CLI (Claude Code, Codex, Cursor CLI, …) running in a worktree's terminal.
Terminal handleThe CLI's name for one live terminal. Changes after an Orca restart — re-list, don't reuse.
Worktree commentShort status line on the workspace card (worktree set --comment).

Patterns

TermMeaning
Fan-outDifferent independent tasks, one worktree + agent each. (Course term.)
RaceSame task, several agents; compare diffs, keep the winner, delete the rest.
HandoffGive a task fully to another agent/worktree and stop. No supervision.

Orchestration (later lessons — experimental feature)

TermMeaning
CoordinatorThe agent/session that creates the Run and tasks, starts workers, reads the inbox.
RunA durable namespace with a coordinator inbox. Tracks work; does not schedule it.
TaskA work item with a spec, optional dependencies, and a status (pending, ready, dispatched, completed, failed, blocked).
DispatchOne attempt to run a task on a terminal.
WorkerAn agent started on a task through a dispatch.
worker_doneThe message a worker sends exactly once when finished — even on failure.
Decision gateA question that blocks a task until someone records an answer.
